# QA 테스트케이스 작성/갱신

## 사전 조건

- `01-prd.md`가 있어야 한다. `02-policy.md`, `04-screens/`도 있으면 함께 근거로 삼는다.

## 절차

1. `01-prd.md`, `02-policy.md`, `04-screens/*.md`를 읽는다.
2. TC를 세 갈래로 도출한다:
   - **REQ 기반**: 각 REQ의 인수 조건(체크박스)을 실행 가능한 절차로 변환 (정상 케이스)
   - **POL 기반**: 각 정책의 위반 케이스 — 정책의 "위반 시 처리·문구"가 그대로 기대 결과가 된다 (예외 케이스)
   - **화면 기반**: 각 화면의 상태 4종(기본/로딩/빈/에러)과 입력 유효성 실패 (경계 케이스)
3. `templates/05-qa-tc.md` 구조로 `05-qa-tc.md`를 작성한다.
   - 기대 결과에 화면 이동, 표시 문구를 원문 그대로 명시한다 — "정상 동작한다" 같은 표현 금지.
   - 절차는 사전 조건부터 재현 가능하게 번호 목록으로 쓴다.
4. **커버리지 체크**: 문서 하단 체크리스트를 실제로 검증한다.
   - TC가 없는 P0 REQ, 위반 TC가 없는 POL이 있으면 목록으로 보고하고 보충한다.
5. **역참조 갱신**: `02-policy.md`의 정책 목록·각 POL의 "관련 테스트"에 TC ID를 채운다.
6. 완료 후 스펙 세트 4종(PRD/정책/화면/TC)이 모두 갖춰졌는지 확인하고, 문서 승인(검토→승인)을 안내한다.

## 규칙

- TC는 QA 담당자(사람 또는 Claude)가 문서만 보고 그대로 실행할 수 있어야 한다.
- 개발·QA 중 정책이나 화면이 CR로 바뀌면 관련 TC도 반드시 함께 갱신된다 (`/merge-change`가 처리).
