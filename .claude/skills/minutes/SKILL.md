# 회의록 → 기획 반영

회의에서 결정된 것이 추적 체인의 출발점이다. 회의록을 요약이 아니라 **기획 산출물의 입력**으로 다룬다.

## 절차

1. 회의록/전사 파일의 경로를 확인한다 (사용자가 붙여넣은 텍스트도 가능. 여러 파일 가능).
2. 원본을 `projects/<프로젝트>/minutes/YYYY-MM-DD-<주제>.md`로 보관한다.
   - 원문은 수정하지 않는다. 파일 상단에 메타(일시, 참석자, 출처 파일명)만 추가한다.
3. **결정사항만 7개 이내로 요약한다.**
   - "결정"과 "논의/의견/아이디어"를 엄격히 구분한다. 결정되지 않은 것을 결정으로 승격하지 않는다.
   - 각 결정에 근거 발언을 짧게 인용한다 (나중에 범위 논쟁이 생기면 이 문서로 되돌린다).
   - 결정인지 애매한 항목은 AskUserQuestion으로 사용자에게 판정받는다.
4. 요약을 사용자에게 보여주고 확인받는다.
5. 확인된 결정을 산출물에 반영한다. 경로 분기:
   - **신규 프로젝트** → `/plan-init` 흐름으로 브리프 작성 (배경·목표·비목표 순, 회의 결정을 출처로 인용)
   - **기존 문서가 초안/검토중** → 해당 문서 직접 갱신 + 근거 회의록 경로 기록
   - **승인된 문서에 영향** → `/change`로 CR 생성 (출처: "회의 YYYY-MM-DD")
6. 반영 후 회의록 파일 하단에 **결정 → ID 매핑 테이블**을 남긴다:
   `| 결정 | 반영 위치 | ID |` (예: "계좌이체 수동 확인" → 02-policy.md → POL-007)
   반영되지 않은 결정이 남으면 "미반영 — 사유"로 명시한다.

## 규칙

- 요약과 반영을 한 턴에 끝내지 않는다. 반드시 사용자 확인(4단계)을 거친다.
- 회의 결정과 기존 산출물이 충돌하면 임의로 덮어쓰지 말고 충돌 내용을 보고하고 판단을 요청한다.
