# IA & 와이어프레임 작성/갱신

## 사전 조건

- `01-prd.md`가 있어야 한다. `02-policy.md`도 있으면 함께 반영한다.

## 절차

### 1단계: IA (03-ia.md)

1. REQ 목록에서 필요한 화면을 도출해 SCR-### ID를 부여한다.
2. `templates/03-ia.md` 구조로 사이트맵(Mermaid), 화면 목록 테이블, 주요 사용자 흐름(Mermaid)을 작성한다.
3. 화면 수가 많으면(10개 초과) 우선순위 P0 화면부터 사용자와 범위를 확정한다.
4. **역참조 갱신**: `01-prd.md` REQ 테이블의 "관련 화면" 열에 SCR ID를 채운다.

### 2단계: 화면정의서 + HTML 목업 (04-screens/)

각 화면(SCR)마다 두 파일을 쌍으로 만든다:

1. **화면정의서** `04-screens/SCR-###-<화면명>.md` — `templates/04-wireframe-spec.md` 구조.
   - ASCII 레이아웃의 구성요소 번호 [n]과 컴포넌트 트리, 구성요소 정의 테이블을 일치시킨다.
   - **컴포넌트 트리(JSX)**는 개발 인수인계용이다 — 개발자(또는 구현 AI)가 이 구조 그대로 컴포넌트를 만들 수 있게 쓰고, 동작·유효성 규칙은 주석에 POL ID로 단다.
   - 상태별 화면(로딩/빈/에러)과 입력 유효성은 반드시 채운다 — QA의 테스트 기준이 된다.
   - 유효성·동작 규칙은 정책서의 POL ID를 인용한다.
2. **HTML 목업** `04-screens/SCR-###-<화면명>.html` — `templates/04-wireframe.html`을 복사해 작성.
   - 로파이 그레이스케일 스타일을 유지한다. 실제 디자인(색상, 브랜딩)을 입히지 않는다.
   - 주석 번호 배지(.n)를 화면정의서의 [n]과 일치시킨다.

### 3단계: 뷰어 갱신 (04-screens/index.html)

- `04-screens/index.html`을 생성/갱신한다: 폴더 내 모든 화면을 카드 목록으로 보여주는 정적 페이지.
  각 카드에 화면 ID, 화면명, 버전, 상태, HTML 목업 링크(iframe 미리보기 또는 링크)를 담는다.
- 화면을 추가·삭제할 때마다 이 목록을 다시 생성한다 — 비개발 팀원이 이 파일 하나만 열면 전체 화면을 훑을 수 있게 하는 것이 목적이다.
- 작성 후 사용자에게 브라우저로 열어 확인하도록 index.html 경로를 안내한다.

## 규칙

- .md와 .html은 항상 같은 내용을 유지한다. 한쪽만 고치지 않는다.
- 승인된 화면정의서는 직접 수정하지 않는다 — `/change` 절차를 안내한다.
- 목업은 구조와 동작 전달이 목적이다. 시각 디자인 품질에 시간을 쓰지 않는다.
- 완료 후 다음 단계로 `/qa-tc`(테스트케이스 작성)를 안내한다 — 스펙 세트 4종의 마지막 조각이다.
