## 1. 화면 목적

**입금이 확인된 건만** 대기열에 올려 집회 전날 일괄 출력하고, 분실 재발급은 개별 출력으로 처리하며 출력 횟수로 구분한다.

## 4. 구성 요소 정의

| # | 요소 | 유형 | 내용/동작 | 관련 정책 |
|---|---|---|---|---|
| 1 | 페이지 헤더 | 공통 | 「명찰 출력」 + 대기·출력 완료·재발급 건수 | |
| 2 | 용지 규격 안내 | 정보 | 규격이 확정되지 않았으면 경고 표시. 확정되면 규격명 표시 | POL-020 |
| 3 | 탭 · 필터 | 탭/입력 | 대기열 / 출력 완료 / 재발급, 지역 필터, 이름·등록번호 검색 | |
| 4 | 대기열 테이블 | 테이블 | 등록번호·이름·지역·구분·입금 상태·출력 횟수·관리. **입금 미확인 건은 체크 불가 + 「출력 불가」** | POL-019, POL-038 |
| 5 | 출력 액션 | 버튼 | [선택 출력] / [지역별 묶음 출력] / [전체 일괄 출력]. 전날 일괄 출력이 기본 운영 방식 | POL-019 |
| — | 미리보기 모달 | 모달 | 이름·등록번호·지역·구분 4개 항목이 실제 용지 규격 비율로 배치된 미리보기 | POL-020 |

## 5. 상태별 화면

| 상태 | 조건 | 표시 내용 |
|---|---|---|
| 기본 | 대기열 있음 | 입금 확인 건만 체크 가능 |
| 빈 상태 (대기열) | 입금 확인 건 0건 | 「출력할 명찰이 없습니다. 입금이 확인된 건만 대기열에 올라옵니다.」 |
| 미입금 출력 시도 | 입금 미확인 건 출력 | 차단. 「입금이 확인되지 않은 신청은 명찰을 출력할 수 없습니다.」 |
| 재출력 | 출력 횟수 ≥ 1 | 경고(진행 가능). 「이미 출력한 명찰입니다. 재발급으로 기록됩니다.」 |
| 규격 미확정 | `paperSize` 없음 | [2] 경고 + 미리보기에 「용지 규격이 확정되지 않았습니다. 출력 전에 실물 용지로 확인해 주세요.」 |
| 출력 중 | 처리 중 | 진행률 표시 + 버튼 비활성 |
| 출력 중단 | 실패 | 「{n}건까지 출력했습니다. 이어서 출력하시겠습니까?」 — 어디까지 출력했는지 확인할 수 있어야 한다 |
| 로딩 / 에러 | 조회 중 / 실패 | 스켈레톤 / 「대기열을 불러오지 못했습니다.」 |

## 6. 입력 유효성

입력 폼 없음. 출력 실행 조건만 검사한다 — 입금 상태 = 매칭(POL-019), 등록번호 발급됨(POL-038).

## 7. 인터랙션 상세

- [전체 일괄 출력] → 확인 모달 「대기 중인 {n}건을 모두 출력합니다.」 → 실행 → 각 건의 출력 횟수 +1.
- 출력 횟수가 1 이상이 되면 **재발급으로 표시**되고 [재발급] 탭에 나타난다(POL-019).
- 현장 접수자는 입금 확인 즉시 개별 출력한다. 전날 일괄 출력에 포함되지 않는다.
- 출력 실행 결과는 이력에 기록된다(POL-033).

> **POL-020은 미확정이다**(오픈 이슈 OI-4). 소형 용지(A6 등) 출력 프린터를 대여할지 구매할지 정해져야 규격이 확정된다.
> 수양회에서 조정해 둔 여백·폼 설정값과 잔여 명찰 케이스 활용 여부도 함께 확인해야 한다.

## 8. 목업 동작 (HTML)

- **입금 미확인 행은 체크박스가 실제로 비활성**이고 「출력 불가」가 뜬다(POL-019 검증 포인트).
- [전체 일괄 출력]을 누르면 대기열 건들의 **출력 횟수가 실제로 1 증가**하고 탭 간 이동이 일어난다(대기열 → 출력 완료).
- 이미 출력한 건을 다시 출력하면 **재발급 경고가 뜨고 [재발급] 탭에 실제로 들어간다.**
- 미리보기 모달이 4개 항목으로 실제 렌더되며, 규격 미확정 경고가 함께 뜬다.
- [용지 규격 확정으로] 버튼으로 POL-020이 확정된 경우의 화면을 비교해 볼 수 있다.
