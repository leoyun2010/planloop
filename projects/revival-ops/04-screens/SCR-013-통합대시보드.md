## 1. 화면 목적

운영 핵심 지표를 한 화면에서 보여주고, **지금 손이 필요한 일**을 건수와 함께 나열해 해당 관리 화면으로 보낸다.

## 3. 컴포넌트 트리 (개발 인수인계용)

```jsx
<AdminLayout active="dashboard">
  <SideNav menus={visibleMenus(account)} />        {/* [1] 권한 없는 메뉴는 숨김 (POL-031) */}
  <PageHeader title="통합 대시보드"                 {/* [2] */}
    crumb={`집회 ${dayNo}일차 · ${asOf} 기준`} />

  <StatRow>                                        {/* [3] 4개 핵심 지표 */}
    <Stat label="접수 인원"     value={stats.registered} />
    <Stat label="입금 확인 인원" value={stats.paid}       {/* 매칭된 사람 수만 (POL-008) */} />
    <Stat label="숙소 미배정"   value={stats.unassigned} />
    <Stat label="상담 대기"     value={stats.counselWaiting} />
  </StatRow>

  <Panel title="환불 집계">                         {/* [4] 완료 건만 차감 (POL-005) */}
    <RefundSummary count={refund.count} amount={refund.amount}
      done={refund.done} pending={refund.pending} />
  </Panel>
  <Panel title="실 참가 인원">                      {/* [4] 접수 − 환불 = 실 인원 (POL-002) */}
    <CapacitySummary actual={stats.registered - refund.done}
      capacity={conf.totalCapacity} buffer={conf.onsiteBuffer}
      bufferLeft={conf.onsiteBuffer - onsiteUsed} />
  </Panel>

  <Panel title="누적 입금액">                       {/* [5] 환불 반영 순 입금액 */}
    <NetAmount value={payment.total - refund.amount} />
  </Panel>

  <ActionList                                      {/* [6] 건수 0이면 강조하지 않는다 */}
    items={[
      { label:'미매칭',        count:m.unmatched,  to:'SCR-016', filter:'unmatched' },
      { label:'부분 매칭',     count:m.partial,    to:'SCR-016', filter:'partial' },
      { label:'명찰 출력 대기', count:m.badgeQueue, to:'SCR-017' },
      { label:'배차 대기',     count:m.dispatch,   to:'SCR-022', filter:'waiting' },
      { label:'환불 요청',     count:m.refundReq,  to:'SCR-015', filter:'refund' },
    ]}
    onGo={(to, filter) => goto(to, { filter })} />  {/* 해당 필터가 적용된 상태로 연다 */}
</AdminLayout>
```

## 4. 구성 요소 정의

| # | 요소 | 유형 | 내용/동작 | 관련 정책 |
|---|---|---|---|---|
| 1 | 사이드 내비 | 공통 | 현재 집회명 + 메뉴 13개. 권한 없는 메뉴는 노출하지 않는다 | POL-031 |
| 2 | 페이지 헤더 | 공통 | 「통합 대시보드」 + 「집회 {n}일차 · {시각} 기준」 | |
| 3 | 핵심 지표 4종 | 지표 | 접수 인원 / 입금 확인 인원 / 숙소 미배정 인원 / 상담 대기 인원. **입금 확인 인원은 매칭된 사람 수만 센다** | POL-008 |
| 4 | 환불 집계 · 실 참가 인원 | 지표 | 환불 인원·금액과 완료/대기 건수. 실 참가 인원 = 접수 − 환불(완료분). 총 정원·잔여 버퍼 좌석 함께 표시 | POL-002, POL-005 |
| 5 | 누적 입금액 | 지표 | 환불을 반영한 **순 입금액** | POL-005 |
| 6 | 조치 필요 목록 | 목록+버튼 | 미매칭 / 부분 매칭 / 명찰 출력 대기 / 배차 대기 / 환불 요청 건수와 이동 버튼. 이동 시 **해당 필터가 적용된 상태로** 열린다 | POL-009 |

## 5. 상태별 화면

| 상태 | 조건 | 표시 내용 |
|---|---|---|
| 기본 | 운영 중 집회 있음 | 지표와 조치 목록 표시 |
| 조치 없음 | 모든 항목 0건 | [6]에 「지금 조치가 필요한 일이 없습니다.」 건수 0인 항목은 강조하지 않는다 |
| 정원 임박 | 잔여 버퍼 20석 미만 | [4] 버퍼 값을 경고색으로 표시 + 「현장 버퍼가 얼마 남지 않았습니다.」 (리스크 R-2 감시 신호) |
| 집계 불일치 | 대시보드 인원 ≠ 개인 단위 매칭 인원 | 지표를 표시하지 않고 「집계가 맞지 않습니다. 입금 매칭을 확인해 주세요.」 + 오류 기록 (POL-008) |
| 운영 중 집회 없음 | 모든 집회가 종료·보관 | 「운영 중인 집회가 없습니다.」 + [집회 만들기] → SCR-014 |
| 로딩 | 집계 조회 중 | 지표 카드 스켈레톤 |
| 에러 | 조회 실패 | 「지표를 불러오지 못했습니다.」 + [다시 시도] |

## 6. 입력 유효성

입력 폼 없음 — 해당 없음.

## 7. 인터랙션 상세

- [6]의 버튼 → 해당 화면으로 이동하며 그 상태 필터가 적용된 상태로 열린다(예: 미매칭 12건 → SCR-016의 「미매칭」 탭).
- 지표는 화면 진입 시 조회하며, 상단에 기준 시각을 표시한다. 자동 새로고침은 하지 않는다(수동 [새로고침]).
- 환불은 **처리 완료분만** 차감한다. 처리 대기 상태에서는 차감하지 않는다(POL-005).

## 8. 목업 동작 (HTML)

- [환불 3건 처리 완료] 버튼을 누르면 **환불 집계·실 참가 인원·순 입금액이 실제로 함께 줄어든다**(POL-005 연동 검증).
- [조치 전부 해소] 버튼으로 [6]의 빈 상태 문구를 확인할 수 있다.
- [버퍼 소진 임박] 버튼으로 정원 경고 상태를 확인할 수 있다.
- [집계 불일치 만들기]로 POL-008 위반 시 지표를 감추는 동작을 확인할 수 있다.
- 조치 목록의 이동 버튼은 어떤 필터로 열리는지 토스트로 알려준다.
