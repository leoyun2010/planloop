## 1. 화면 목적

접수자 명단을 찾고 고치고, **입금 상태에 따라 접수 취소인지 환불인지 헷갈리지 않게** 처리한다. 현장 방문자를 대신 등록한다.

## 3. 컴포넌트 트리 (개발 인수인계용)

```jsx
<AdminLayout active="registrants">
  <PageHeader title="접수 · 환불 관리"                  {/* [1] */}
    summary={`총 ${rows.length}명 · 미매칭 ${unmatched}건`}>
    <Button primary label="+ 현장 접수" onClick={openOnsiteModal} />  {/* POL-003 — 항상 동작 */}
  </PageHeader>

  <Toolbar>
    <SearchInput placeholder="이름·등록번호·휴대폰"      {/* [2] 하이픈 무관 */}
      onInput={q => filter({ q })} />
    <TabBar data-tabs="reg"                              {/* [3] */}
      items={['전체','미매칭만','환불만']} onChange={t => filter({ tab: t })} />
  </Toolbar>

  <DataTable rows={visibleRows}>                         {/* [4] */}
    <Col name="check" type="checkbox" />
    <Col name="regNo"  render={r => r.regNo ?? '미발급'} />       {/* POL-038 */}
    <Col name="name" /><Col name="phone" /><Col name="joinType" />
    <Col name="payment" render={r => <Chip label={r.payment} />} /> {/* POL-009 용어 3종 */}
    <Col name="source" render={r => `${r.source} · ${r.by}`} />     {/* 등록 경로·등록자 (POL-033) */}
    <Col name="actions" render={r => resolvePol005Buttons(r)} />    {/* POL-005 버튼 분기 */}
    rowClass={r => r.payment === '미매칭' ? 'bad' : ''}             {/* POL-009 행 강조 */}
  </DataTable>

  <SelectionBar count={selected.length} />               {/* [5] */}

  <EditModal    onSubmit={saveEdit} />       {/* 모든 상태에서 사용 가능 (POL-005) */}
  <RefundModal  onSubmit={doRefund}          {/* 수취인 기본값 = 실제 입금자 (POL-006) */}
    payee={resolvePol006Payee(app, targets)} />
  <CancelModal  onSubmit={doCancel} />       {/* 환불 계좌 입력란 없음 (POL-005) */}
  <OnsiteModal  onSubmit={addOnsite} />      {/* 입력 항목은 SCR-002와 동일 (POL-042) */}
  <HistoryModal rows={history} />            {/* 건별 이력 (POL-033) */}
</AdminLayout>
```

## 6. 입력 유효성

|---|---|---|---|---|---|

| 현장 접수 | 지역·성별·구분·숙소 사용 | Y | 지정 값 | 「{항목}을(를) 선택해 주세요.」 | POL-042 |

## 7. 인터랙션 상세

- 환불 처리 완료 → 상태가 「환불」로 바뀌고 **명단에서 삭제되지 않는다.** 대시보드 집계에 −1명 / −금액 반영(POL-005).
- 접수 취소 → 상태가 「취소」로 바뀌고 접수 인원 집계에서 제외된다. 환불 계좌를 받지 않는다.
- 모든 수정·취소·환불은 담당자·사유와 함께 이력에 기록된다. 기록 실패 시 원 처리도 실패시킨다(POL-033).
- 현장 접수는 **접수 마감·정원 도달 이후에도 가능하다**(POL-001·POL-002·POL-044 예외).

> **POL-006은 미확정이다**(오픈 이슈 OI-3). 환불 수취인 기본값을 인도자(실제 입금자)로 둘지, 취소한 본인으로 둘지 확정되지 않았다.
> 이 화면은 현재 기준(실제 입금자)으로 그렸고, 목업에서 두 경우를 모두 확인할 수 있게 했다.

## 8. 목업 동작 (HTML)

- **검색·필터가 실제로 동작한다.** 하이픈을 빼고 `01011112222`로 검색해도 찾힌다.
- **POL-005 버튼 분기가 행마다 실제로 다르게 렌더된다.** 미입금 행에는 [환불]이 없고, 환불 완료 행에는 [이력]만 있다.
- [환불] 처리하면 상태가 「환불」로 바뀌고 **행이 명단에 남은 채** 상단 집계가 줄어든다.
- [접수 취소] 모달에는 계좌 입력란이 아예 없다(POL-005 검증 포인트).
- **[POL-006 대안으로 전환]** 버튼으로 환불 수취인 기본값이 인도자 ↔ 본인으로 바뀌는 것을 확인할 수 있다.
- [+ 현장 접수]로 등록하면 **등록 경로 = 현장, 등록자 = 로그인 담당자**로 실제로 행이 추가된다.
- 각 행 [이력]에 처리 기록이 실제로 쌓인다.
