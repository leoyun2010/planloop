## 1. 화면 목적

**누구를 어느 방에 어느 상담사와 붙일지 정하는 곳.** 본부에서 받은 상담 신청(현장·전화)을 입력하고 배치를 확정한다.

## 3. 컴포넌트 트리 (개발 인수인계용)

```jsx
<AdminLayout active="cregist">
  <PageHeader title="상담 접수 · 배치"                {/* [1] */}
    summary={`배치 대기 ${waiting.length}건`}>
    <Button primary label="+ 상담 접수" onClick={openIntake} />   {/* 본부 전용 (POL-021) */}
  </PageHeader>

  <WaitingList rows={waiting}                        {/* [2] */}
    searchable
    columns={['접수 경로','이름','연락처','희망 일시','구원 여부','상담 사유']}
    onAssign={openAssign} />                         /* 구원 여부는 SCR-004 입력값 (REQ-048) */

  <RoomBoard                                         {/* [3] 시간 × 상담실 격자 */}
    date={date} rooms={rooms} slots={slots}
    onEmptyClick={openAssignAt}                      /* 빈 칸 클릭 → 대기자 선택 */
    disabledRooms={rooms.filter(r => r.status === '미사용')} />  /* POL-036 */

  <ConfirmedList rows={confirmed}                    {/* [4] */}
    onChange={openReassign} />                       /* 변경 이력 기록 (POL-033) */

  <UserSyncNotice />                                 {/* [5] 확정 시 SCR-008·SCR-011 연동 */}

  <IntakeModal                                       {/* 본부 접수 — 현장/전화 (POL-021) */}
    fields={['접수 경로','이름','휴대폰','희망 일시','상담 사유']}
    onSubmit={addIntake} />

  <AssignModal                                       {/* 상담실·상담사·시간 (POL-036) */}
    counselors={availableCounselors(date, time)}     /* 가용 상담사만 (POL-035 · 미확정 OI-7) */
    onSubmit={confirmAssign} />
</AdminLayout>
```

> **이 화면이 「정하는 곳」이고, SCR-020은 「흘러가는 것을 보는 현황판」이다.** 두 화면은 같은 배정 데이터를 쓴다(POL-036).

## 4. 구성 요소 정의

| # | 요소 | 유형 | 내용/동작 | 관련 정책 |
|---|---|---|---|---|
| 1 | 페이지 헤더 | 공통 | 「상담 접수 · 배치」 + 배치 대기 건수 + [+ 상담 접수] | POL-021 |
| 2 | 배치 대기 목록 | 테이블 | 접수 경로(현장/전화)·이름·연락처·희망 일시·**구원 여부**·상담 사유·[배치]. 이름·번호로 검색 | POL-021 |
| 3 | 상담실 배치판 | 격자 | 날짜별 **시간 × 상담실** 격자. 빈 칸을 클릭해 대기자 중에서 골라 배치. 미사용 상담실은 배치 불가 | POL-036 |
| 4 | 확정된 배치 | 목록 | 이름·일시·상담실·상담사 + [변경]. 변경 시 이력 기록 | POL-033 |
| 5 | 사용자 연동 안내 | 정보 | 확정되면 SCR-008 마이페이지와 SCR-011 상담 안내에 표시된다 | |
| — | 상담 접수 모달 | 모달 | 접수 경로·이름·휴대폰·희망 일시·상담 사유. **사용자 모바일에는 신청 폼이 없다** | POL-021, POL-042 |
| — | 배치 모달 | 모달 | 날짜·시간·상담실·상담사 지정. **그 시간에 가능한 상담사만** 선택 목록에 노출, 불가한 상담사는 비활성 | POL-035, POL-036 |

## 5. 상태별 화면

| 상태 | 조건 | 표시 내용 |
|---|---|---|
| 기본 | 대기 있음 | 대기 목록 + 배치판 |
| 빈 상태 (대기) | 배치 대기 0건 | 「배치할 상담이 없습니다. 본부 접수처에서 받은 신청을 [+ 상담 접수]로 등록해 주세요.」 |
| 미사용 상담실 | 상태 = 미사용 | 그 열은 회색 처리, 클릭 불가 |
| 이중 배치 | 같은 상담사·같은 시간 | 차단. 「이 시간에 이미 배정된 상담이 있습니다.」 |
| 가용 상담사 없음 | 그 시간에 가능한 상담사 0명 | 「이 시간에 가능한 상담사가 없습니다. 다른 시간을 골라 주세요.」 |
| 로딩 / 에러 | 조회 중 / 실패 | 스켈레톤 / 「상담 접수 목록을 불러오지 못했습니다.」 |

## 6. 입력 유효성

| 모달 | 필드 | 필수 | 형식/제한 | 실패 시 문구 | 관련 정책 |
|---|---|---|---|---|---|
| 접수 | 접수 경로 | Y | 현장 / 전화 | 「접수 경로를 선택해 주세요.」 | POL-021 |
| 접수 | 이름 | Y | 2~20자 | 「이름은 2자 이상 20자 이하로 입력해 주세요.」 | POL-042 |
| 접수 | 휴대폰 | Y | 숫자 10~11자리 | 「휴대폰 번호는 숫자 10~11자리로 입력해 주세요.」 | POL-042 |
| 접수 | 희망 일시 | Y | 집회 기간 내 | 「희망 일시를 입력해 주세요.」 | |
| 접수 | 상담 사유 | N | 최대 500자 | 「500자 이내로 입력해 주세요.」 | POL-042 |
| 배치 | 상담실 | Y | 미사용 아닌 방 | 「상담실을 선택해 주세요.」 | POL-036 |
| 배치 | 상담사 | Y | 그 시간 가용 | 「이 시간에 가능한 상담사를 선택해 주세요.」 | POL-035 |

> **POL-035의 가용 상담사 필터는 상담사 가능 시간 입력 위치가 정해져야 완성된다**(오픈 이슈 OI-7).
> 값이 없으면 필터가 동작할 수 없다. 목업은 상담사별 가능 시간을 미리 넣어 두고 필터가 도는 모습을 보여준다.

## 7. 인터랙션 상세

- [+ 상담 접수] → 본부가 받은 신청을 입력 → 배치 대기 목록에 「배치 대기」 상태로 추가.
- [배치] 또는 배치판 빈 칸 클릭 → 상담실·상담사·시간 확정 → **SCR-020 타임라인에 블록이 생성**되고 대기 목록에서 제거된다.
- 확정되면 신청자의 SCR-008 마이페이지와 SCR-011 상담 안내에 확정 일시·상담실이 표시된다.
- [변경] → 상담실·상담사·시간을 바꾼다. 변경 전후가 이력에 기록된다(POL-033).
- **사용자 화면에는 상담 신청 폼이 없다.** 이 화면이 유일한 접수 경로다(POL-021).

## 8. 목업 동작 (HTML)

- [+ 상담 접수]로 등록하면 **배치 대기 목록에 실제로 추가**된다(접수 경로 기록 포함).
- [배치] 또는 배치판 빈 칸 클릭 → 배치 확정 → **대기 목록에서 사라지고 배치판·확정 목록에 실제로 나타난다.**
- **가용 상담사 필터가 실제로 동작한다.** 이상담사는 6/19 13시 이전에 불가로 잡혀 있어 오전 시간에는 비활성으로 표시된다(POL-035).
- 같은 상담사·같은 시간에 이중 배치하면 **실제로 차단**된다(POL-036).
- 미사용 상담실(상담실 4) 열은 클릭이 막힌다.
- [변경]으로 배치를 바꾸면 이력에 기록된다.
