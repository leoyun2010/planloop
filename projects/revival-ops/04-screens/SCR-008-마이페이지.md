## 1. 화면 목적

등록번호·입금·숙소·셔틀·상담 상태를 한 화면에서 확인시키고, 「방금 입금했는데 왜 완료가 아니냐」는 문의를 안내 문구로 흡수한다.

## 5. 상태별 화면

| 상태 | 조건 | 표시 내용 |
|---|---|---|
| 기본 (입금 확인 전) | 입금 미매칭 | 등록번호 「미발급」, 입금 「확인 중」, [4]에 [신청 취소하기] 노출 |
| 부분 매칭 | 동행 중 일부만 입금 | 입금 「부분 매칭」 + 「함께 신청하신 분 중 {n}명의 입금이 확인되었습니다.」 취소 버튼은 본인의 개인 입금 여부로 판단(POL-005와 같은 단위) |
| 입금 확인 후 | 매칭 완료 | 등록번호 발급값 표시, 입금 「확인」, [4]에 본부 연락처만 |
| 배정 완료 | 숙소 배정됨 | 숙소에 구역·방·좌석 표시 |
| 취소됨 | 본인 또는 관리자 취소 | 전체 상태를 「취소」로 표시하고 [4] 숨김. 「이 신청은 취소되었습니다.」 |
| 환불 완료 | 환불 처리됨 | 「환불 완료」 배지. 명단에서 삭제되지 않는다(POL-005) |
| 로딩 | 조회 중 | [2][3] 스켈레톤 |
| 에러 | 조회 실패 | 「신청 정보를 불러오지 못했습니다.」 + [다시 시도] |

빈 상태: 해당 없음 (본인 확인을 통과했다면 신청이 반드시 존재한다).

## 6. 입력 유효성

입력 폼 없음. 취소 실행 시 확인 절차만 있다 — 「신청을 취소하시겠습니까? 취소하시면 되돌릴 수 없고 다시 신청하셔야 합니다.」

## 7. 인터랙션 상세

- [4] [신청 취소하기] → 확인 모달 → [취소하기] → 접수 상태가 「취소」로 변경되고 화면 전체가 취소 상태로 바뀐다. 변경 이력에 기록된다(POL-033).
- 입금 상태가 「매칭」으로 바뀌는 즉시 [4]의 구성이 버튼에서 안내로 바뀐다.
- 본인 확인을 거치지 않고 `/me`로 접근하면 SCR-007로 돌려보낸다.

> **POL-004는 검토중이다**(오픈 이슈 OI-2, 담당 박채림, 기한 착수 +2주). 이 화면은 현재 기준(입금 전 본인 취소 / 입금 후 관리자 문의)으로 그려 두었다.
> 기준이 뒤집혀 **본인 취소를 전면 금지**하기로 하면 [4]는 항상 안내만 남는다. 목업에서 두 경우를 모두 확인할 수 있게 해 두었다.
> 동행 신청에서 **동행자 1명만 취소**하는 경우의 처리도 함께 확정해야 한다 — 현재 화면에는 반영되어 있지 않다.

## 8. 목업 동작 (HTML)

- 입금 상태를 **미매칭 / 부분 매칭 / 매칭** 3개로 전환하면 등록번호·배지·[4] 취소 영역이 정책대로 실제로 바뀐다.
- [신청 취소하기]를 누르면 확인 모달이 뜨고, 확인하면 화면이 실제로 취소 상태로 전이된다.
- POL-004 대안(본인 취소 전면 금지)도 버튼으로 전환해 볼 수 있다.
