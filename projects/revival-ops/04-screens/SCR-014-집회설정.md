## 1. 화면 목적

집회를 만들고 **접수 기간·정원·버퍼·참가비·계좌**를 설정한다. 여기서 정한 값이 사용자 접수 화면과 대시보드에 그대로 반영된다.

## 3. 컴포넌트 트리 (개발 인수인계용)

```jsx
<AdminLayout active="conferences">
  <PageHeader title="집회 생성 · 설정">                {/* [1] */}
    <Button label="+ 새 집회 만들기" onClick={openCreateModal} />
  </PageHeader>

  <ConferenceList                        {/* [2] 운영 중 / 종료·보관 */}
    items={conferences} selected={cur}
    onSelect={setCur} onArchive={archive} />

  <Section title="기본 정보">             {/* [3] */}
    <TextField name="name" required />
    <TextField name="place" required />
    <DateRange name="period" required />
    <Select name="status" options={['운영 중','종료·보관']} />
  </Section>

  <Section title="접수 기간">             {/* [4] POL-001 */}
    <DateTimeField name="applyStartAt" required />
    <DateTimeField name="applyEndAt" required
      validate={v => checkPol001Setting({ applyEndAt: v, startDate })} />  {/* 3일 전 미만이면 경고 */}
  </Section>

  <Section title="정원 · 현장 버퍼">       {/* [5] POL-002 */}
    <NumberField name="totalCapacity" required min={1} />
    <NumberField name="onsiteBuffer" required min={0}
      validate={v => v < totalCapacity || 'MSG_BUFFER_TOO_LARGE'} />
    <Computed label="온라인 접수 차단선"
      value={totalCapacity - onsiteBuffer} />
    <Checkbox name="applyBlocked" label="정원 도달로 접수 차단됨"  {/* POL-044 — 수동으로만 해제 */}
      hint="자동으로 다시 열리지 않습니다." />
  </Section>

  <Section title="참가비 · 계좌">          {/* [6] SCR-006·SCR-012와 대조 (POL-046) */}
    <NumberField name="fee" required />
    <TextField name="account" required />
  </Section>

  <Section title="현장 접수 방침">          {/* [7] POL-003 */}
    <Checkbox name="showNoOnsiteNotice"
      label="사용자 화면·안내문에 「현장 접수 없음」 표기" />
  </Section>

  <ReflectionMap />                        {/* [8] 어디에 반영되는지 명시 (REQ-001 A2-07) */}

  <Footer>                                 {/* [9] 저장 시 변경 이력 기록 (POL-033) */}
    <Button label="이력" onClick={openHistory} />
    <Button label="취소" onClick={reset} />
    <Button primary label="저장" onClick={save} />
  </Footer>
</AdminLayout>
```

## 4. 구성 요소 정의

| # | 요소 | 유형 | 내용/동작 | 관련 정책 |
|---|---|---|---|---|
| 1 | 페이지 헤더 | 공통 | 「집회 생성 · 설정」 + [+ 새 집회 만들기] | |
| 2 | 집회 목록 | 목록 | 집회명·상태·장소·기간. 선택하면 아래 설정이 그 집회 값으로 바뀐다. 종료·보관 집회는 신규 접수를 받지 않는다 | |
| 3 | 기본 정보 | 입력 | 집회명·장소·기간·상태(운영 중 / 종료·보관) | |
| 4 | 접수 기간 | 입력 | 접수 시작·마감 일시(분 단위). **마감이 집회 시작 3일 전보다 늦으면 경고**(저장은 가능) | POL-001 |
| 5 | 정원 · 버퍼 | 입력 | 총 정원, 현장 버퍼. 온라인 차단선(= 정원 − 버퍼)을 실시간 계산해 보여준다. 버퍼 ≥ 정원이면 저장 차단. 「정원 도달로 접수 차단됨」은 **수동으로만 해제** | POL-002, POL-044 |
| 6 | 참가비 · 계좌 | 입력 | 참가비 금액과 입금 계좌. SCR-006·SCR-012의 안내문과 일치해야 한다 | POL-046 |
| 7 | 현장 접수 방침 | 체크 | 켜면 사용자 화면·안내문에 「현장 접수는 받지 않습니다」 문구가 노출된다. 기능(현장 수동 접수)은 끄지 않는다 | POL-003 |
| 8 | 반영 위치 안내 | 정보 | 이 설정이 어느 화면에 반영되는지 나열 — SCR-001 / SCR-006 / SCR-012 / SCR-013 | |
| 9 | 하단 액션 | 버튼 | [이력] 건별 변경 이력, [취소] 원복, [저장] — 저장 시 변경 전후 값이 이력에 기록된다 | POL-033 |

## 5. 상태별 화면

| 상태 | 조건 | 표시 내용 |
|---|---|---|
| 기본 | 운영 중 집회 선택 | 모든 필드 편집 가능 |
| 종료·보관 집회 선택 | 상태 = 종료·보관 | 필드는 읽기 전용. 「종료·보관된 집회입니다. 기록만 조회할 수 있습니다.」 |
| 마감일 경고 | 마감이 집회 시작 3일 전보다 늦음 | [4]에 「접수 마감이 집회 시작 3일 전보다 늦습니다. 숙소 배정과 명찰 출력 시간이 부족할 수 있습니다.」 (저장 가능) |
| 버퍼 오류 | 버퍼 ≥ 총 정원 | [5]에 「현장 버퍼 좌석은 총 정원보다 클 수 없습니다.」 저장 차단 |
| 접수 차단됨 | 정원 도달 | [5] 체크박스 켜짐 + 「자동으로 다시 열리지 않습니다. 다시 받으시려면 정원을 조정하거나 이 항목을 직접 해제하세요.」 (POL-044) |
| 빈 상태 | 집회 0건 | 「아직 만든 집회가 없습니다.」 + [+ 새 집회 만들기] |
| 로딩 / 에러 | 조회 중 / 실패 | 스켈레톤 / 「집회 정보를 불러오지 못했습니다.」 |

## 6. 입력 유효성

| 필드 | 필수 | 형식/제한 | 실패 시 문구 | 관련 정책 |
|---|---|---|---|---|
| 집회명 | Y | 1~50자 | 「집회명을 입력해 주세요.」 | |
| 장소 | Y | 1~50자 | 「장소를 입력해 주세요.」 | |
| 기간 | Y | 시작일 ≤ 종료일 | 「종료일은 시작일 이후로 정해 주세요.」 | |
| 접수 시작 일시 | Y | 분 단위 | 「접수 시작 일시를 입력해 주세요.」 | POL-001 |
| 접수 마감 일시 | Y | 시작 일시 이후, 집회 시작일 이전 | 「접수 마감은 접수 시작 이후여야 합니다.」 / 「접수 마감은 집회 시작일 이전이어야 합니다.」 / 경고: 「접수 마감이 집회 시작 3일 전보다 늦습니다. …」 | POL-001 |
| 총 정원 | Y | 1 이상 정수 | 「총 정원을 1명 이상으로 입력해 주세요.」 | POL-002 |
| 현장 버퍼 | Y | 0 이상, 총 정원 미만 | 「현장 버퍼 좌석은 총 정원보다 클 수 없습니다.」 | POL-002 |
| 참가비 | Y | 0 이상 정수 | 「참가비를 입력해 주세요.」 | |
| 입금 계좌 | Y | 1~50자 | 「입금 계좌를 입력해 주세요.」 | |

## 7. 인터랙션 상세

- [5]의 총 정원·버퍼를 입력하면 **온라인 차단선이 즉시 재계산**되어 표시된다.
- [저장] → 유효성 검사 → 통과 시 「저장되었습니다.」 토스트 + 변경 이력 기록. 실패 시 첫 오류 필드로 스크롤.
- 접수 기간 중 마감을 앞당기면 그 시점부터 즉시 차단된다. 이미 제출된 신청은 유지된다(POL-001).
- [2]에서 다른 집회를 선택하면 저장하지 않은 변경이 있는지 확인한다 — 「저장하지 않은 변경이 있습니다. 이동하시겠습니까?」

## 8. 목업 동작 (HTML)

- **온라인 차단선이 실시간 재계산된다.** 정원·버퍼를 바꿔 보면 즉시 반영된다.
- 버퍼를 정원보다 크게 넣고 [저장]하면 POL-002 검사가 실제로 걸린다.
- 마감일을 집회 시작 2일 전으로 바꾸면 POL-001 경고가 실제로 뜬다(저장은 된다).
- [2]에서 종료·보관 집회를 선택하면 **모든 입력이 실제로 읽기 전용**이 된다.
- [저장] 시 변경 전후 값이 이력 모달에 실제로 쌓인다(POL-033).
