## 1. 화면 목적

**개인 단위 계정**을 발급하고 역할·메뉴 권한을 지정한다. 회(단위) 공용 계정은 만들지 않는다.

## 3. 컴포넌트 트리 (개발 인수인계용)

```jsx
<AdminLayout active="accounts" guard={account.role === '전체 어드민'}>  {/* POL-030 */}
  <PageHeader title="계정 · 권한">                    {/* [1] */}
    <Button primary label="+ 계정 추가" onClick={openCreate}
      disabled={account.role !== '전체 어드민'} />
  </PageHeader>

  <AccountTable rows={accounts}                       {/* [2] */}
    cols={['이름','아이디','역할','소속','접근 메뉴','관리']}
    onEditPermission={openPermission} />

  <PermissionPanel                                    {/* [3] 메뉴 단위 체크 (POL-031) */}
    account={sel}
    roles={['전체 어드민','본부 총괄','본부 팀원','셔틀팀','국내선교팀']}
    menus={ADMIN_MENUS}
    defaults={POL031_DEFAULT_MENUS}
    lockedMenus={['계정·권한']}                        /* 전체 어드민만 (POL-030) */
    onRoleChange={applyDefaults}
    onSave={savePermission} />                        /* 변경 이력 기록 (POL-033) */

  <NoAccountNotice />                                 {/* [4] POL-032 */}

  <CreateModal                                        {/* 개인 단위만 — 공용 계정 금지 (POL-029) */}
    fields={['이름','아이디','초기 비밀번호','역할','소속','외부 팀']}
    onSubmit={createAccount} />
</AdminLayout>
```

## 4. 구성 요소 정의

| # | 요소 | 유형 | 내용/동작 | 관련 정책 |
|---|---|---|---|---|
| 1 | 페이지 헤더 | 공통 | 「계정 · 권한」 + [+ 계정 추가]. **전체 어드민이 아니면 이 화면에 들어올 수 없다** | POL-030 |
| 2 | 계정 목록 | 테이블 | 이름·아이디·역할·소속·접근 메뉴 수·[권한] | |
| 3 | 권한 설정 | 체크 | 역할 선택 시 기본 권한이 적용된다. 메뉴 카테고리 단위로 체크. **계정·권한 메뉴는 전체 어드민만** | POL-030, POL-031 |
| 4 | 미발급 대상 안내 | 정보 | 「집회장 팀장·부팀장은 시스템에 들어올 일이 거의 없어 계정을 발급하지 않습니다.」 외부 팀 중 발급 대상은 셔틀팀뿐 | POL-032 |
| — | 계정 추가 모달 | 모달 | 이름·아이디·초기 비밀번호·역할·소속. **초기 비밀번호는 최초 로그인 시 변경 필수** | POL-029 |

### 역할별 기본 권한 (POL-031)

| 역할 | 기본 접근 메뉴 |
|---|---|
| 전체 어드민 | 전체 (계정 · 권한 포함) |
| 본부 총괄 | 계정 · 권한을 제외한 전체 |
| 본부 팀원 | 계정 · 권한을 제외한 전체 |
| 셔틀팀 | 셔틀 관리만 |
| 국내선교팀 | 접수 · 환불 관리 (인수인계 시 확정 — OI-16) |

| 권한 없음 | 전체 어드민 아님 | 화면 진입 차단. 「계정 추가와 권한 변경은 전체 관리자만 할 수 있습니다.」 + 대시보드로 이동. 시도 사실을 이력에 기록 |
| 마지막 어드민 보호 | 전체 어드민이 1명뿐 | 그 계정의 역할 변경·삭제 차단. 「마지막 전체 관리자 계정은 역할을 바꾸거나 삭제할 수 없습니다.」 |
| 외부 팀 경고 | 셔틀팀 외 외부 팀 계정 발급 | 경고(진행 가능). 「외부 팀 계정은 셔틀팀만 발급하기로 정해져 있습니다. 그래도 발급하시겠습니까?」 발급 시 이력 기록 |

## 6. 입력 유효성

| 필드 | 필수 | 형식/제한 | 실패 시 문구 | 관련 정책 |
|---|---|---|---|---|
| 이름 | Y | 2~20자 | 「이름은 2자 이상 20자 이하로 입력해 주세요.」 | POL-042 |
| 아이디 | Y | 영문·숫자 4~20자, 중복 불가 | 「아이디는 영문·숫자 4~20자로 입력해 주세요.」 / 「이미 사용 중인 아이디입니다.」 | |
| 초기 비밀번호 | Y | 8자 이상 | 「초기 비밀번호는 8자 이상으로 입력해 주세요.」 | POL-029 |
| 역할 | Y | 5개 역할 중 하나 | 「역할을 선택해 주세요.」 | POL-031 |
| 소속 | N | 1~20자 | — | |

## 7. 인터랙션 상세

- 역할을 바꾸면 **기본 권한이 자동 적용**된다. 그 뒤 개별 메뉴를 추가·제거할 수 있다(POL-031).
- 권한 없는 메뉴는 그 계정의 화면에서 **노출되지 않고**, URL로 직접 접근해도 차단된다.
- 계정 발급·역할 변경·권한 변경은 모두 이력에 기록된다(POL-033).
- 비밀번호 분실 시 전체 어드민이 초기 비밀번호를 재발급하고, 사용자는 최초 로그인처럼 변경해야 한다.
- **본부 인원의 메뉴를 임의로 좁히지 않는다.** 날짜에 따라 담당 업무가 접수에서 상담으로 이동하기 때문이다(POL-031 배경).

## 8. 목업 동작 (HTML)

- 계정 행 [권한]을 누르면 **권한 패널이 실제로 그 계정 값으로 채워진다.**
- **역할을 바꾸면 체크박스가 기본 권한으로 실제로 재설정**된다(셔틀팀 → 셔틀 관리 1개만).
- 「계정·권한」 메뉴는 전체 어드민이 아닌 역할에서 **체크가 실제로 잠긴다**(POL-030).
- **마지막 전체 어드민의 역할을 바꾸려 하면 실제로 차단**된다.
- 셔틀팀이 아닌 외부 팀 계정을 발급하려 하면 경고 확인이 뜬다(POL-032).
- [권한 없는 계정으로 보기]를 누르면 이 화면 진입 차단 화면을 볼 수 있다(POL-030).
