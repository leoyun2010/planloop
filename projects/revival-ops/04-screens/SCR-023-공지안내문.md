## 1. 화면 목적

사용자에게 보이는 공지·일정·안내문을 관리하고, 문자 템플릿과 발신번호를 설정한다.

## 5. 상태별 화면

| 상태 | 조건 | 표시 내용 |
|---|---|---|
| 기본 | 항목 있음 | 탭별 목록 |
| 빈 상태 (공지) | 공지 0건 | 「등록된 공지가 없습니다.」 + [+ 공지 작성] |
| 빈 상태 (안내문) | 항목 0건 | 「등록된 안내문 항목이 없습니다.」 |
| 계좌 불일치 | 안내문 계좌 ≠ 집회 설정 | 경고. 「안내문에 적힌 참가비·계좌가 집회 설정과 다릅니다. 확인해 주세요.」 사용자 화면에는 경고를 노출하지 않는다 |
| 발신번호 미등록 | `senderNumberVerified = false` | 문자 발송 실행 시 차단. 「발신번호가 등록되지 않아 문자를 보낼 수 없습니다. [계정·설정]에서 발신번호를 먼저 등록해 주세요.」 |
| 문자 미도입 | `sms.enabled = false` | 템플릿 편집은 가능하지만 발송되지 않는다. 「도입 여부가 결정되지 않았습니다.」 (POL-034 · OI-15) |
| 로딩 / 에러 | 조회 중 / 실패 | 스켈레톤 / 「콘텐츠를 불러오지 못했습니다.」 |

## 7. 인터랙션 상세

- 게시 여부를 바꾸면 **사용자 화면(SCR-009, SCR-012)에 즉시 반영**된다(POL-046).
- 안내문 순서를 바꾸면 사용자 보관함의 표시 순서가 그대로 따라간다.
- 참가비·계좌 안내는 집회 설정(SCR-014)과 자동 대조한다. 다르면 관리자에게만 경고를 띄운다.
- 발신번호 사전등록 없이는 문자 발송을 실행하지 않는다. 미도입 상태에서도 템플릿은 미리 만들어 둘 수 있다.

> **POL-034는 검토중이다**(오픈 이슈 OI-15, 담당 총괄, 기한 D-45). 유료 문자 도입 여부가 결정되지 않았다.
> 도입하지 않으면 SCR-006·SCR-008의 화면 안내만으로 안내가 완결되어야 한다.

## 8. 목업 동작 (HTML)

- **탭 4개가 실제로 전환**된다.
- 공지의 게시 토글을 끄면 「사용자 화면에서 즉시 사라집니다」 안내가 뜨고 목록 표시가 바뀐다(POL-046).
- 안내문 [▲][▼]로 **순서가 실제로 바뀐다.**
- **[계좌 바꿔보기]로 집회 설정과 어긋나게 만들면 경고가 실제로 뜬다**(POL-046 검증 포인트).
- 문자 탭에서 발신번호를 등록하지 않은 채 [테스트 발송]을 누르면 **실제로 차단**된다(POL-034).
- 발신번호를 등록하면 상태가 「등록 완료」로 바뀌고 발송이 가능해진다.
