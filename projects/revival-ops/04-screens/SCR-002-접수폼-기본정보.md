## 1. 화면 목적

참가자의 이름·휴대폰·지역·성별과 참가 구분을 받는다. 참가 구분이 다음 단계 경로를 결정한다.

## 3. 컴포넌트 트리 (개발 인수인계용)

<ApplyStep1Page>

  <TextField name="name" label="이름" required                {/* [3] 2~20자 (POL-042) */}

  <TextField name="region" label="지역" required              {/* [5] 1~20자 (POL-042) */} />

## 4. 구성 요소 정의

| # | 요소 | 유형 | 내용/동작 | 관련 정책 |
|---|---|---|---|---|
| 1 | 상단 헤더 | 공통 | 「집회 신청 · 1/4」 + 「기본 정보」 | |
| 2 | 단계 진행 바 | 정보 | 전체 4단계 중 1단계. 진행률 25% | |
| 3 | 이름 | 입력(필수) | 2~20자. 앞뒤 공백 제거 후 저장 | POL-042 |
| 4 | 휴대폰 번호 | 입력(필수) | 숫자 10~11자리. 하이픈·공백 제거 후 저장. 입력 완료 시 중복 검사 | POL-042, POL-037 |
| 5 | 지역 | 입력(필수) | 1~20자 | POL-042 |
| 6 | 성별 | 선택(필수) | 남 / 여 | POL-042 |
| 7 | 참가 구분 | 선택(필수) | 참여자 / 인도자. 인도자 선택 시 다음 단계가 SCR-003, 참여자면 SCR-004 | POL-042 |
| 8 | 중복 신청 안내 | 경고 | 같은 번호의 신청이 있으면 표시. **차단하지 않는다.** [계속 신청] / [내 신청 확인하기] 2개 버튼 | POL-037 |
| 9 | 다음 버튼 | 버튼 | 유효성 통과 시 다음 단계로. 실패 시 해당 필드에 오류 표시하고 진행 차단 | POL-042 |

## 5. 상태별 화면

| 상태 | 조건 | 표시 내용 |
|---|---|---|
| 기본 | 진입 직후 | 빈 폼. [9] 활성(누르면 유효성 검사) |
| 입력 오류 | 필수값 미입력·형식 위반 | 해당 필드 테두리 빨강 + 필드 하단 오류 문구. 진행 차단 |
| 중복 경고 | 같은 휴대폰 번호의 신청 존재 | [8] 노출. 진행은 가능 (POL-037) |
| 로딩 | 중복 검사 조회 중 | [4] 우측에 로딩 표시. [9] 잠시 비활성 |
| 에러 | 중복 검사 실패 | 검사를 건너뛰고 진행을 허용한다(신청을 막지 않는다). 토스트 「지금은 기존 신청 내역을 확인할 수 없습니다.」 |
| 접수 마감 | 마감 이후 URL 직접 접근 | SCR-001로 돌려보내고 마감 문구 표시 (POL-001) |

빈 상태: 해당 없음.

## 6. 입력 유효성

| 필드 | 필수 | 형식/제한 | 실패 시 문구 | 관련 정책 |
|---|---|---|---|---|
| 이름 | Y | 2~20자 | 미입력: 「이름을 입력해 주세요.」 / 길이: 「이름은 2자 이상 20자 이하로 입력해 주세요.」 | POL-042 |
| 휴대폰 번호 | Y | 숫자 10~11자리 | 미입력: 「휴대폰 번호를 입력해 주세요.」 / 형식: 「휴대폰 번호는 숫자 10~11자리로 입력해 주세요.」 | POL-042 |
| 지역 | Y | 1~20자 | 「지역을 입력해 주세요.」 | POL-042 |
| 성별 | Y | 남 / 여 | 「성별을(를) 선택해 주세요.」 | POL-042 |
| 참가 구분 | Y | 참여자 / 인도자 | 「참가 구분을(를) 선택해 주세요.」 | POL-042 |
| (중복) | - | 같은 번호 신청 존재 | 경고: 「이 번호로 접수된 신청이 이미 있습니다. 새로 신청하시려면 그대로 진행하시고, 신청 내역을 확인하시려면 [내 신청 확인하기]를 눌러 주세요.」 | POL-037 |

## 7. 인터랙션 상세

- 휴대폰 입력 후 포커스 이탈 → 중복 검사 → 있으면 [8] 표시(진행은 계속 가능).
- [9] 클릭 → 5개 필드 순서대로 검사 → 첫 실패 필드로 스크롤·포커스 → 통과 시 참가 구분에 따라 SCR-003(인도자) 또는 SCR-004(참여자)로 이동.
- 다음 단계에서 뒤로 돌아오면 입력값이 유지된다.

## 8. 목업 동작 (HTML)

- 5개 필드 유효성 검사가 실제로 동작한다(POL-042 의사코드를 `_wf.js`의 `WF.checkName` / `WF.checkPhone`으로 구현).
- 휴대폰에 `01000000000`을 넣고 포커스를 빼면 중복 경고(POL-037)가 실제로 뜬다. 차단되지 않는다.
- 참가 구분을 바꾸면 [9] 버튼 문구와 다음 단계 안내가 실제로 바뀐다.
