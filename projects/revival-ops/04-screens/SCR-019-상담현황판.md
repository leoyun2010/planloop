## 1. 화면 목적

**상담실 실시간 상태와 결과 집계를 보는 곳.** 종이 결과지를 받아 결과와 간증 가능 여부를 입력한다.
(누구를 어디 배치할지는 SCR-021, 진행 상태를 바꾸는 것은 SCR-020 — 세 화면의 역할이 나뉘어 있다. POL-036)

## 3. 컴포넌트 트리 (개발 인수인계용)

```jsx
<AdminLayout active="counseling">
  <PageHeader title="상담 현황판" crumb={`${today} · ${asOf} 기준`} />   {/* [1] */}

  <StatRow>                                          {/* [2] POL-024 — 결과 활용 2목적 */}
    <Stat label="오늘 상담"   value={sessions.length} />
    <Stat label="해결"        value={count('해결')} />
    <Stat label="재상담 필요" value={count('재상담 필요')} />
    <Stat label="간증 가능"   value={countTestimony('가능')} />
  </StatRow>

  <RoomStatusGrid                                    {/* [3] 실시간 공유 (POL-036) */}
    rooms={rooms}                                    /* 상담 중 / 공실 / 미사용 */
    onChange={(room, status) => updateRoom(room, status)} />

  <ResultTable rows={sessions}>                      {/* [4] 종이 결과지 기반 입력 (POL-023) */}
    <Col name="time" /><Col name="name" /><Col name="counselor" /><Col name="room" />
    <Col name="result"    render={r => <Chip label={r.result ?? '미입력'} />} />
    <Col name="testimony" render={r => <Chip label={r.testimony ?? '미입력'} />} />
    <Col name="actions"   render={r => <Button label={r.result ? '수정' : '결과 입력'}
                                        onClick={openResult(r)} />} />
  </ResultTable>

  <TestimonyList                                     {/* [5] 결과와 무관하게 간증 항목만 본다 */}
    rows={sessions.filter(s => s.testimony === '가능')}
    onExport={exportCsv} />                          /* 내보내기는 이력 기록 (POL-041) */

  <ResultModal                                       {/* 결과·간증을 별도 항목으로 (POL-024) */}
    results={['해결','재상담 필요','미해결']}
    testimonies={['가능','본인 거절','해당 없음']}
    onSubmit={saveResult} />                         /* SCR-020 드로어와 같은 데이터 */
</AdminLayout>
```

## 4. 구성 요소 정의

| # | 요소 | 유형 | 내용/동작 | 관련 정책 |
|---|---|---|---|---|
| 1 | 페이지 헤더 | 공통 | 「상담 현황판」 + 날짜·기준 시각 | |
| 2 | 상담 지표 | 지표 | 오늘 상담 / 해결 / 재상담 필요 / 간증 가능 4종 | POL-024 |
| 3 | 상담실 상태 | 카드 | 상담실별 상담 중 / 공실 / 미사용 + 담당 상담사 + 경과 시간. 수정하면 다른 관리자 화면에도 반영 | POL-036 |
| 4 | 결과 입력 | 테이블 | 시각·이름·상담사·상담실·결과·간증 가능 여부·관리. 상담사가 적어 온 종이 결과지를 본부가 입력 | POL-023, POL-024 |
| 5 | 간증자 컨택 명단 | 목록 | 간증 가능으로 입력된 인원만. [명단 내보내기] 시 이력 기록 | POL-024, POL-041 |
| — | 결과 입력 모달 | 모달 | 결과(해결/재상담 필요/미해결)와 간증 가능 여부(가능/본인 거절/해당 없음)를 **별도로** 입력. 상담 요약은 선택 | POL-024 |

## 5. 상태별 화면

| 상태 | 조건 | 표시 내용 |
|---|---|---|
| 기본 | 오늘 상담 있음 | 지표·상담실·결과 목록 |
| 빈 상태 | 오늘 상담 0건 | 「오늘 진행된 상담이 없습니다.」 |
| 결과 미입력 | 종료 상담인데 결과 없음 | 경고. 「결과가 입력되지 않은 종료 상담이 {n}건 있습니다.」 (POL-023) |
| 미사용 상담실 | 상태 = 미사용 | 배치 대상에서 제외됨을 표시 |
| 로딩 / 에러 | 조회 중 / 실패 | 스켈레톤 / 「상담 현황을 불러오지 못했습니다.」 |

## 6. 입력 유효성

| 필드 | 필수 | 형식/제한 | 실패 시 문구 | 관련 정책 |
|---|---|---|---|---|
| 상담 결과 | Y | 해결 / 재상담 필요 / 미해결 | 「상담 결과를 선택해 주세요.」 | POL-024 |
| 간증 가능 여부 | Y | 가능 / 본인 거절 / 해당 없음 | 「간증 가능 여부를 선택해 주세요.」 | POL-024 |
| 상담 요약 | N | 최대 500자 | 「500자 이내로 입력해 주세요.」 | POL-042 |

**결과가 「해결」이어도 간증 가능을 자동 설정하지 않는다.** 두 값을 연동하면 정책 위반이다(POL-024).

## 7. 인터랙션 상세

- [3] 상담실 상태를 바꾸면 즉시 저장되고 다른 관리자 화면에 반영된다(POL-036).
- [4] 결과 입력 → 지표([2])와 간증자 명단([5])에 즉시 반영된다.
- **같은 건을 이 화면과 SCR-020 타임라인 드로어 어디에서 입력해도 같은 데이터에 기록된다**(POL-036).
- 상담 결과는 사용자 화면에 노출하지 않는다. 집계와 간증자 컨택 두 목적으로만 쓴다(POL-024).

> **POL-023은 미확정이다**(오픈 이슈 OI-14). 종이 상담 신청서 포맷이 정해지지 않아 입력 항목이 늘어날 수 있다.

## 8. 목업 동작 (HTML)

- 상담실 상태를 바꾸면 카드가 실제로 전환되고, 미사용으로 바꾼 방은 배치 대상 제외로 표시된다.
- 결과를 입력하면 **상단 지표 4종이 실시간으로 바뀌고** 간증자 명단이 갱신된다.
- **결과를 「해결」로 골라도 간증 가능이 자동으로 켜지지 않는다**(POL-024 검증 포인트).
- 결과 미입력 종료 상담이 있으면 경고가 실제로 뜬다.
- [명단 내보내기]는 이력 기록 안내를 띄운다(POL-041).
