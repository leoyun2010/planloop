## 1. 화면 목적

접수가 끝났음을 알리고, **등록번호는 입금 확인 후 발급된다**는 점과 참가비·계좌·입금자명 규칙을 안내한다.

## 3. 컴포넌트 트리 (개발 인수인계용)

```jsx
<ApplyDonePage>
  <MobileHeader title="접수되었습니다" sub="신청 완료" />   {/* [1] */}

  <DoneNotice                          {/* [2] 등록번호는 입금 확인 후 발급 (POL-038) */}
    regNo={participant.regNo}           /* 없으면 "미발급" 표시 */
    message="신청이 접수되었습니다. 등록번호는 입금 확인 후 발급됩니다." />

  <PaymentGuide                        {/* [3] 집회 설정값 그대로 표시 */}
    count={application.totalCount}
    fee={conf.fee}
    amount={application.totalCount * conf.fee}
    account={conf.account}
    depositorNotice="입금자명은 신청자 이름으로 보내 주세요." />

  <PaymentDelayNotice />               {/* [4] 상시 노출 — 미노출은 정책 위반 (POL-007) */}

  <SmsSentNotice                       {/* [5] 문자 미도입 시 렌더하지 않는다 (POL-034) */}
    visible={smsConfig.enabled && smsConfig.templates.등록완료.inUse} />

  <SecondaryButton label="안내문 전체 보기" onClick={goto("SCR-012")} />  {/* [6] */}
  <PrimaryButton   label="내 신청 확인하기" onClick={goto("SCR-007")} />  {/* [7] */}
</ApplyDonePage>
```

## 4. 구성 요소 정의

| # | 요소 | 유형 | 내용/동작 | 관련 정책 |
|---|---|---|---|---|
| 1 | 상단 헤더 | 공통 | 「신청 완료」 + 「접수되었습니다」 | |
| 2 | 접수 완료 안내 | 정보 | 「신청이 접수되었습니다. 등록번호는 입금 확인 후 발급됩니다.」 등록번호 자리에 「미발급」 표시 | POL-038 |
| 3 | 참가비·계좌 안내 | 정보 | 신청 인원 × 참가비 = 총 입금액. 계좌·예금주는 집회 설정값 그대로. 「입금자명은 신청자 이름으로 보내 주세요.」 | POL-046 |

| 5 | 문자 발송 안내 | 정보 | 문자를 도입한 경우에만 표시. 미도입 시 이 화면 안내만으로 완결되어야 한다 | POL-034 |

| 7 | 내 신청 확인하기 | 버튼 | SCR-007 본인 확인 → SCR-008 마이페이지 | POL-029 |

## 5. 상태별 화면

| 상태 | 조건 | 표시 내용 |
|---|---|---|
| 기본 (개인 신청) | 총 인원 1명 | [3]에 「80,000원」 단일 금액 |
| 동행 신청 | 총 인원 2명 이상 | [3]에 「80,000원 × {n} = {합계}원」. 안내 「대표(인도자) 한 분이 한 번에 입금하셔도 됩니다.」 |
| 문자 도입 | `smsConfig.enabled` | [5] 표시 「안내 문자를 보냈습니다.」 |
| 문자 미도입 | 기본값 | [5] 숨김. [4]와 [7]만으로 안내 완결 (POL-034 예외) |
| 로딩 | 신청 결과 조회 중 | [2][3] 스켈레톤 |
| 에러 | 신청 결과 조회 실패 | 「신청 정보를 불러오지 못했습니다. 잠시 후 [내 신청 확인하기]로 확인해 주세요.」 — 신청 자체는 이미 저장된 상태이므로 재신청을 유도하지 않는다 |

빈 상태: 해당 없음.

## 7. 인터랙션 상세

- 이 화면은 뒤로 가기로 SCR-005에 다시 돌아갈 수 없다(중복 신청 방지). 뒤로 가면 SCR-001로 보낸다.
- [7] → SCR-007 본인 확인 → 방금 신청한 휴대폰·이름으로 조회하면 SCR-008 마이페이지가 열린다.
- 등록번호는 이 시점에 존재하지 않는다. 관리자가 입금 매칭(SCR-016)을 완료해야 발급된다(POL-038).

## 8. 목업 동작 (HTML)

- 인원 수를 바꾸면 총 입금액이 실제로 재계산된다(1명 / 3명 전환 버튼).
- 문자 도입 여부(POL-034)를 토글하면 [5] 블록이 실제로 나타나고 사라진다.
- 등록번호는 항상 「미발급」이며, [입금 확인됨으로 가정] 버튼을 누르면 POL-038 형식(`20260619-0021`)으로 채워지는 것을 보여준다.
