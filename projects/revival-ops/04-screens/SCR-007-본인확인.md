## 1. 화면 목적

회원가입·비밀번호 없이 **신청 시 입력한 휴대폰 번호와 이름**으로 본인을 확인해 마이페이지로 보낸다.

## 2. 레이아웃 (텍스트 와이어프레임)

```
+------------------------------------------+
| [1] 내 신청 확인                          |
|     본인 확인                             |
+------------------------------------------+
| [2] 신청하실 때 적으신 휴대폰 번호와      |
|     이름을 넣어 주세요.                   |
|     따로 가입하거나 비밀번호를 만들지     |
|     않으셔도 됩니다.                      |
|                                          |
| [3] 휴대폰 번호 *                         |
|     [ 010-0000-0000                    ]  |
|                                          |
| [4] 이름 *                                |
|     [ 예) 김복음                       ]  |
|                                          |
| [5] [        확인하기                  ]  |
|                                          |
| [6] +------------------------------------+|
|     | 입력하신 정보와 일치하는 신청      ||
|     | 내역이 없습니다.                   ||
|     | 본부 접수처 010-0000-0000          ||
|     |                    [ 전화 걸기 ]   ||
|     +------------------------------------+|
+------------------------------------------+
| [7] 접수 | 공지/일정 | 셔틀 | 마이페이지  |
+------------------------------------------+
```

## 3. 컴포넌트 트리 (개발 인수인계용)

```jsx
<AuthPage>
  <MobileHeader title="본인 확인" sub="내 신청 확인" />   {/* [1] */}
  <AuthGuideText />                                       {/* [2] */}

  <TextField name="phone" label="휴대폰 번호" required     {/* [3] 하이픈 무관 (POL-029) */}
    inputMode="numeric" validate={WF.checkPhone} />
  <TextField name="name" label="이름" required             {/* [4] */}
    validate={WF.checkName} />

  <PrimaryButton label="확인하기"                          {/* [5] 둘 다 일치해야 통과 (POL-029) */}
    onClick={submit}
    disabled={rateLimited} />                              /* [5] 10분 10회 초과 시 차단 (POL-040) */

  <AuthFailNotice                    {/* [6] 실패·차단 시 본부 연락처와 함께 */}
    visible={failed || rateLimited}
    message={rateLimited ? MSG_TOO_MANY_ATTEMPTS : MSG_NO_MATCHING_APPLICATION}
    tel={conf.deskTel} />

  <BottomTabBar active="myinfo" />   {/* [7] */}
</AuthPage>
```

## 4. 구성 요소 정의

| # | 요소 | 유형 | 내용/동작 | 관련 정책 |
|---|---|---|---|---|
| 1 | 상단 헤더 | 공통 | 「내 신청 확인」 + 「본인 확인」 | |
| 2 | 안내 문구 | 정보 | 「신청하실 때 적으신 휴대폰 번호와 이름을 넣어 주세요. 따로 가입하거나 비밀번호를 만들지 않으셔도 됩니다.」 | POL-029 |
| 3 | 휴대폰 번호 | 입력(필수) | 숫자 10~11자리. 하이픈·공백 유무와 무관하게 조회 | POL-029, POL-042 |
| 4 | 이름 | 입력(필수) | 2~20자. 앞뒤 공백 제거 후 대조 | POL-042 |
| 5 | 확인하기 | 버튼 | 휴대폰과 이름이 **모두** 일치할 때만 SCR-008 이동 | POL-029 |
| 6 | 실패 안내 | 정보 | 불일치: 「입력하신 정보와 일치하는 신청 내역이 없습니다. 본부 접수처(연락처)로 문의해 주세요.」 / 차단: 「조회 시도가 너무 많습니다. 10분 후에 다시 시도해 주세요. 급하시면 본부 접수처(연락처)로 문의해 주세요.」 본부 번호와 [전화 걸기] 함께 노출 | POL-029, POL-040 |
| 7 | 하단 탭바 | 공통 | 마이페이지 탭 활성 | |

## 5. 상태별 화면

| 상태 | 조건 | 표시 내용 |
|---|---|---|
| 기본 | 진입 직후 | 빈 폼. [6] 숨김 |
| 조회 중 | 요청 처리 중 | [5] 비활성 + 「확인하는 중입니다…」 |
| 실패 (불일치) | 일치 신청 없음 | [6] 노출. 입력값은 유지 |
| 차단 | 동일 IP 10분간 10회 초과 | [5] 비활성 + [6]에 차단 문구. 남은 시간 표시. 시도 사실을 서버에 기록 |
| 성공 | 휴대폰·이름 일치 | SCR-008로 이동 |
| 에러 | 서버 오류 | 「지금은 조회할 수 없습니다. 잠시 후 다시 시도해 주세요.」 + [다시 시도] |

빈 상태: 해당 없음.

## 6. 입력 유효성

| 필드 | 필수 | 형식/제한 | 실패 시 문구 | 관련 정책 |
|---|---|---|---|---|
| 휴대폰 번호 | Y | 숫자 10~11자리 | 「휴대폰 번호를 입력해 주세요.」 / 「휴대폰 번호는 숫자 10~11자리로 입력해 주세요.」 | POL-042 |
| 이름 | Y | 2~20자 | 「이름을 입력해 주세요.」 / 「이름은 2자 이상 20자 이하로 입력해 주세요.」 | POL-042 |
| (조회 결과) | - | 휴대폰+이름 동시 일치 | 「입력하신 정보와 일치하는 신청 내역이 없습니다. 본부 접수처(연락처)로 문의해 주세요.」 | POL-029 |
| (시도 제한) | - | 10분 10회 | 「조회 시도가 너무 많습니다. 10분 후에 다시 시도해 주세요. 급하시면 본부 접수처(연락처)로 문의해 주세요.」 | POL-040 |

## 7. 인터랙션 상세

- 본인 확인을 거치지 않고 `/me`로 직접 접근하면 이 화면으로 돌려보낸다(POL-029).
- 동행자로 등록된 인원도 **본인의** 휴대폰과 이름으로 조회된다(대표자 정보로만 조회되는 것이 아니다).
- 실패할 때마다 시도 횟수가 누적된다. 10회를 넘기면 10분간 [5]가 비활성화되고 남은 시간이 표시된다.
- 성공해도 세션 유효 시간이 지나면 다시 본인 확인을 요구한다.

## 8. 목업 동작 (HTML)

- 모의 명단 3건(김복음/이믿음/박소망)으로 **조회가 실제로 동작한다.** 일치하면 성공, 아니면 [6]이 뜬다.
- 하이픈을 넣든 빼든 같은 결과가 나온다(정규화 검증).
- **10회 실패하면 실제로 차단**되고 남은 시간이 카운트다운된다(POL-040). [시도 횟수 초기화] 버튼으로 되돌린다.
