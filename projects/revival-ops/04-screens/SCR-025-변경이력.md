## 1. 화면 목적

**누가 무엇을 언제 왜 바꿨는지** 조회한다. 데이터가 이상해졌을 때 원인을 찾는 시간을 줄이는 것이 목적이다.

## 3. 컴포넌트 트리 (개발 인수인계용)

```jsx
<AdminLayout active="logs">
  <PageHeader title="변경 이력" summary={`총 ${total}건`} />   {/* [1] */}

  <Toolbar>
    <TabBar data-tabs="area"                         {/* [2] POL-033 기록 대상 7영역 */}
      items={['전체','접수','입금','환불','숙소','상담','셔틀','설정']} />
    <Select name="actor" options={actors} />         /* 담당자별 필터 */
    <DateRange name="period" />
    <SearchInput placeholder="이름·등록번호" />      /* 특정 참가자 추적 */
  </Toolbar>

  <LogTable rows={visibleRows} readOnly>             {/* [3] 최신순 */}
    <Col name="at" />
    <Col name="actor" />
    <Col name="area" render={r => <Chip label={r.area} />} />
    <Col name="action" />
    <Col name="target" />
    <Col name="detail" render={r => (
      <>
        <Diff before={r.before} after={r.after} />   {/* 변경 전 → 후 */}
        {r.reason && <Reason>사유: {r.reason}</Reason>}
      </>
    )} />
  </LogTable>

  <Pagination />
  <ImmutableNotice />                                {/* [4] 수정·삭제 불가 (POL-033) */}
</AdminLayout>
```

> 각 관리 화면의 [이력] 버튼은 **같은 데이터를 그 건으로 필터링해** 팝업으로 보여준다(REQ-069).

## 4. 구성 요소 정의

| # | 요소 | 유형 | 내용/동작 | 관련 정책 |
|---|---|---|---|---|
| 1 | 페이지 헤더 | 공통 | 「변경 이력」 + 총 건수 | |
| 2 | 필터 | 탭/입력 | 영역 탭 8종(전체 + 7영역), 담당자 선택, 기간, 이름·등록번호 검색 | POL-033 |
| 3 | 이력 테이블 | 테이블 | **최신순.** 일시·담당자·영역·처리·대상·변경 전후·사유. **읽기 전용** | POL-033 |
| 4 | 불변 안내 | 정보 | 「기록된 이력은 수정·삭제할 수 없습니다.」 | POL-033 |

### 기록 대상 (POL-033)

| 영역 | 기록 대상 | 사유 입력 |
|---|---|---|
| 접수 | 등록, 정보 수정, 접수 취소 | 취소만 필수 |
| 입금 | 자동·수동·분할 매칭, 매칭 해제, 엑셀 업로드 | 선택 |
| 환불 | 환불 처리 | 필수 |
| 숙소 | 배정, 이동, 교환, 해제, 보류 지정, 메모 | 선택 |
| 상담 | 배치, 배치 변경, 진행 상태 변경, 결과 입력, 장소 변경 | 선택 |
| 셔틀 | 요청 등록, 배차 확정, 배차 취소, 탑승 확인 | 취소만 필수 |
| 설정 | 집회 설정, 계정·권한, **명단 내보내기** | 선택 |

**조회는 기록 대상이 아니다.** 다만 명단 내보내기는 개인정보가 외부로 나가므로 기록한다(POL-041).

## 5. 상태별 화면

| 상태 | 조건 | 표시 내용 |
|---|---|---|
| 기본 | 이력 있음 | 최신순 목록 |
| 빈 상태 | 조건에 맞는 이력 0건 | 「조건에 맞는 변경 기록이 없습니다.」 |
| 이력 없음 | 전체 0건 | 「아직 기록된 변경이 없습니다.」 |
| 건별 조회 | 관리 화면에서 진입 | 그 건의 기록만 팝업으로 표시 |
| 로딩 | 조회 중 | 스켈레톤 (건수가 많아도 첫 화면 2초 이내 — NFR-002) |
| 에러 | 조회 실패 | 「변경 이력을 불러오지 못했습니다.」 + [다시 시도] |

## 6. 입력 유효성

입력 폼 없음 — **읽기 전용 화면이다.** 이력을 수정·삭제하는 기능을 만들지 않는다(POL-033).

## 7. 인터랙션 상세

- 영역 탭·담당자·기간·검색은 함께 적용된다.
- 이름 또는 등록번호로 검색하면 **그 참가자에게 일어난 변경만** 시간순으로 볼 수 있다(REQ-069).
- 이력 기록에 실패하면 **원 처리도 함께 실패시킨다.** 기록 없는 변경을 만들지 않는다(POL-033).
- 각 관리 화면의 [이력] 버튼은 이 데이터를 그 건으로 필터링해 팝업으로 연다.

## 8. 목업 동작 (HTML)

- **영역 탭 8종 · 담당자 필터 · 기간 · 검색이 모두 실제로 동작**하고 함께 적용된다.
- 「김복음」으로 검색하면 그 사람에게 일어난 변경만 남는다(REQ-069 검증 포인트).
- **변경 전 → 후와 사유가 각 행에 실제로 표시**된다.
- 수정·삭제 버튼이 화면에 존재하지 않는다(POL-033 검증 포인트).
- [명단 내보내기 기록 보기] 필터로 POL-041 관련 기록을 확인할 수 있다.
