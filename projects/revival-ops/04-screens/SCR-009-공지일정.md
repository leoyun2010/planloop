## 1. 화면 목적

관리자가 게시한 공지와 그날의 일정을 참가자가 열람한다. **사용자는 열람만 가능하다.**

## 3. 컴포넌트 트리 (개발 인수인계용)

```jsx
<NoticePage>
  <MobileHeader title="공지 · 일정" sub={conf.name} />   {/* [1] */}

  <TabBar value={tab} onChange={setTab}                  {/* [2] */}
    items={['오늘 일정', '전체 일정', '공지']} />

  <ScheduleList                        {/* [3] 해당 날짜, 시간 오름차순 (POL-046) */}
    date={tab === '오늘 일정' ? today : null}
    items={schedules}
    emptyText="오늘 등록된 일정이 없습니다." />

  <NoticeList                          {/* [4] 게시 상태만, 최신순 (POL-046) */}
    items={notices.filter(n => n.published)}
    emptyText="아직 등록된 공지가 없습니다."
    readOnly />                        {/* 사용자 화면에서 수정·삭제 불가 (POL-046) */}

  <PaperNotice />                      {/* [5] 어르신 배포용 병행 안내 (P2·선택) */}
  <BottomTabBar active="notice" />     {/* [6] */}
</NoticePage>
```

## 4. 구성 요소 정의

| # | 요소 | 유형 | 내용/동작 | 관련 정책 |
|---|---|---|---|---|
| 1 | 상단 헤더 | 공통 | 집회명 + 「공지 · 일정」 | |

| 3 | 일정 목록 | 목록 | 해당 날짜의 일정을 **시간 오름차순**으로 표시. 시간·일정명·장소 | POL-046 |
| 4 | 공지 목록 | 목록 | **게시 상태인 공지만** 최신순. 제목·날짜·본문 | POL-046 |
| 5 | 종이 배포 안내 | 정보 | 「시간표·연대표는 접수처에서 종이로도 받으실 수 있습니다.」 (P2·선택) | |
| 6 | 하단 탭바 | 공통 | 공지/일정 탭 활성 | |

## 5. 상태별 화면

| 상태 | 조건 | 표시 내용 |
|---|---|---|
| 기본 | 공지·일정 있음 | [3][4] 목록 표시 |
| 빈 상태 (일정) | 해당 날짜 일정 0건 | 「오늘 등록된 일정이 없습니다.」 — 빈 화면을 두지 않는다 (POL-046) |
| 빈 상태 (공지) | 게시 공지 0건 | 「아직 등록된 공지가 없습니다.」 |
| 로딩 | 조회 중 | 스켈레톤 3줄 |
| 에러 | 조회 실패 | 「공지를 불러오지 못했습니다.」 + [다시 시도] |
| 접수 마감 후 | 마감 이후 | 이 화면은 정상 동작한다. 마감은 신규 신청만 차단한다 (POL-001 예외) |

## 6. 입력 유효성

입력 폼 없음 — 해당 없음. 사용자 화면에서 공지·일정을 작성·수정·삭제할 수 없다(POL-046).

## 7. 인터랙션 상세

- 탭 전환은 화면 이동 없이 목록만 교체한다.
- 관리자가 SCR-023에서 공지를 비게시로 바꾸면 이 화면에서 **즉시** 사라진다(POL-046).
- 공지 카드를 눌러 본문을 펼친다(아코디언). 별도 상세 화면을 두지 않는다.

## 8. 목업 동작 (HTML)

- 탭 3개가 실제로 전환된다.
- [공지 전부 비게시로] 버튼으로 **POL-046의 게시 필터와 빈 상태 문구**가 실제로 동작하는 것을 확인할 수 있다.
- 공지 카드를 누르면 본문이 펼쳐진다.
