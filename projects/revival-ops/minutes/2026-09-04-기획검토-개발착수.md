## 원문


회의 요약
이번 회의는 청년부 관련 앱(숙소 배치, 상담 관리, 접수 배치, 셔틀 관리 등) 개발을 위한 기획 검토 및 개발 착수를 논의하는 자리였다.

화면 기획서를 기반으로 숙소 배치도와 상담 스케줄 기능에 대해 채린 자매로부터 피드백을 받았으며, 1~2층 배치 구조, 특이사항 표시, 상담 기록의 민감성 등에 대한 의견이 오갔다.

참석자들은 기획을 추가로 다듬기보다 현재 수준에서 충분하다고 판단하여 바로 개발에 착수하기로 결정했고, 백엔드 언어와 프레임워크, 인프라(서버, 도메인) 준비에 대해서도 논의했다.

마지막으로 개발 킥오프 일정을 9월 9일로 확정하고 회의를 마무리했다.

주요 논의
기획 검토 방식: 개인이 모은 기획 체크리스트를 기준으로 AI(플러스 플러스)를 활용해 1차 검토 후 재검토 진행

숙소 배치도 기능: 구역명/방/침대 수 입력 후 도면 생성, 보류 자리·특이사항 자리 지정, 랜덤 배치 로직 논의

채린 자매 피드백: 1층·2층 침대를 세로로 붙여서 표시(동행 인원 배치 편의), 방별 용도(스텝방 등) 메모 기능 필요, 사용 불가 자리 표시 기능 필요, 1층 홀수·2층 짝수 번호 체계 요청

방 개수가 구역마다 다른 문제 해결 방안: 구역-방-침대 순으로 단계적으로 입력받는 구조로 개선 논의

상담 현황판/스케줄 기능: 대시보드 형태로 상담 건수·해결 건수·재상담 필요 여부 표시, 상담 상세 내용(간증 등)은 기록하지 않는 방향으로 논의

상담 기록의 개인정보 민감성 문제(간증 내용 등) 및 구원 여부와 무관한 일반 상담자 분류 문제는 실제 운영하며 결정하기로 함

상담 스케줄 시간 단위: 10분 대신 30분 단위로 시작/종료 시간 설정하는 방식으로 단순화

접수 배치, 셔틀 관리 기능은 기존 요청사항(수기 입력, 관리자 소통 방식) 그대로 반영됨을 확인

기획을 추가로 반복할지 여부: 현재 기획서 수준이 충분하다고 판단, 실사용하며 보완하는 방향으로 결론

개발 언어/프레임워크: 프론트엔드는 React+Tailwind로 고정, 백엔드는 Python 방향으로 의견 수렴(최종 결정은 개발 담당자가 확인 후 진행)

인프라: 서버는 기존 리소스 활용(우분투, 도커), 도메인은 별도로 요청 예정

결정 사항
기획서 추가 수정 없이 현재 수준에서 개발을 시작하기로 결정

프론트엔드는 React + Tailwind CSS로 결정

상담 스케줄 시간 입력은 30분 단위로 설정하기로 결정

개발 킥오프 미팅을 9월 9일(수) 오후 8시 30분~10시로 확정

사용 불가 자리 표시 기능 및 1층 홀수/2층 짝수 번호 체계를 숙소 배치도에 추가하기로 결정

액션 아이템
진영 - 숙소 배치도에 사용 불가 표시, 1층 홀수·2층 짝수 번호 체계 반영

진영 - 은주 자매와 별도로 접수 배치 페이지 피드백 논의 진행

진영 - 대시보드 탭, 입금 매칭 탭 등 세부 기능 추가 검토 및 보완

윤아 - 9월 9일 킥오프 전까지 클로드 계정 세팅 완료(용현 또는 배수민 본부장에게 전화 인증 요청)

열님 - 태종에게 도메인 요청, 우분투/도커 서버 환경 준비

열님 - 기획 시스템(플랜 루프 기반 클로드 자동화 툴) 자료 공유

전체 참석자 - 9월 9일 8시 30분 개발 킥오프 미팅 참석
