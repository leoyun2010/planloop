### 3항 유형 A 중 3건 — 검토서 분류 정정: 「기능 부재」가 아니라 「REQ 누락」

검증 중 확인된 사실: 아래 3건은 **화면정의서·정책서에 이미 정의되어 있고 REQ만 없었다.** 결정이 필요한 것이 아니라 추적 체인이 끊긴 정합성 문제였으므로, 기존 산출물에 이미 쓰여 있는 내용만 옮겨 REQ를 신설했다(추측 없음).

| 항목 | 이미 존재하던 정의 | 신규 ID |
|---|---|---|
| 3.1 참가비·계좌 설정 | SCR-014 구성요소 [6] 「참가비 · 계좌」 + POL-046 대조 규칙(「안내문에 적힌 참가비·계좌가 집회 설정과 다릅니다」) | **REQ-073** |
| 3.5 입금 매칭 해제 | SCR-016 [해제] 버튼 + 인터랙션 문구 + POL-033 기록 대상 「매칭 해제」 | **REQ-074** |
| 3.9 명단 내보내기 | SCR-019 [명단 내보내기] 버튼 + POL-033 기록 대상 + POL-041 예외 조항 | **REQ-075 (보류)** |

REQ-075는 내보내기 항목 범위·권한이 미정이라 **보류** 상태로 두었다. NFR-004가 건강 상세·알러지·구원 여부를 암호화 대상으로 두고 있어, 범위 결정 없이 구현하면 복호화된 민감정보가 통제 없이 반출된다.

|---|---|
| **3.10은 "명시 필요"보다 심각하다** | 검토서는 "상담 결과가 갱신하는 것으로 보이나 문서에 명시 필요"라고 했으나, 실제로는 **두 값의 선택지 자체가 다르다.** REQ-008 본인 입력은 `해결 / 재확인 / 미해결`, REQ-056 상담 결과는 `해결 / 재상담 필요 / 미해결`. 갱신하려 해도 `재확인 ↔ 재상담 필요`가 매핑되지 않는다. OI-30에 이 사실을 명기했다 |
| **3.11에 변수가 하나 늘었다** | 검토서 작성(09-03) 이후 [2026-09-04 회의](2026-09-04-기획검토-개발착수.md) 결정 D-5로 **POL-051 사용 불가 좌석**이 신설되었다. 이제 좌석은 정원(1,400)·버퍼(80석)·보류(방당 1층 1자리)·사용 불가 4개 기준이 얽힌다. OI-31에 반영했다 |
| **화면이 REQ보다 앞서간 사례가 3건** | 3.1·3.5·3.9는 모두 화면정의서에 기능이 그려져 있는데 REQ가 없었다. `/sync-impl`이 다루는 "구현이 기획보다 앞선" 경우의 문서 내부 판본이다 |

### 미반영으로 남긴 것

- **11건 중 어느 것도 요구사항·정책 결정으로 승격하지 않았다.** REQ-073~075는 신규 결정이 아니라 기존 산출물에 이미 있던 정의를 옮긴 것이다.
- 검토서 4항의 경고 — *"결정 전 개발 착수 시 해당 부분은 임의 판단으로 구현됨"* — 는 유효하다. OI-22~OI-31 10건이 미해결인 채로 **2026-09-09 개발 킥오프**를 맞는다.
