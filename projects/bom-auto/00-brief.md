## 1. 한 줄 정의

> **인성정보 영업사원과 엔지니어**가 **벤더별로 받은 BoM을 인성정보 표준 양식으로 자동 변환하고, SKU·수량·라이선스·EOS 오류를 자동 검증받고, 견적서·원가분석표까지 뽑을 수 있게 하는** **사내 웹 서비스**

## 2. 해결하려는 문제

AS-IS 흐름: 고객 요구사항 접수 → 영업사원이 제안 장비 BoM을 직접 구성 → 엔지니어에게 사양 검토 요청 → 검토 완료 BoM으로 제조사 DC 요청·견적 작성. **건당 180분, 월 5건.**

- **변경 시 반복 수작업** — 고객 요구사항이 바뀔 때마다 BoM·견적서를 손으로 다시 고친다.
- **오기입·누락** — 제품 SKU, 수량, 라이선스 기간, 옵션을 잘못 적거나 빠뜨릴 수 있다. 샘플에서도 국내 건에 유럽형 전원 케이블이 들어간 사례, 한 BoM 안에 서비스 기간 36개월과 12개월이 섞인 사례가 확인된다.
- **담당자별 편차** — 담당자의 경험과 제조사별 제품 지식에 따라 제품 선정·검증 결과가 달라진다.
- **검증 반복으로 효율 저하** — 영업이 구성하고 엔지니어가 검토하는 왕복이 수작업이라 두 직군 모두 시간이 든다.
- **양식이 제각각이다** — 견적서는 사업부별로 3종, 원가분석표는 2종이 쓰인다.
- **노하우가 개인 폴더에 갇혀 있다** — 과거 견적서·BoM이 개인 프로젝트 폴더에 엑셀로 흩어져 있어 조직이 재사용하지 못한다.

## 4. 핵심 가치 제안

- **인성정보의 통일된 양식 정의**: 사업부별로 정형화되지 않은 양식을 통일한다. 표준 BoM(가격 없음, 전사 공유), 고객 견적서 2종(단일 표형 / Summary + 세부 시트형), 원가분석표(작성자 전용)로 정의한다.
- **수작업 엑셀 대비**: 벤더마다 다른 BoM 양식(Cisco CCW .xls, Dell Configurator .xlsx)을 사람이 옮겨 적지 않고, 표준 BoM으로 자동 변환한다.
- **엔지니어 수기 검토 대비**: SKU·수량·기간·EOS는 고정 규칙으로 판정하고, 호환성·필수 액세서리 누락·고객에게 불필요한 항목은 AI가 지적한다. 엔지니어는 지적된 항목만 판단하면 된다.
- **개인 경험 의존 대비**: 확정 BoM 이력이 조직에 쌓여 2차의 유사 사례 추천·노하우 룰의 근거가 된다.

## 5. 핵심 기능 (우선순위순)

우선순위는 PRD 기준이다. **P0 = 2026-10-08 MVP**, P1 = 2차 (D-03, D-18).

1. **벤더 BoM → 인성정보 표준 BoM 변환** [P0] — Cisco CCW 내보내기(.xls, 구성형·가격형)와 Dell Solutions Configurator 내보내기(.xlsx)를 판별·변환한다. 상위 품목·구성품 계층을 유지한다 (PRD REQ-004 ~ REQ-006, REQ-013).
2. **정합성 검증 + 검증 리포트** [P0] — 고정 규칙(필수값·수량·SKU 형식·중복·기간 불일치·합계 불일치)과 AI 검토 권고(호환성·액세서리 누락·불필요 항목)를 적용한다. 결과는 화면과 xlsx로 제공한다 (REQ-007, REQ-009, REQ-010).
3. **제품별 EOS 조회** [P0] — 검증 시 자동으로 조회하고, SKU 단건으로도 검색할 수 있다. MVP는 **Cisco·Dell 모두 AI 웹 검색**(출처 URL 필수)이다. Cisco EoX API 연동은 2차(P1)다 (REQ-008, REQ-019, REQ-029, D-38).
4. **확정·버전 이력 관리** [P0] — 오류가 0건일 때 영업이 직접 확정한다. 확정본은 잠기고, 수정은 새 버전으로 만든다 (REQ-011, REQ-012).
5. **원가·견적가 계산 + 고객 견적서·원가분석표 출력** [P0] — **제조사에서 승인받은 DC율**을 구분별로 적용해 최종 견적을 만든다. 원가 = List 금액 × (1 − DC율) × 환율, 견적가 = 원가 × (1 + 마진율)이며 행별로 원 미만을 절사한다. 견적서는 2종 중 골라 **xlsx 또는 PDF**로 받는다(소비자가 열 표시). 마진 분석 리포트는 제공하지 않는다 (REQ-016 ~ REQ-018, REQ-028, D-07, D-15, D-23 ~ D-25).
6. **BoM 초안 자동 구성 · 유사 사례 추천 · 과거 데이터 적재** [P1] — 과거 사례가 쌓인 뒤 2차에 한다 (REQ-023 ~ REQ-025).
7. **담당자 노하우 룰 등록·공유** [P1] — 등록된 룰은 2번 검증에 쓰인다 (REQ-022).

AI 역할(요구사항 원문): 과거 견적·BoM 사례를 토대로 SKU·수량·라이선스·호환성 오류와 누락 항목을 지적하고, 고객 입장에서 불필요한 BoM 정보 등을 안내한다. MVP에서는 과거 사례 없이 BoM 자체를 검토하고, Dell EOS 검색도 AI가 맡는다.

## 6. 성공 기준

- **작성 시간 단축** — 건당 소요시간 180분 → **60분 이하**(약 67% 단축). 측정: 첫 파일 업로드부터 첫 견적서 다운로드까지 걸린 시간의 중앙값(시스템 로그).
- **오류 감소** — 확정 BoM에 고정 규칙 오류 0건. 확정 이후 발견되는 오기입·누락 건수의 현재 기준값과 목표치: 미정 — 확인 필요.
- **표준화** — 시스템에서 나가는 BoM·견적서·원가분석표가 모두 표준 양식이다 (양식 이탈 0건).

## 8. 범위에서 제외하는 것

**1차 출시에서 하지 않기로 결정한 것**

- **StrataVAR(PqW) 연동** — 해당 API는 별도 구매가 필요하다(요구사항 행 3 문제점).
- **마진 분석 리포트** — 견적가·마진은 계산하지만 수익성 분석은 하지 않는다.
- **엔지니어 검토 요청·승인 흐름** — 영업이 직접 확정한다 (D-06).
- **환율 자동 조회** — 사용자가 입력한다 (D-07).
- **모바일 지원** — PC Chrome·Edge만 지원한다 (D-09).
- **ERP 연계** (D-23).
- **제조사 DC 요청서 작성** — 시스템은 DC 요청서를 만들지 않는다. 승인받은 DC율을 견적에 입력해 최종 견적서를 만든다 (D-23).
- **2차 이후**: 초안 자동 구성·유사 사례 추천·노하우 룰·과거 데이터 적재(P1), PDF 입력·추가 벤더 HPE/Aruba·Fortinet·Juniper(P2)
