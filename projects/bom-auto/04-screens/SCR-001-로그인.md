# 화면정의서 — SCR-001 로그인·인증 오류

| 항목 | 내용 |
|---|---|
| 화면 ID | SCR-001 |
| 문서 버전 | v1.1 |
| 상태 | 승인 |
| 경로(URL) | `/login` (SSO 콜백 오류는 `/auth/callback` → `/login?error=…`) |
| 접근 권한 | 미인증 사용자 (POL-001). 유효한 세션이 있으면 `/boms`로 이동 |
| 진입 경로 | GNB [로그아웃] 이후, SSO 인증 실패·취소, 세션 만료(API 401), Naver Works 계정 정보 누락, 비활성화된 계정으로 로그인 |
| 관련 요구사항 | REQ-001, REQ-037 |
| 관련 정책 | POL-001, POL-002, POL-013, POL-047 |
| 관련 테스트 | TC-001, TC-003, TC-004, TC-005, TC-006, TC-010, TC-147, TC-180 |
| HTML 목업 | [SCR-001-로그인.html](SCR-001-로그인.html) |

## 1. 화면 목적

- 로그인하지 않은 사용자가 Naver Works SSO로 로그인하게 하고, 로그인이 안 된 이유를 정책서 문구 그대로 알려준다.

> 세션 없이 보호된 URL에 접근하면 서버가 바로 Naver Works로 보낸다(POL-001 — 문구 없음). 그래서 이 화면은 로그아웃 뒤, 오류가 났을 때, 세션이 만료됐을 때만 보인다.

## 3. 컴포넌트 트리 (개발 인수인계용)

```jsx
<LoginPage>                              {/* 유효 세션이면 즉시 /boms로 replace (POL-001) */}
  <LoginCard>
    <ServiceTitle />                     {/* [1] */}
    <StatusMessage                       /* [2] query.error / query.reason 으로 결정 */
      kind={"logout" | "processing" | "sso_failed" | "expired" | "profile_missing" | "disabled"} />
    <SsoButton                           /* [3] 클릭 → GET /auth/login?returnTo=… → Naver Works */
      returnTo={safeReturnTo(query.returnTo)}   /* POL-001 safeReturnTo: 같은 출처 상대 경로만 */
      disabled={processing} />
    <BrowserNotice />                    {/* [4] NFR-010 */}
  </LoginCard>
</LoginPage>
```

## 5. 상태별 화면

| 상태 | 조건 | 표시 내용 |
|---|---|---|
| 기본 | 로그아웃 뒤, 또는 `/login`에 직접 접속 | [2] 「로그아웃되었습니다.」(로그아웃 뒤에만) + [3] 활성. 자동으로 SSO로 보내지 않는다(로그아웃 직후 바로 다시 로그인되는 것 방지) |
| 로딩 | SSO 콜백 처리 중 (`/auth/callback`) | [2] 「로그인 처리 중입니다…」 + 스피너, [3] 비활성 |
| 빈 상태 | 해당 없음 | 조회할 데이터가 없는 화면이다 |
| 에러 — 인증 실패 | Naver Works 인증 실패·사용자 취소 (`?error=sso_failed`) | [2] 「Naver Works 인증에 실패했습니다. 다시 시도하거나 관리자에게 문의해 주세요.」 + [3] 라벨 「다시 로그인」 |
| 에러 — 세션 만료 | API가 401을 반환 (`?reason=expired`) | [2] 「로그인 시간이 만료되었습니다. 다시 로그인해 주세요.」 + [3] 「다시 로그인」 |
| 에러 — 계정 정보 없음 | Naver Works 응답에 계정 ID·이름·메일 누락 (`?error=profile_missing`) | [2] 「Naver Works 계정 정보를 받지 못했습니다. 관리자에게 문의해 주세요.」 + [3] 「다시 로그인」 |
| 에러 — 비활성 계정 | 관리자가 SCR-012에서 비활성화한 계정으로 로그인 (`?error=disabled`) | [2] 「사용이 중지된 계정입니다. 관리자(CSD)에게 문의해 주세요.」 + [3] 「다시 로그인」. 세션을 만들지 않는다 (POL-047, DEC-63) |

## 6. 입력 유효성 (입력 폼이 있는 경우)

해당 없음 — 입력 폼이 없다. 아이디·비밀번호는 Naver Works 화면에서 입력한다.

## 7. 인터랙션 상세

- [3] 클릭 → `GET /auth/login?returnTo={safeReturnTo}` → Naver Works 로그인 → `GET /auth/callback`
  - 성공·역할 있음 → `returnTo`(없거나 안전하지 않으면 `/boms` — SCR-003)
  - 성공·역할 미지정(첫 로그인 포함) → SCR-002 (POL-002)
  - 실패·취소 → SCR-001 에러(인증 실패), 세션을 만들지 않는다 (POL-001)
  - 계정 정보 누락 → SCR-001 에러(계정 정보 없음) (POL-013)
  - 비활성화된 계정 → SCR-001 에러(비활성 계정), 세션을 만들지 않는다. 감사 로그에는 로그인 실패(사유 `disabled`)로 남는다 (POL-047)
- 로그인 성공·실패는 감사 로그에 기록한다 (POL-011).
- 어느 화면에서든 API 401을 받으면 입력 중이던 내용과 상관없이 SCR-001 세션 만료 상태로 이동한다. 현재 URL을 `returnTo`로 넘긴다.
- 로그인한 상태에서 관리자가 계정을 비활성화하면 서버가 세션을 바로 지운다. 다음 요청이 401이라 세션 만료 상태로 오고, [다시 로그인]하면 비활성 계정 상태가 된다 (POL-047).
