## 1. 화면 목적

- 벤더 BoM 파일(.xls·.xlsx·.csv)을 올려 형식을 판별하고 표준 BoM으로 변환한다. 거부됐거나 판별에 실패하면 그 이유를 정책서 문구 그대로 보여준다.

## 3. 컴포넌트 트리 (개발 인수인계용)

```jsx
<UploadPanel versionId revision onClose={closeAndRefreshTable}>   {/* [1] */}
  <DropZone                                         /* [2] 여러 파일 선택 가능 — 고른 순서대로 1개씩 처리 (POL-014) */
    accept=".xls,.xlsx,.csv"                        /* 확장자 대소문자 무시 */
    onFiles={files => queue(files)} />
  <FileQueue>                                       {/* [3] 파일별 카드 */}
    {items.map(f =>
      <FileCard name size stage                     /* 대기 | 검사 중 | 변환 중 | 완료 | 거부 | 판별 실패 */
        message={f.message}                         /* POL-014 거부 사유 표 / POL-015 판별 안내 / POL-016 중단 사유 — 원문 그대로 */
        summary={f.summary}>                        {/* [5] POL-016 요약 문구 */}
        {f.stage === "판별 실패" &&
          <ManualFormatPicker                       /* [4] POL-015 detectForced */
            options={["CISCO_CONFIG", "CISCO_PRICED", "DELL"]}
            onSubmit={fmt => POST(`/api/versions/${versionId}/files`, {file, forcedFormat: fmt, revision})}
            onCancel={discard} />}
      </FileCard>)}
  </FileQueue>
  <Footer><Button onClick={close} disabled={processing}>닫기</Button></Footer>  {/* [6] */}
</UploadPanel>
```

## 4. 구성 요소 정의

| # | 요소 | 유형 | 내용/동작 | 관련 정책 |
|---|---|---|---|---|
| 1 | 패널 제목 + 닫기 | 텍스트·버튼 | 「벤더 BoM 파일 올리기」. 처리 중에는 [x]가 비활성이다 | |
| 2 | 파일 놓기 영역 | 파일 입력 | 「파일을 끌어다 놓거나 클릭해 선택하세요」와 제한 안내 「.xls, .xlsx, .csv · 파일당 10MB · 데이터 3,000행 이하」. 여러 파일을 고르면 고른 순서대로 한 개씩 처리한다 | POL-014 |
| 3 | 처리 목록 | 카드 목록 | 파일마다 파일명 · 크기 · 단계 라벨 · 결과 문구. 단계: 대기 → 검사 중 → 변환 중 → 완료 / 거부 / 판별 실패. 앞 파일이 실패해도 뒤 파일은 계속 처리한다 | POL-014, POL-015, POL-016 |
| 4 | 형식 직접 선택 | 라디오 + 버튼 | 판별에 실패한 파일 카드 안에만 나온다. 문구 「파일 형식을 판별하지 못했습니다. 형식을 직접 선택해 주세요.」와 라디오 3개, [이 형식으로 변환](선택 전 비활성), [취소](파일을 버리고 저장하지 않음) | POL-015 |
| 5 | 변환 요약 | 텍스트 | 완료된 카드 안에 「총 {N}행 변환(상위 품목 {A}, 구성품 {B}), 미분류 {M}행」. 하위 제품이 있으면 「하위 제품 {C}」를 넣는다. 건너뛴 옵션 행이 있으면 「상위 품목이 없는 옵션 행 {n}개를 건너뛰었습니다.」를 덧붙인다 | POL-016 |
| 6 | [닫기] | 버튼 | 패널을 닫고 SCR-005 표를 새로 불러온다. 처리 중에는 비활성이다 | |

## 5. 상태별 화면

| 상태 | 조건 | 표시 내용 |
|---|---|---|
| 기본 | 변환 성공 (Cisco 구성형) | 카드: 「완료」 + 「Cisco CCW(구성형)로 인식했습니다. 단가가 없어 견적은 단가 입력 후 만들 수 있습니다. 가격형으로 다시 내보내면 단가가 자동으로 들어갑니다.」 + [5] 요약. 가격형이면 「Cisco CCW(가격형)로 인식했습니다.」, Dell이면 「Dell Solutions Configurator 파일로 인식했습니다.」 |
| 로딩 | 검사·변환 중 | 카드에 단계 라벨 「검사 중」 또는 「변환 중」 + 진행 표시. [x]·[6] 비활성 |
| 빈 상태 | 파일을 아직 고르지 않음 | [2]만 표시. [3]은 「올린 파일이 없습니다.」 |
| 에러 — 거부 | POL-014 검사 실패 | 카드: 「거부」 + 사유 문구 1개. ① 「.xls, .xlsx, .csv 파일만 올릴 수 있습니다.」 ② 「파일 크기는 10MB 이하여야 합니다. (현재 {크기}MB)」 ③ 「파일을 열 수 없습니다. 파일이 손상되었는지 확인해 주세요.」 / 「암호가 걸린 파일은 읽을 수 없습니다. 암호를 해제한 뒤 다시 올려 주세요.」 / 「CSV 파일의 문자 인코딩을 읽을 수 없습니다. UTF-8 또는 CP949로 저장해 주세요.」 ④ 「빈 파일입니다. 내용이 있는 파일을 올려 주세요.」 ⑥ 「데이터 행은 3,000행 이하여야 합니다. (현재 {n}행)」 |
| 에러 — 변환 중단 | POL-016·POL-019 중단 사유 | 「필수 컬럼이 없어 변환할 수 없습니다: {컬럼 목록}」 / 「품목 행을 찾지 못했습니다.」 / 「# 열이 숫자로 바뀌어 라인 번호를 읽을 수 없습니다. CCW에서 다시 내보낸 원본 파일을 올려 주세요.」 / 「Dell 파일의 통화가 원화(₩)가 아닙니다. 지원하지 않는 통화입니다.」 |
| 에러 — 판별 실패 | 시그니처 불일치 | [4] 표시. 직접 고른 형식의 필수 머리글이 없으면 「선택한 형식의 필수 컬럼이 없습니다: {컬럼 목록}」, 머리글 행이 없으면 「품목 표의 머리글 행을 찾지 못했습니다. 벤더 도구에서 내보낸 원본 파일인지 확인해 주세요.」 |
| 에러 — 충돌 | 다른 창에서 먼저 저장됨 (409) | 카드: 「다른 창에서 먼저 저장된 내용이 있습니다. 새로고침한 뒤 다시 수정해 주세요.」 파일은 저장하지 않는다 |

- 거부·중단된 파일은 서버에 저장하지 않고 표준 BoM도 바꾸지 않는다 (POL-014).

## 6. 입력 유효성 (입력 폼이 있는 경우)

| 필드 | 필수 | 형식/제한 | 실패 시 문구 | 관련 정책 |
|---|---|---|---|---|
| 파일 확장자 | Y | .xls·.xlsx·.csv (대소문자 무시). .xlsm·.xlsb·.pdf 불가 | 「.xls, .xlsx, .csv 파일만 올릴 수 있습니다.」 | POL-014 |
| 파일 크기 | Y | 10MB 이하 | 「파일 크기는 10MB 이하여야 합니다. (현재 {크기}MB)」 | POL-014 |
| 데이터 행 수 | Y | 머리글 아래 비어 있지 않은 행 3,000행 이하 | 「데이터 행은 3,000행 이하여야 합니다. (현재 {n}행)」 | POL-014 |
| 형식 직접 선택 | Y (판별 실패 시) | 3개 중 1개 | 선택 전 [이 형식으로 변환] 비활성 | POL-015 |

- 확장자와 크기는 브라우저에서 먼저 검사하고, 서버가 같은 순서(POL-014 ① ~ ⑦)로 다시 검사한다.

## 7. 인터랙션 상세

- 파일을 놓음 → 카드 추가(대기) → `POST /api/versions/{id}/files`(multipart, `revision`) → 서버가 POL-014 ① ~ ⑦을 수행 → 응답 `{stage, format, message, summary}`로 카드를 갱신한다.
- 판별 실패 → [4]에서 형식을 고르고 [이 형식으로 변환] → 같은 API에 `forcedFormat`을 붙여 다시 보낸다 (POL-015 detectForced).
- 변환 성공 → 행을 기존 행 뒤에 파일 순서대로 이어 붙이고, 행 번호를 1부터 다시 매긴다. 수정 번호 +1, 검증 상태 「재검증 필요」(이미 검증했다면) (POL-005, POL-016). 감사 로그 「파일 업로드」 (POL-011).
- [닫기] → SCR-005 표 새로고침. 새로 붙은 행으로 스크롤한다.
