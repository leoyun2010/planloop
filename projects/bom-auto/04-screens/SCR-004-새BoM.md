| 항목 | 내용 |
|---|---|
| 화면 ID | SCR-004 |
| 문서 버전 | v1.0 |
| 상태 | 승인 |
| 경로(URL) | `/boms?new=1` (SCR-003 위 모달) |
| 접근 권한 | 영업 (POL-008 CREATE_BOM). 그 밖의 역할이 URL로 열면 모달을 띄우지 않는다 |
| 진입 경로 | SCR-003 [새 BoM], SCR-003 빈 상태의 [새 BoM] |
| 관련 요구사항 | REQ-003 |
| 관련 정책 | POL-003, POL-004, POL-008 |

## 1. 화면 목적

- 영업이 고객사명과 건명을 입력해 BoM 건(작성중 v1)을 만들고, 바로 파일 업로드로 넘어간다.

## 2. 레이아웃 (텍스트 와이어프레임)

```
+-------------------- SCR-003 (어둡게) --------------------+
|        +----------------------------------------+       |
|        | [1] 새 BoM                          [x] |       |
|        |                                        |       |
|        | [2] 고객사명 *                   3/50   |       |
|        |     [대웅제약                        ]  |       |
|        |                                        |       |
|        | [3] 건명 *                      11/100  |       |
|        |     [마곡 C&D 센터 구축               ]  |       |
|        |                                        |       |
|        | [4] 같은 고객사명·건명으로도 만들 수      |       |
|        |     있습니다. 건마다 ID로 구분합니다.     |       |
|        |                                        |       |
|        |                [5] [취소] [만들기]      |       |
|        +----------------------------------------+       |
+---------------------------------------------------------+
```

## 3. 컴포넌트 트리 (개발 인수인계용)

```jsx
<NewBomModal onClose={closeToList}>                 {/* [1] Esc·[x]·[취소]로 닫기 */}
  <TextField name="customer" label="고객사명" required
    maxLength={50} counter                          /* [2] POL-003: trim 후 1~50자, 제어 문자 불가 */ />
  <TextField name="title" label="건명" required
    maxLength={100} counter                         /* [3] POL-003: trim 후 1~100자 */ />
  <HelpText>같은 고객사명·건명으로도 만들 수 있습니다. 건마다 ID로 구분합니다.</HelpText>  {/* [4] 중복 허용 */}
  <Footer>                                          {/* [5] */}
    <Button onClick={close}>취소</Button>
    <PrimaryButton onClick={submit} loading={saving}>만들기</PrimaryButton>
    {/* submit: 클라이언트 검사 → POST /api/boms → 201 {bomId, versionNo: 1}
        → goto(`/boms/${bomId}/v/1?upload=1`)  (SCR-005 + SCR-006 패널) */}
  </Footer>
</NewBomModal>
```

## 4. 구성 요소 정의

| # | 요소 | 유형 | 내용/동작 | 관련 정책 |
|---|---|---|---|---|
| 1 | 모달 제목 + 닫기 | 텍스트·버튼 | 「새 BoM」. [x]·Esc·바깥 클릭으로 닫는다. 입력값이 있으면 닫기 전에 POL-005 이탈 확인 문구를 띄운다 | POL-005 |
| 2 | 고객사명 | 입력 | 필수. 글자 수 카운터 「{n}/50」 | POL-003 |
| 3 | 건명 | 입력 | 필수. 글자 수 카운터 「{n}/100」 | POL-003 |
| 4 | 중복 안내 | 텍스트 | 「같은 고객사명·건명으로도 만들 수 있습니다. 건마다 ID로 구분합니다.」 | POL-003 |
| 5 | [취소] / [만들기] | 버튼 | [만들기]는 항상 활성이다. 누르면 검사하고, 실패하면 필드 아래에 문구를 띄운다. 저장 중에는 스피너를 보이고 중복 클릭을 막는다 | POL-003, POL-004 |

## 5. 상태별 화면

| 상태 | 조건 | 표시 내용 |
|---|---|---|
| 기본 | 모달을 막 열었을 때 | 빈 입력칸 2개, 카운터 「0/50」·「0/100」 |
| 로딩 | [만들기] 처리 중 | [만들기] 스피너·비활성, 입력칸 읽기 전용 |
| 빈 상태 | 해당 없음 | 입력 폼이다. 빈 입력은 기본 상태다 |
| 에러 — 입력 오류 | 검사 실패 | 해당 필드 아래 문구(6장), 필드 테두리 강조 |
| 에러 — 저장 실패 | 서버 오류 | 모달 하단에 「요청을 처리하지 못했습니다. 잠시 후 다시 시도해 주세요.」. 입력값은 유지 (IA 4.1) |

## 6. 입력 유효성 (입력 폼이 있는 경우)

| 필드 | 필수 | 형식/제한 | 실패 시 문구 | 관련 정책 |
|---|---|---|---|---|
| 고객사명 | Y | 앞뒤 공백 제거 후 1~50자 | 비었을 때 「고객사명을 입력해 주세요.」 / 초과 「고객사명은 50자 이내로 입력해 주세요.」 | POL-003 |
| 건명 | Y | 앞뒤 공백 제거 후 1~100자 | 비었을 때 「건명을 입력해 주세요.」 / 초과 「건명은 100자 이내로 입력해 주세요.」 | POL-003 |
| 공통 | — | 줄바꿈·제어 문자 불가 (붙여넣기 포함) | 「줄바꿈과 제어 문자는 입력할 수 없습니다.」 | POL-003 |

- 입력칸의 `maxLength`로 초과 입력을 막는다. 서버도 같은 규칙으로 다시 검사한다 (POL-003).

## 7. 인터랙션 상세

- [만들기] → 검사 → `POST /api/boms {customer, title}` → BoM 건 ID 발급, v1 「작성중」·「미검증」, 작성자·생성일시 기록(REQ-003, POL-004) → 감사 로그 「BoM 건 생성」(POL-011) → `/boms/{id}/v/1?upload=1` 이동 (SCR-005 + SCR-006 패널 열림).
- 영업이 아닌 사용자가 `/boms?new=1`로 들어오면 모달을 띄우지 않는다. API는 403이다 (POL-008).
