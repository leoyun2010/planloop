| 항목 | 내용 |
|---|---|

| 문서 버전 | v1.0 |

## 1. 화면 목적

- 관리자가 Naver Works로 로그인한 사용자 목록을 보고, 여러 명을 골라 역할(영업·엔지니어·관리자·역할 미지정)을 한 번에 지정한다.

+--------------------------------------------------------------------------------------+

## 3. 컴포넌트 트리 (개발 인수인계용)

```jsx
<UserRolePage>                                     {/* 관리자 아니면 403 (POL-008) */}
  <GNB active="users" />                           {/* [1] */}
  <PageHead title="사용자 역할 관리" />             {/* [2] */}
  <UserFilter                                      /* [3] 역할 필터 + 이름·계정 부분 일치 */
    roles={["전체", "역할 미지정", "영업", "엔지니어", "관리자"]} />
  <BulkRoleBar                                     /* [4] POL-010 changeRoles */
    selectedCount={selected.length}
    disabled={selected.length === 0}               /* MSG_NO_SELECTION */
    onApply={role => PATCH("/api/users/roles", {userIds: selected, role})} />
  <UserTable                                       /* [5] POL-013 수집 항목만 */
    columns={["선택", "이름", "Naver Works 계정", "부서", "역할", "최초 로그인", "최근 로그인"]}
    sort="firstLoginAt desc"
    selectAllOnPage />
  <Pager pageSize={50} />                          {/* [6] */}
</UserRolePage>
```

## 4. 구성 요소 정의

| # | 요소 | 유형 | 내용/동작 | 관련 정책 |
|---|---|---|---|---|
| 1 | GNB | 공통 | [사용자 관리] 활성 (관리자만 보이는 메뉴) | POL-008 |
| 2 | 페이지 제목 | 텍스트 | 「사용자 역할 관리」 | |
| 3 | 필터 | 입력 폼 | 역할(전체/역할 미지정/영업/엔지니어/관리자), 이름·계정 부분 일치(대소문자 무시). [검색] 또는 Enter. 오른쪽에 「총 {n}명」 | |
| 4 | 일괄 지정 바 | 선택·버튼 | 「선택 {n}명」 · 역할 선택 · [역할 지정]. 선택이 0명이면 [역할 지정] 비활성. 성공하면 토스트 「{n}명의 역할을 변경했습니다: {역할}」, 선택을 해제하고 목록을 다시 불러온다 | POL-010 |
| 5 | 사용자 표 | 표 | 열: 선택 · 이름 · Naver Works 계정 · 부서(없으면 「-」) · 역할 · 최초 로그인 일시 · 최근 로그인 일시. 기본 정렬은 최초 로그인 내림차순(새 사용자가 위). 머리글 체크박스는 현재 페이지 전체를 고른다. 선택은 페이지를 넘겨도 유지된다 | POL-013 |
| 6 | 페이지 이동 | 페이저 | 페이지당 50명(D-35 — 관리 대상 약 190명) | |

## 5. 상태별 화면

| 상태 | 조건 | 표시 내용 |
|---|---|---|
| 기본 | 사용자 1명 이상 | [3] ~ [6]. 예시는 「역할 미지정」 필터로 새 사용자를 고른 상태 |
| 변형 — 자기 해제 오류 | 선택에 본인이 있고 새 역할이 관리자가 아님 | 요청 전체 거부. [4] 아래에 「자신의 관리자 역할은 해제할 수 없습니다. 선택 목록에서 본인을 빼 주세요.」 |
| 변형 — 성공 | 지정 완료 | 토스트 「3명의 역할을 변경했습니다: 엔지니어」 |
| 로딩 | 목록 조회·지정 처리 중 | [5] 스켈레톤 / [역할 지정] 스피너 |
| 빈 상태 | 조건에 맞는 사용자 0명 | 「조건에 맞는 사용자가 없습니다.」 |
| 에러 | 조회·지정 실패 | 조회: 「데이터를 불러오지 못했습니다. 다시 시도해 주세요.」 + [다시 시도] / 지정: 「요청을 처리하지 못했습니다. 잠시 후 다시 시도해 주세요.」 (선택 유지) |

## 6. 입력 유효성 (입력 폼이 있는 경우)

| 필드 | 필수 | 형식/제한 | 실패 시 문구 | 관련 정책 |
|---|---|---|---|---|
| 선택한 사용자 | Y | 1명 이상 | [역할 지정] 비활성 | POL-010 |
| 새 역할 | Y | 영업 / 엔지니어 / 관리자 / 역할 미지정 | — (선택 전 [역할 지정] 비활성) | POL-010 |
| 본인 포함 여부 | — | 본인이 선택에 있으면 새 역할은 관리자만 | 「자신의 관리자 역할은 해제할 수 없습니다. 선택 목록에서 본인을 빼 주세요.」 | POL-010 |

## 7. 인터랙션 상세

- [역할 지정] → `PATCH /api/users/roles {userIds, role}` → 서버가 한 트랜잭션으로 처리(일부만 반영하지 않음) → 이전 역할과 같은 사용자는 건너뛰고 {n}에서도 뺀다 → 바뀐 사용자마다 변경자·일시·이전·새 역할을 감사 로그에 남긴다 (POL-010, POL-011).
- 바뀐 역할은 대상 사용자의 **다음 요청**부터 적용된다. 「역할 미지정」으로 바꾸면 그 사용자는 SCR-002로 이동한다 (REQ-020).
- 역할이 바뀌어도 그 사용자가 작성한 BoM 건은 그대로 남는다. 영업이 아니게 되면 자기 건의 가격·견적도 볼 수 없다 (POL-008).
