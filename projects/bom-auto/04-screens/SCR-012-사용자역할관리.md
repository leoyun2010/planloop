## 1. 화면 목적

- 관리자가 Naver Works로 로그인한 사용자 목록을 보고, 여러 명을 골라 역할(영업·엔지니어·관리자·역할 미지정)을 한 번에 지정한다.
- 퇴사자 등은 골라서 비활성화(로그인 차단)하고, 필요하면 다시 활성화한다 (REQ-037).

## 3. 컴포넌트 트리 (개발 인수인계용)

```jsx
<UserRolePage>                                     {/* 관리자 아니면 403 (POL-008) */}
  <GNB active="users" />                           {/* [1] */}
  <PageHead title="사용자 역할 관리" />             {/* [2] */}
  <UserFilter                                      /* [3] 역할·상태 필터 + 이름·계정 부분 일치 */
    roles={["전체", "역할 미지정", "영업", "엔지니어", "관리자"]}
    statuses={["전체", "사용 중", "비활성"]} />
  <BulkRoleBar                                     /* [4] POL-010 changeRoles · POL-047 비활성화 */
    selectedCount={selected.length}
    disabled={selected.length === 0}               /* MSG_NO_SELECTION */
    onApply={role => PATCH("/api/users/roles", {userIds: selected, role})}
    onDisable={openDialog("disable")}              /* → [7] */
    onEnable={() => PATCH("/api/users/status", {userIds: selected, disabled: false})} />
  <UserTable                                       /* [5] POL-013 수집 항목만 */
    columns={["선택", "이름", "Naver Works 계정", "부서", "역할", "최초 로그인", "최근 로그인", "상태"]}
    sort="firstLoginAt desc"
    selectAllOnPage />
  <Pager pageSize={50} />                          {/* [6] */}
  <ConfirmDialog id="disable"                      /* [7] → PATCH /api/users/status {disabled: true} */ />
</UserRolePage>
```

## 7. 인터랙션 상세

- [역할 지정] → `PATCH /api/users/roles {userIds, role}` → 서버가 한 트랜잭션으로 처리(일부만 반영하지 않음) → 이전 역할과 같은 사용자는 건너뛰고 {n}에서도 뺀다 → 바뀐 사용자마다 변경자·일시·이전·새 역할을 감사 로그에 남긴다 (POL-010, POL-011).
- 바뀐 역할은 대상 사용자의 **다음 요청**부터 적용된다. 「역할 미지정」으로 바꾸면 그 사용자는 SCR-002로 이동한다 (REQ-020).
- 역할이 바뀌어도 그 사용자가 작성한 BoM 건은 그대로 남는다. 작성자 역할(영업·관리자)이 아니게 되면 자기 건의 가격·견적도 볼 수 없다 (POL-008).
- [비활성화] → [7] → `PATCH /api/users/status {userIds, disabled: true}` → 한 트랜잭션으로 처리, 이미 비활성인 사용자는 건너뛰고 {n}에서도 뺀다 → 대상의 로그인 세션을 **바로 지운다**(다음 요청부터 SCR-001 세션 만료 → 다시 로그인하면 「사용이 중지된 계정입니다. 관리자(CSD)에게 문의해 주세요.」). 역할과 작성한 BoM 건은 그대로 둔다. 바뀐 사용자마다 감사 로그 「사용자 비활성화」 (POL-047, POL-011, DEC-63).
- [다시 활성화] → `PATCH /api/users/status {userIds, disabled: false}` → 이미 사용 중인 사용자는 건너뛴다 → 감사 로그 「사용자 다시 활성화」. 다시 로그인할 수 있고, 역할은 비활성화 전과 같다 (POL-047).
