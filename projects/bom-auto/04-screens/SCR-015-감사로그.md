# 화면정의서 — SCR-015 감사 로그

| 항목 | 내용 |
|---|---|
| 화면 ID | SCR-015 |
| 문서 버전 | v1.0 |
| 상태 | 승인 |
| 경로(URL) | `/admin/audit?event=&userId=&result=&from=&to=&page=` |
| 접근 권한 | 관리자 (POL-008 감사 로그 행). 그 밖의 역할은 SCR-013(403) |
| 진입 경로 | GNB [감사 로그] (관리자에게만 표시) |

## 1. 화면 목적

- 관리자가 로그인·역할 변경·확정·다운로드·환경설정 변경 등 감사 기록(POL-011)을 사건·사용자·결과·기간으로 걸러 보고, 같은 조건 그대로 CSV 로 내려받는다(POL-044).

## 3. 컴포넌트 트리 (개발 인수인계용)

```jsx
<AuditPage>                                         {/* 관리자 아니면 403 (POL-008) */}
  <GNB active="audit" />                            {/* [1] */}
  <NoticeBar />                                     {/* 공통 */}
  <PageHead title="감사 로그"                        /* [2] */
    action={<CsvButton disabled={!data || data.total === 0}
              onClick={() => download(`/api/audit.csv?${filters}`)} />} />   {/* POL-044 — 페이지 번호는 빼고 보낸다 */}
  <Hint code="AUDIT_HINT" />                        {/* [3] */}
  <AuditFilter                                      /* [4] 조건은 URL 에 둔다 */
    event={data.events} user={data.users} result={["SUCCESS","FAILURE"]} from to />
  <AuditTable rows={GET(`/api/audit?${filters}&page=${page}`)}   /* [5] 최신순, 50건 */
    columns={["일시","사건","사용자","대상 ID","결과","상세"]} />
  <Pager pageSize={50} />                           {/* [6] */}
</AuditPage>
```

## 4. 구성 요소 정의

| # | 요소 | 유형 | 내용/동작 | 관련 정책 |
|---|---|---|---|---|
| 1 | GNB | 공통 | [감사 로그] 활성 (관리자만 보이는 메뉴) | POL-008 |
| 2 | 페이지 제목·CSV | 텍스트·버튼 | 「감사 로그」, 오른쪽 [CSV 내려받기] — 조회 결과가 1건 이상일 때만 활성, 내려받는 중 스피너. 지금 거른 조건 그대로(페이지 무관) 최신순으로 내려받는다. 파일명 `감사로그_{오늘 YYYY-MM-DD}.csv`(UTF-8 BOM) | POL-044 |
| 3 | 안내 | 텍스트 | 「로그인·역할 변경·확정·다운로드·환경설정 변경 등의 기록입니다. 금액은 남기지 않습니다. CSV 는 지금 거른 조건 그대로(최대 10만 건) 내려받고, 내려받은 사실도 기록됩니다.」 | POL-011, POL-044 |
| 4 | 필터 | 입력 폼 | 사건(전체 + POL-011 사건 이름 목록, 예: 로그인 · 역할 변경 · 사용자 비활성화 · BoM 건 생성 · 확정 · 견적서 다운로드 · 환경설정 변경 · 감사 로그 내보내기 · EOS 검색 결과 다운로드 …) · 사용자(전체 + 사용자 이름) · 결과(전체/성공/실패) · 기간(시작일 ~ 종료일, KST, 양 끝 포함, 비우면 제한 없음). [검색]을 누르면 조건을 주소에 넣고 1페이지부터 다시 조회한다(같은 조건이면 다시 읽기). [초기화]는 조건을 모두 비운다. 오른쪽 「총 {n}건 · 최신순」 | POL-044 |
| 5 | 기록 표 | 표 | 열: 일시(KST, 초까지) · 사건(이름) · 사용자(없으면 「-」, 지운 사용자는 「#{id}」) · 대상 ID(없으면 「-」) · 결과(성공/실패 — 실패는 강조) · 상세(추가 정보 `키=값` 을 「 · 」로 이어 붙임 — 바뀐 항목 이름·건수 등, 금액 없음). 정렬은 일시 내림차순. 읽기 전용 | POL-011 |
| 6 | 페이지 이동 | 페이저 | 페이지당 50건. 「&lt; {page} / {pages} &gt;」 — 두 페이지 이상일 때만 보인다 | POL-044 |

## 5. 상태별 화면

| 상태 | 조건 | 표시 내용 |
|---|---|---|
| 기본 | 기록 1건 이상 | [2] ~ [6]. 예시는 조건 없이 처음 연 화면 |
| 변형 — 조건 적용 | 사건 「환경설정 변경」·기간 지정 | 걸러진 기록, 「총 {n}건 · 최신순」 |
| 변형 — CSV 내려받는 중 | [CSV 내려받기] 처리 중 | 버튼 스피너·비활성 |
| 변형 — CSV 한도 초과 | 조건에 맞는 기록이 10만 건 초과 | 파일을 만들지 않고 토스트 「내보낼 기록이 100000건을 넘습니다. 기간이나 조건을 좁혀 주세요.」 |
| 로딩 | 조회 중 | [5] 스켈레톤 |
| 빈 상태 | 조건에 맞는 기록 0건 | 「조건에 맞는 기록이 없습니다.」, [CSV 내려받기] 비활성 |
| 에러 | 조회 실패(기간 순서가 거꾸로인 400 포함) | 「데이터를 불러오지 못했습니다. 다시 시도해 주세요.」 + [다시 시도]. CSV 실패는 토스트 「요청을 처리하지 못했습니다. 잠시 후 다시 시도해 주세요.」 |

## 6. 입력 유효성 (입력 폼이 있는 경우)

| 필드 | 필수 | 형식/제한 | 실패 시 문구 | 관련 정책 |
|---|---|---|---|---|
| 사건 | N | POL-011 사건 코드 목록 안 | 서버 400 「입력값을 확인해 주세요.」 — 화면은 목록에서만 고르므로 생기지 않는다 | POL-044 |
| 결과 | N | 성공 / 실패 | — (목록에서 고른다) | POL-044 |
| 기간 | N | 시작일 ≤ 종료일 | 서버 400 「시작일이 종료일보다 늦습니다.」 — 화면은 에러 상태로 보여준다 | POL-044 |
| CSV 건수 | — | 10만 건 이하 | 「내보낼 기록이 {n}건을 넘습니다. 기간이나 조건을 좁혀 주세요.」({n} = 100000) | POL-044 |

## 7. 인터랙션 상세

- 조회: `GET /api/audit?event=&userId=&result=&from=&to=&page=` → `{items, total, page, pageSize: 50, events, users}`. 사건·사용자 선택지도 이 응답으로 채운다. 조회는 읽기 전용이라 감사 로그를 남기지 않는다.
- CSV: `GET /api/audit.csv?{같은 조건}` → 감사 로그 「감사 로그 내보내기」(AUDIT_EXPORT)를 **먼저** 쓰고(실패하면 파일을 주지 않는다) 내려준다. 기록의 추가 정보에 쓴 조건과 건수를 남긴다(POL-011, POL-044).
- 감사 로그는 쓰기 전용(append-only)이다. 이 화면에서 고치거나 지울 수 없다.
- 주소에 조건이 있으므로 뒤로 가기·새로고침·링크 공유로 같은 결과를 다시 볼 수 있다.
