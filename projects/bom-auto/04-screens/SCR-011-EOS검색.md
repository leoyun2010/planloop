## 1. 화면 목적

- BoM 없이 SKU 하나의 EOS 일정(EoS 공지일·End-of-Sale·LDoS·대체 제품)을 조회한다.
- [여러 SKU] 탭에서는 붙여 넣은 SKU 최대 100개를 차례로 조회해 표로 보고 xlsx 로 받는다 (REQ-040).

## 3. 컴포넌트 트리 (개발 인수인계용)

```jsx
<EosSearchPage>
  <GNB active="eos" />                              {/* [1] */}
  <PageHead title="EOS 검색" />                      {/* [2] */}
  <Tabs items={["SKU 하나", "여러 SKU"]} />           {/* [6] ?mode=bulk */}
  {bulk ? <BulkEos                                  /* [7]~[9] 단건 검색 API 를 4개씩 동시에 (POL-050) */
      onXlsx={() => POST("/api/eos/bulk.xlsx", {vendor, skus})} /> : <>
  <EosForm                                          /* [3] POL-029 단건 검색 입력 검사 */
    vendor={["Cisco", "Dell"]}                      /* 필수 — MSG 「벤더를 선택해 주세요.」 */
    sku={{single: true, formatByVendor: SKU_RE}}    /* 쉼표 불가, R3 형식 (POL-024) */
    onSubmit={q => GET(`/api/eos?vendor=${q.vendor}&sku=${q.sku}`)} />
  <EosResultCard                                    /* [4] POL-029 표시 문구 · 값 없는 날짜는 생략 */
    badge={res.manual ? "관리자 등록" : "AI 검색 결과 — 틀릴 수 있습니다"}  /* Cisco·Dell 모두 AI 검색 (D-38), 관리자 등록이 먼저 (DEC-64) */
    sources={res.sourceUrls} />
  <ResultMeta                                       /* [5] 조회 일시 · 캐시 여부 (TTL 7일) */
    onRefresh={() => GET(`/api/eos?...&refresh=1`)} />   {/* 캐시 무시 후 갱신 — 관리자 등록값은 그대로 */}
  </>}
</EosSearchPage>
```

## 4. 구성 요소 정의

| # | 요소 | 유형 | 내용/동작 | 관련 정책 |
|---|---|---|---|---|
| 1 | GNB | 공통 | [EOS 검색] 활성 | POL-008 |
| 2 | 페이지 제목 | 텍스트 | 「EOS 검색」 | |
| 3 | 검색 폼 | 입력 폼 | 벤더 라디오(Cisco/Dell, 기본 선택 없음), SKU 입력(앞뒤 공백 제거), [조회]. Enter로도 조회한다 | POL-029, POL-024 |
| 4 | 결과 카드 | 정보 | 첫 줄: SKU · 벤더 · 상태 라벨(판매중/EoS 예정/판매 종료/확인 불가). 둘째 줄: POL-029 표시 문구 원문. 셋째 줄: EoS 공지일 · End-of-Sale · LDoS(값 있는 것만). 대체 제품이 있으면 「대체 제품: {SKU}」. 모든 결과(Cisco·Dell)에 「AI 검색 결과 — 틀릴 수 있습니다」 표시와 출처 URL(새 탭 링크)을 붙인다. 관리자가 등록한 EOS(SCR-014 [EOS 관리])면 표시가 「관리자 등록」이고 문구가 「(관리자 등록, 출처: {url})」 형식이다 | POL-029, POL-043 |
| 5 | 조회 정보 | 텍스트·버튼 | 「조회 {일시}」와, 캐시에서 가져온 결과면 「캐시된 결과」 표시. [다시 조회]는 캐시를 쓰지 않고 새로 조회한 뒤 캐시를 갱신한다. 관리자 등록값이 있으면 [다시 조회]해도 등록값을 그대로 보여준다 | POL-029, POL-043 |
| 6 | 검색 방식 탭 | 탭 | [SKU 하나](`/eos`) · [여러 SKU](`/eos?mode=bulk`). 탭을 바꾸면 조건을 비운다 | POL-050 |
| 7 | 여러 SKU 입력 | 입력 폼 | 벤더 라디오(Cisco/Dell, 기본 선택 없음)와 안내 「SKU를 한 줄에 하나씩(또는 쉼표로 나눠) 붙여 넣으세요. 최대 100개, 중복은 한 번만 조회합니다.」, SKU 목록(여러 줄 입력칸). 줄바꿈·쉼표·세미콜론·공백으로 나누고, 대소문자를 무시한 중복은 처음 것만 남긴다. 조회 중에는 입력을 잠근다 | POL-050 |
| 8 | 조회·진행·내려받기 | 버튼·텍스트 | [조회 ({n}개)]({n} = 나눈 SKU 수) → 조회 중에는 [멈추기](남은 SKU 를 조회하지 않음)와 「{완료}/{전체} 조회 중…」, 끝나면 「{n}개 조회를 마쳤습니다. (실패 {failed}개)」. 오른쪽 [xlsx 다운로드]는 조회 성공이 1건 이상이고 조회 중이 아닐 때만 활성 | POL-007, POL-050 |

## 5. 상태별 화면

| 상태 | 조건 | 표시 내용 |
|---|---|---|
| 기본 | 결과 있음 (예: Cisco EoS 예정) | [4]·[5] |
| 변형 — 판매중 | AI 결과, 유효한 출처 있음, EoS 공지 없음 (Cisco·Dell) | 「판매중 (AI 검색 결과 — 틀릴 수 있습니다, 출처: {URL})」 + 출처 링크 |
| 변형 — 판매 종료 | AI 결과 End-of-Sale ≤ 오늘 (Cisco·Dell) | 「판매 종료로 보입니다 (AI 검색 결과 — 틀릴 수 있습니다) — End-of-Sale {날짜}, LDoS {날짜} (출처: {URL})」 |
| 변형 — 찾지 못함 | AI `NOT_FOUND` | 「{벤더} 자료에서 찾을 수 없는 SKU입니다 (AI 검색 결과 — 틀릴 수 있습니다)」 |
| 변형 — 관리자 등록 | 관리자가 등록한 SKU | [4] 표시 「관리자 등록」, 문구 예 「EoS 예정 — End-of-Sale {날짜} (관리자 등록, 출처: {URL})」. [다시 조회]해도 같다 |
| 로딩 | 조회 중 (AI 검색은 수십 초 걸릴 수 있음) | [4] 자리에 「EOS 정보를 조회하고 있습니다…」 + 스피너, [조회] 비활성 |
| 빈 상태 | 조회 전 | [4] 자리에 「벤더와 SKU를 입력해 조회하세요.」 |
| 에러 — 조회 실패 | API 오류·시간 초과·유효한 출처 없음 | 「EOS 정보를 가져오지 못했습니다」 + [다시 시도] |
| 에러 — 입력 오류 | 6장 검사 실패 | 입력칸 아래 문구, 조회하지 않음 |
| 여러 SKU — 기본 | [여러 SKU] 탭, 조회 전 | [7] 빈 입력칸, [8] [조회 (0개)], [xlsx 다운로드] 비활성, [9] 없음 |
| 여러 SKU — 조회 중 | SKU 를 4개씩 동시에 단건 검색 | [8] [조회] 스피너·비활성, [멈추기], 「{완료}/{전체} 조회 중…」. [9] 행마다 대기/조회 중/결과 |
| 여러 SKU — 완료 | 모든 SKU 처리(또는 멈춤) | [8] 「{n}개 조회를 마쳤습니다. (실패 {failed}개)」, [xlsx 다운로드] 활성(성공 1건 이상) |
| 여러 SKU — 입력 오류 | 벤더 미선택 / SKU 0개·100개 초과 | [8] 아래 「벤더를 선택해 주세요.」 / 「SKU를 1 ~ 100개 입력해 주세요.」, 조회하지 않음 |

## 6. 입력 유효성 (입력 폼이 있는 경우)

| 필드 | 필수 | 형식/제한 | 실패 시 문구 | 관련 정책 |
|---|---|---|---|---|
| 벤더 | Y | Cisco / Dell | 「벤더를 선택해 주세요.」 | POL-029 |
| SKU | Y | 1개. 쉼표 불가 | 「SKU를 하나만 입력해 주세요.」 (비었거나 쉼표가 있을 때) | POL-029 |
| SKU 형식 | Y | 벤더별 R3 형식 — Cisco `^[A-Z0-9][A-Z0-9./=+-]{1,39}$`, Dell `^\d{3}-[A-Z0-9]{4,5}$` | 「{벤더} SKU 형식이 아닙니다.」 | POL-024, POL-029 |
| 여러 SKU — 벤더 | Y | Cisco / Dell | 「벤더를 선택해 주세요.」 | POL-050 |
| 여러 SKU — SKU 목록 | Y | 중복을 뺀 1 ~ 100개 | 「SKU를 1 ~ 100개 입력해 주세요.」 | POL-050 |
| 여러 SKU — 각 SKU 형식 | — | 단건과 같은 형식 검사. 틀린 SKU 는 그 행만 건너뛴다 | 그 행에 「{벤더} SKU 형식이 아닙니다.」 | POL-024, POL-050 |

## 7. 인터랙션 상세

- [조회] → 입력 검사 → `GET /api/eos?vendor=&sku=` → 캐시(벤더·대문자 SKU, 7일)에 있으면 바로 반환, 없으면 AI 웹 검색(Cisco·Dell 공통, D-38. 입력: SKU만 — POL-012). Cisco EoX API 조회는 P1(REQ-029) → [4]·[5].
- 「확인 불가」 결과(API 실패·출처 없음)는 캐시하지 않는다. [다시 시도]는 같은 조건으로 다시 조회한다.
- 관리자 등록 EOS(벤더 + SKU)가 있으면 캐시·AI 검색보다 먼저 쓰고, [다시 조회]해도 AI 를 부르지 않는다 (POL-043, DEC-64).
- **여러 SKU**: [조회] → 입력 검사 → 형식이 맞는 SKU 를 4개씩 동시에 단건 검색 API(`GET /api/eos`)로 조회한다(같은 캐시·판정). [멈추기]는 아직 시작하지 않은 SKU 를 조회하지 않는다. [xlsx 다운로드] → `POST /api/eos/bulk.xlsx {vendor, skus}` → AI 를 다시 부르지 않고 캐시·관리자 등록값만 읽어 파일 `EOS검색_{벤더}_{YYYY-MM-DD}.xlsx` 를 만든다. 캐시에 없는 SKU(조회 실패·시간 초과)는 상태가 「조회 안 됨」이다. 감사 로그 「EOS 검색 결과 다운로드」(POL-011, POL-050).
- BoM 검증의 R8(SCR-007)과 같은 캐시·같은 판정 규칙을 쓴다. 단건 검색 화면은 등급(오류/경고)을 표시하지 않는다.
