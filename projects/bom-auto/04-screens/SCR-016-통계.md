# 화면정의서 — SCR-016 통계

| 항목 | 내용 |
|---|---|
| 화면 ID | SCR-016 |
| 문서 버전 | v1.0 |
| 상태 | 승인 |
| 경로(URL) | `/admin/stats` |
| 접근 권한 | 관리자 (POL-008 통계 행). 그 밖의 역할은 SCR-013(403) |
| 진입 경로 | GNB [통계] (관리자에게만 표시) |

## 1. 화면 목적

- 관리자가 기간별 서비스 활동(새 BoM·검증·확정·견적·다운로드)을 월별·사용자별·벤더별로 보고, 검증 판정 분포와 AI 검토 권고 품질 지표(PRD 리스크 5 — 확인함 비율·일괄 확인 비율·재검증에서 사라진 권고·AI 검토 실패율)를 확인한다(POL-045).

## 4. 구성 요소 정의

| # | 요소 | 유형 | 내용/동작 | 관련 정책 |
|---|---|---|---|---|
| 1 | GNB | 공통 | [통계] 활성 (관리자만 보이는 메뉴) | POL-008 |
| 2 | 페이지 제목 | 텍스트 | 「통계」 | |
| 3 | 안내 | 텍스트 | 「활동 건수는 감사 로그로 셉니다 — BoM 건을 지워도 남습니다. 벤더별 새 BoM 은 남아 있는 BoM 기준입니다.」 | POL-045 |
| 4 | 기간 | 선택·버튼 | 최근 6개월(기본, 5개월 전 1일 ~ 오늘) / 이번 달 / 지난 달 / 직접 지정(시작일 ~ 종료일 [조회]). 고르면 바로 다시 조회(직접 지정은 [조회]). 오른쪽 [새로고침](조회 중 스피너). 아래 소제목 「{from} ~ {to}」(KST, 양 끝 포함) | POL-045 |
| 5 | 활동 카드 | 카드 6개 | 새 BoM · 검증 실행 · 확정 · 견적 만들기 · 견적서 다운로드 · 표준 BoM 다운로드 — 각 「{n}건」. 검증 실행은 기간 안에 시작한 검증 수, 나머지는 감사 로그의 성공 기록 수(확정은 「AI 검토 없이 확정」 포함) | POL-045 |
| 6 | 월별 | 표 | 열: 월 · [5]의 6개 지표 | POL-045 |
| 7 | 사용자별 | 표 | 열: 사용자(모르면 「(알 수 없음)」) · [5]의 6개 지표 | POL-045 |
| 8 | 벤더별 새 BoM | 표 | Cisco · Dell · 「행 없음(파일 안 올림)」 — 각 「{n}건」. 기간 안에 만든, 지금 남아 있는 BoM 건의 행 벤더로 센다(두 벤더가 섞이면 양쪽에 센다) | POL-045 |
| 9 | 검증 판정 | 표 | 소제목 옆 「오류 {n} · 경고 {n}」, 규칙별(R1 ~ R9) 건수. 기간 안에 시작해 끝난 검증의 판정. 없으면 「판정이 없습니다.」 | POL-045 |
| 10 | AI 권고 품질 | 카드·표 | 소제목 「AI 권고 품질」, 안내 「「재검증에서 사라진 권고」는 같은 BoM 의 다음 검증에서 같은 분류·같은 대상 행의 권고가 나오지 않은 비율로, 권고를 반영해 고쳤는지 추정한 값입니다. 다음 검증이 있는 권고만 셉니다.」. 카드 5개: AI 검토 권고 「{n}건」(검증 {n}건 · 검증당 {n}건) · 확인함 비율(확인함을 체크한 권고 / 권고) · 일괄 확인 비율(일괄 체크 / 확인함 체크 {n}건) · 재검증에서 사라진 권고(다음 검증이 있는 권고 {n}건 기준) · AI 검토 실패율(AI 검토를 끝내지 못한 검증). 분모가 0 이면 「-」. 권고가 있으면 「권고 분류 · 건수」 표. 활동이 0건이어도 이 영역은 보인다 | POL-045 |

## 5. 상태별 화면

| 상태 | 조건 | 표시 내용 |
|---|---|---|
| 기본 | 활동 1건 이상 | [3] ~ [10]. 예시는 최근 6개월 |
| 변형 — 직접 지정 | 기간 「직접 지정」 | [4]에 시작일 ~ 종료일 + [조회] |
| 로딩 | 조회 중 | [5] ~ [10] 자리에 스켈레톤, [새로고침] 스피너 |
| 빈 상태 | 기간 안 활동 0건 | [5] ~ [9] 대신 「{from} ~ {to} 기간에 활동이 없습니다.」. [10] AI 권고 품질은 그대로(값이 없으면 「-」) |
| 에러 | 조회 실패(기간 오류 400 포함) | 「데이터를 불러오지 못했습니다. 다시 시도해 주세요.」 + [다시 시도] |

## 6. 입력 유효성 (입력 폼이 있는 경우)

| 필드 | 필수 | 형식/제한 | 실패 시 문구 | 관련 정책 |
|---|---|---|---|---|
| 기간(직접 지정) | Y | 시작일 ≤ 종료일, 최대 366일(양 끝 포함) | 서버 400 「시작일이 종료일보다 늦습니다.」 / 「조회 기간은 1년(366일) 이내로 골라 주세요.」 — 화면은 에러 상태로 보여준다. 두 칸 중 하나라도 비면 [조회]해도 조회하지 않는다 | POL-045 |

## 7. 인터랙션 상세

- 조회: `GET /api/stats?from=&to=` (기간을 비우면 서버가 최근 6개월로 계산). 읽기 전용이라 감사 로그를 남기지 않는다.
- 지표 정의(POL-045): 활동은 감사 로그 성공 기록 기준(BoM 건 삭제와 무관). 「재검증에서 사라진 권고」 = 같은 BoM 의 다음 완료 검증에 같은 분류·대상 행 계보가 겹치는 권고가 없으면 해소 — 권고에 대상 행 계보를 남기기 시작한 뒤의 권고만 잰다. 일괄 확인 비율은 「확인함 체크·해제」 감사 기록 중 체크(해제 제외)의 일괄 여부로 센다.
- 숫자는 천 단위 쉼표, 비율은 「{n}%」. 차트는 두지 않는다(표·카드만).
