## 1. 화면 목적

- 견적서 양식(단일 표형 / Summary + 상세 견적서)과 파일 형식(xlsx / PDF)을 고르고, 견적서 머리·거래 조건·견적 담당을 넣어 인성정보 견적서 표준양식(VER1) 배치의 고객 견적서를 내려받는다 (DEC-59·61).
- 담당자 연락처와 자주 쓰는 거래 조건을 「내 기본값」으로 저장해 다음 견적의 처음 값으로 쓴다 (POL-042).

## 3. 컴포넌트 트리 (개발 인수인계용)

```jsx
<DocModal data calc onClose>                        {/* [1] 높이 = 화면 − 160px, 넘치면 창 안 스크롤 */}
  <RadioGroup name="form" options={["single", "summary"]}
    labels={["견적서 (단일 표형)", "Summary (견적 요약 + 견적서 상세)"]} />   {/* [2] DEC-59·61 */}
  <RadioGroup name="type" options={["xlsx", "pdf"]} />                        {/* [3] */}
  <HeaderFields                                     /* [4] 견적마다 저장. 처음 값 = 관리자 설정(POL-040) 위에 내 기본값(POL-042) */
    date title to cc validDays
    terms={["warrantyTerm", "install", "delivery", "paymentTerms"]}   /* 선택지 제안(datalist) + 직접 입력 */
    notes owner={readOnly} ownerPhone subName subPhone subEmail />
  <Checkbox label="DOC_SAVE_MY_DEFAULTS"            /* [9] 저장한 적 없으면 처음엔 체크 */
    initial={MY_DOC_FIELDS.every(k => !myDocDefaults[k])} />
  {form === "summary" && <DetailTexts tops={tops} max={500} />}         {/* [5] */}
  <EosBanner flags={eosFlags(calc.rows, h.date, h.validDays)} />         {/* [10] 입력 중인 값 기준 (DEC-60) */}
  <DocSummary totals={calc.totals} />                                    {/* [6] */}
  {excludedWithAmount > 0 && <Warn code="EXCLUDED_HAS_AMOUNT" />}       {/* [7] 차단 아님 */}
  <Footer sticky>                                   {/* [8] 버튼 줄은 스크롤해도 아래에 고정 */}
    <Button onClick={onClose}>취소</Button>
    <PrimaryButton disabled={items === 0 || busy}
      onClick={() => PUT(`/api/quotes/${id}/doc-header`, {...h, saveMyDefaults})
        .then(() => GET(`/api/quotes/${id}/document?form=${form}&type=${type}`))} />
  </Footer>
</DocModal>
```

## 4. 구성 요소 정의

| # | 요소 | 유형 | 내용/동작 | 관련 정책 |
|---|---|---|---|---|
| 1 | 제목 + 닫기 | 텍스트·버튼 | 「견적서 다운로드」. 생성 중에는 닫기 비활성. 모달 높이는 화면 높이 − 160px로 제한하고, 넘치면 모달 안에서 스크롤한다(CR-003 QA) | |
| 2 | 양식 | 라디오 | 「견적서 (단일 표형)」(기본값) / 「Summary (견적 요약 + 견적서 상세)」. 마지막으로 고른 양식을 견적에 저장해 다음에 기본값으로 쓴다 | POL-037, DEC-59, DEC-61 |
| 3 | 형식 | 라디오 | 「xlsx」(기본값) / 「PDF」 | POL-037 |
| 4 | 머리 입력 | 입력 폼 | 순서대로 견적일자(기본 오늘) · 견적명(기본 BoM 건명) · 수신(빈 칸 안내 「예) ABC 주식회사 귀중」) · 참조(「예) 홍길동 상무님」) · 유효기간(일) · 하자 보증기간 · 장비 설치지원 · 납기 / 장소 · 대금 결제조건 · 특기사항 · 담당자(작성자 이름 · 메일, 읽기 전용) · 담당자 HP · 담당자(부) · 담당자(부) HP · 담당자(부) E-mail. **거래 조건 4종**(하자 보증기간·장비 설치지원·납기 / 장소·대금 결제조건)은 입력칸에 선택지를 제안하고 직접 입력도 된다 — 선택지는 관리자 설정(SCR-014 [견적 기본값·견적서 문구], POL-040). **처음 값**(머리를 아직 저장하지 않은 견적): 유효기간·장비 설치지원·납기 / 장소·대금 결제조건 = 관리자 설정 처음 값(기본 14일 · 「별도 협의」 · 「발주 후 4주 이내 / 귀사 지정 장소」 · 「계산서 발행 후 60일 이내」), 하자 보증기간 = 서비스 행 기간이 있으면 「{n} Months」, 없으면 관리자 설정 처음 값(기본 「제조사 정책에 따름」). 그 위에 **내 기본값**(POL-042 — 담당자 HP·담당자(부)·담당자(부) HP·담당자(부) E-mail·하자 보증기간·납기 / 장소·대금 결제조건 중 저장한 칸)이 먼저 쓰인다. 이미 머리를 저장한 견적은 저장된 값 그대로 | POL-037, POL-040, POL-042 |
| 5 | 상세 내역 | 입력 목록 | Summary 양식일 때만 보인다. 라벨 「상세 내역 (견적 블록 설명)」, 상위 품목마다 「견적 {n}. {품명}」과 입력칸(기본값 = 상위 품목 품명) | POL-037 |
| 6 | 요약 | 텍스트 | 「품목 {n}행 (제외 {m}행) · 공급가액 {supply}원 · 합계금액(VAT 포함) {total}원」. 금액은 SCR-009 [11]과 같다 | POL-036, POL-037 |
| 7 | 제외 금액 경고 | 경고 | 제외 행 중 금액이 있는 행이 있을 때: 「견적서에서 제외한 행 중 금액이 있는 행이 {n}개 있습니다. 이 금액은 견적서 합계에서 빠집니다.」 다운로드는 막지 않는다 | POL-037 |
| 8 | [취소] / [다운로드] | 버튼 | 버튼 줄은 모달을 스크롤해도 아래에 고정된다(CR-003 QA). [다운로드]는 [4]·[5] 값을 견적에 저장(+ [9]가 체크면 내 기본값 저장)한 뒤 파일을 만든다. 파일명 `{고객사명}_{건명}_견적서_v{n}.{xlsx|pdf}`. 제외 후 품목이 0행이면 비활성 | POL-007, POL-037 |
| 9 | 내 기본값 저장 | 체크박스 | 담당자 칸 아래 「담당자 연락처·하자 보증기간·납기·결제조건을 내 기본값으로 저장 — 다음에 만드는 견적에 자동으로 채워집니다」. 내 기본값을 아직 저장한 적이 없으면(7칸 모두 빈 값) 처음엔 체크, 저장한 적이 있으면 해제 상태로 연다. 체크하고 [다운로드]하면 지금 입력한 7칸(빈 칸 포함)을 내 기본값으로 저장한다. 체크하지 않으면 이 견적에만 저장된다 | POL-042 |
| 10 | EOS 경고 배너 | 배너 | SCR-009 [14]와 같은 문구 — 「견적일 이전에 판매가 끝난 품목이 {n}개 있습니다: {items}」 / 「견적 유효기간({until}까지) 안에 판매가 끝나는 품목이 {n}개 있습니다: {items}」. 기준은 **입력 중인** 견적일·유효기간(바꾸면 바로 다시 비교). 견적서 파일에는 넣지 않고 다운로드를 막지 않는다 | DEC-60 |

## 5. 상태별 화면

| 상태 | 조건 | 표시 내용 |
|---|---|---|
| 기본 | 단일 표형 · xlsx, 내 기본값 없음 | [5] 숨김, 담당자 연락처 칸 빈 값, [9] 체크 |
| 변형 — Summary 양식 | Summary 선택 | [5] 표시. 받은 파일은 Summary 시트(페이지) 뒤에 상세 견적서 시트(새 페이지)가 붙는다 |
| 변형 — 내 기본값 있음 | 내 기본값을 저장한 적 있음 | 담당자 HP·담당자(부)·거래 조건 칸이 내 기본값으로 채워져 있고 [9] 해제 |
| 변형 — EOS 경고 | 행 End-of-Sale이 입력 중인 견적일 이전이거나 유효기간 안 | [10] 배너. 다운로드 가능 |
| 로딩 | 저장·파일 생성 중 | [8] 「⟳ 다운로드」 비활성, 입력 읽기 전용, [1] 닫기 비활성 |
| 빈 상태 | 제외 후 품목 0행 | [6] 자리에 「견적서에 넣을 품목이 없습니다. 견적서 제외를 해제해 주세요.」, [다운로드] 비활성 |
| 에러 — 입력 오류 | 6장 검사 실패(서버 400) | 해당 입력칸 아래 문구, 아무것도 저장하지 않음(머리·내 기본값 모두) |
| 에러 — 생성 실패 | 금지 값 검사 실패·서버 오류 | 「견적서를 만들지 못했습니다. 관리자에게 문의해 주세요.」 / 감사 로그 기록 실패 등 그 밖의 오류는 「요청을 처리하지 못했습니다. 잠시 후 다시 시도해 주세요.」 |

## 7. 인터랙션 상세

- [다운로드] → `PUT /api/quotes/{id}/doc-header {revision, form, type, …머리, details, saveMyDefaults}` → 입력 검사(400 — 칸별 문구) → 머리 저장(+ 내 기본값 저장) → `GET /api/quotes/{id}/document?form=&type=` → 서버가 저장 조건을 다시 검사(409)하고 POL-037 금지 값 검사를 거쳐 파일 전송 → 모달 닫힘, 토스트 「견적서를 내려받았습니다.」 → 감사 로그(일시·견적 ID·양식·형식, POL-011).
- **견적서 배치(DEC-59·61)**: 표준양식 「견적서」·「Summary」 시트 배치(xlsx·PDF 같음, PDF는 A4 세로·표 머리글 반복). 머리 「QUOTATION」, 문서번호 `{접두어}{YY}-{MMDD}-Q{견적 ID 4자리}`(접두어 = 관리자 설정, 기본 `ISI`), 수신·참조·견적일·견적명, 공급자 회사 정보·CI(관리자 설정, SCR-014 — 기본 = 표준양식 「기준정보」), 견적금액 합계(VAT 포함)와 한글 금액. 품목 열: NO · 구분 · 모델명/Part No. · 상세 내역 · 수량 · 공급단가 · 공급가 합 · 비고(소비자가 열 없음). 합계 3행(공급가액·부가세·합계금액). 거래 조건 6항목(하자 보증기간 · 장비 설치지원 · 납기/장소 · 대금 결제조건 · 견적 유효기간 「견적일로부터 n일」 · 특기사항), 견적 담당(정·부), 구매 확인란과 하단 발주 문구(관리자 설정). Summary 양식은 상위 품목마다 「견적 n」 블록 → 「n-k」 항목 → 소계이고, 그 뒤에 단일 표형 상세 견적서가 붙는다.
- 어느 셀에도 원가·DC율·할인율·마진율·환율·GP가 없다 (POL-037 금지 머리글).
