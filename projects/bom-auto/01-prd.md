## 1. 개요

### 1.1 배경

매니지드서비스사업부 영업은 고객의 네트워크·IT 인프라 요구사항을 받으면 제안 장비 BoM을 직접 구성한다. 구성한 BoM은 엔지니어의 사양 검토를 거쳐 제조사 DC 요청과 견적 작성으로 이어진다. 이 흐름에 **건당 180분, 월 5건**이 든다(요구사항 기재값).

반복되는 문제는 네 가지다. 샘플 파일에서도 확인된다.

- **양식이 벤더·사업부마다 다르다.** Cisco CCW와 Dell Configurator는 행 구조부터 다르다. 인성정보 쪽 산출물도 제각각이어서, 견적서 양식이 사업부별로 3종, 원가분석표가 2종이다. 사람이 이 양식들 사이를 손으로 옮겨 적는다.
- **입력 오류가 생긴다.** 대웅제약 Cisco 샘플에서는 국내 설치 장비에 유럽형 전원 케이블(CAB-TA-EU, CAB-9K10A-EU)이 들어가 있다. 같은 BoM 안에 서비스 기간 36개월 행과 12개월 행이 섞여 있다.
- **판단이 사람마다 다르다.** 담당자의 경험과 제조사별 제품 지식에 따라 제품 선정·검증 결과가 달라진다.
- **데이터가 쌓이지 않는다.** 과거 견적서·BoM이 개인 폴더에 엑셀로 흩어져 있다.

### 1.2 목표

| # | 목표 | 성공 지표 | 목표치 |
|---|---|---|---|
| 1 | BoM·견적 작성 시간 단축 | 한 BoM 건에서 첫 파일 업로드부터 첫 견적서 다운로드까지 걸린 시간의 중앙값 (시스템 로그로 측정) | **60분 이하** (기준값 180분, 요구사항 자기 기재) |
| 2 | 양식 표준화 | 시스템에서 다운로드한 BoM·견적서·원가분석표 중 이 문서가 정의한 양식 파일의 비율 | 100% |
| 3 | 확정 BoM 오류 제거 | 확정된 BoM 버전 중 고정 규칙 「오류」가 1건 이상 남은 버전 수 | 0건 |
| 4 | 실무 오기입·누락 감소 | 확정 이후 발견된 SKU·수량·라이선스 오류 건수 | 기준값·목표치 미정 — 확인 필요 (OI-09) |

### 1.3 범위 제외 (Out of Scope)

**하지 않는 것**

- **StrataVAR(PqW) 연동** — API를 별도로 구매해야 한다 (브리프 8장).
- **마진 분석 리포트** — 견적가·마진은 계산하지만, 마진 추이나 수익성 분석은 제공하지 않는다 (D-01).
- **엔지니어 검토 요청·승인 흐름** — 영업이 직접 확정한다. 엔지니어는 공유된 BoM과 검증 리포트를 조회한다 (D-06).
- **환율 자동 조회** — 환율은 사용자가 입력한다 (D-07). 샘플은 모두 KRW여서 환율 입력이 필요 없다.
- **ERP 연계** (D-23).
- **제조사 DC 요청서 작성** — 시스템은 DC 요청서를 만들지 않는다. 제조사에서 승인받은 DC율을 견적에 입력해 최종 견적서를 만든다(REQ-016, D-23).
- **모바일 지원** (D-09).

**2차 이후로 미룬 것** (D-03) — 이 문서에 REQ로 정의하되 우선순위는 P1·P2다.

- 템플릿 파일 교체 관리 화면 → P1 (REQ-021)
- 노하우 룰·과거 데이터 일괄 적재·BoM 초안 자동 구성·유사 사례 추천 → P1 (REQ-022 ~ REQ-025)
- PDF BoM 입력, 추가 벤더(HPE/Aruba, Fortinet, Juniper) → P2 (REQ-026, REQ-027)
- Cisco EoX API 연동 → P1 (REQ-029). API 계정 확보에 시간이 걸려, MVP의 Cisco EOS는 AI 웹 검색으로 조회한다 (D-38)

## 2. 사용자

### 2.1 페르소나

| 페르소나 | 설명 | 핵심 니즈 |
|---|---|---|
| 영업사원 (40명) | 벤더 BoM을 받아 인성정보 양식으로 만들고 견적서를 낸다. BoM 건의 작성자다 | 옮겨 적기 없이 표준 BoM을 만들고, 오류를 확정 전에 잡고, 견적서·원가분석표를 바로 뽑는다 |
| 엔지니어 (150명) | 제안 구성의 사양을 검토한다. 시스템에서는 조회만 한다 | 공유된 BoM의 구성과 검증 결과, 제품별 EOS를 바로 확인한다 |
| 관리자 (CSD 담당자) | 사용자 역할을 지정하고 서비스를 운영한다 | 누가 어떤 권한을 갖는지 한 화면에서 관리한다 |

### 2.2 사용자 스토리

- 영업사원으로서, 나는 CCW에서 받은 .xls나 Dell Configurator에서 받은 .xlsx를 올려 **인성정보 표준 BoM을 바로 다운로드**하고 싶다.
- 영업사원으로서, 나는 **확정하기 전에** SKU·수량·서비스 기간 오류, EOS 제품, 국가 규격이 맞지 않는 전원 케이블 같은 문제를 **시스템이 짚어주길** 원한다. 엔지니어에게 다시 묻는 왕복을 줄이기 위해서다.
- 영업사원으로서, 나는 제조사에서 승인받은 **DC율과 마진율만 넣으면 고객 견적서(xlsx·PDF)와 원가분석표**를 받고 싶다. 견적서는 네트워크 건이면 단일 표형, 서버 건이면 Summary형으로 받는다.
- 영업사원으로서, 나는 고객 요구사항이 바뀌면 **확정본을 복사해 새 버전을 만들고**, 이전 버전과 구분해 보관하고 싶다.
- 엔지니어로서, 나는 영업이 만든 BoM의 **구성과 검증 결과를 조회**하고, 특정 SKU의 **EOS 일정을 검색**하고 싶다.
- 관리자로서, 나는 Naver Works로 처음 로그인한 사용자에게 **영업·엔지니어 역할을 지정**하고 싶다.

### REQ-001 Naver Works SSO 로그인

- **설명**: 모든 화면은 로그인한 사용자만 쓸 수 있다. 로그인 수단은 Naver Works SSO 하나다(D-11). 자체 아이디·비밀번호는 없다.
- **사용자 시나리오**: 사용자가 서비스 주소에 접속한다 → Naver Works 로그인 화면으로 이동한다 → 인증을 마치면 BoM 목록으로 돌아온다.
- **인수 조건 (Acceptance Criteria)**:
  - [ ] 로그인하지 않은 상태로 어떤 화면 URL에 접근해도 Naver Works 로그인 화면으로 이동한다.
  - [ ] 로그인하지 않은 상태로 API를 호출하면 HTTP 401을 반환하고 데이터를 반환하지 않는다.
  - [ ] Naver Works 인증에 성공하면 처음 요청한 화면으로 이동한다. 처음 요청한 화면이 없으면 BoM 목록으로 이동한다.
  - [ ] Naver Works 계정으로 처음 로그인한 사용자는 사용자 목록에 「역할 미지정」으로 등록된다.
  - [ ] 로그아웃하면 서비스 세션이 끝나고, 이후 화면 접근 시 다시 로그인 화면으로 이동한다.
- **예외/에러 케이스**: Naver Works 인증에 실패하거나 취소하면 서비스 세션을 만들지 않는다. 세션 만료 시간은 정책서에서 정한다.

- **인수 조건 (Acceptance Criteria)**:
  - [ ] .xls·.xlsx·.csv 이외의 확장자를 올리면 업로드가 거부되고 파일이 저장되지 않는다.
  - [ ] 한 번에 올릴 수 있는 파일 크기와 데이터 행 수에 한도가 있고, 초과하면 업로드가 거부된다. 한도값은 NFR-002를 따른다.

- **예외/에러 케이스**: 필수 필드의 원천 컬럼이 파일에 아예 없으면 변환을 중단한다. 일부 행에만 값이 비어 있으면 변환은 진행하고 REQ-007에서 판정한다. Dell의 `옵션 표시 가격`은 제품 수량이 2 이상이어도 해당 행 수량 전체의 총 가격이다(D-22). 제품 수량을 다시 곱하지 않는다.

### REQ-006 표준 BoM 조회·편집

- **설명**: 작성자는 「작성중」 버전의 표준 BoM과 가격 정보를 표에서 직접 고친다. 고객 요구사항 변경을 BoM에 반영하는 수단이다.
- **사용자 시나리오**: 고객이 C9200L 스위치를 6대에서 8대로 늘려달라고 한다 → 영업이 상위 품목과 구성품의 수량을 고친다 → 저장하면 검증 결과가 「재검증 필요」로 바뀐다.
- **인수 조건 (Acceptance Criteria)**:
  - [ ] 작성자는 POL-020의 편집 불가 필드(행 번호·원본 라인 번호·원본 파일명·원본 행 번호·행 유형·EOS 상태·벤더 Net 금액)를 뺀 모든 필드를 셀 단위로 수정할 수 있다.
  - [ ] 작성자는 행을 추가·삭제할 수 있다. 직접 추가한 행의 원본 파일명은 「직접 입력」이다. 상위 품목을 삭제하면 그 구성품도 함께 삭제되며, 삭제 전에 구성품 개수를 알려주고 확인을 받는다.
  - [ ] 수정한 셀은 원본 값과 구분되게 표시되고, 원본 값을 조회할 수 있다.
  - [ ] 내용을 수정한 뒤 저장하면 직전 검증 결과가 「재검증 필요」 상태가 되고, 재검증 전에는 확정할 수 없다.
  - [ ] 「확정」 버전은 편집할 수 없다. 모든 셀이 읽기 전용이다.
  - [ ] 작성자가 아닌 사용자에게는 편집 기능이 표시되지 않는다.
- **예외/에러 케이스**: 저장하지 않고 화면을 떠나려 하면 이탈 확인을 표시한다. 같은 작성자가 두 탭에서 동시에 편집하면 나중 저장이 앞 저장을 덮어쓰지 않게 막는다. 처리 방식은 정책서에서 정한다.

### REQ-008 BoM EOS 자동 조회

- **설명**: 검증을 실행하면 표준 BoM의 모든 SKU에 EOS 상태를 붙이고 R8로 판정한다(D-04). MVP에서는 **Cisco·Dell 모두 AI(LLM)가 웹을 검색**해 EoS 공지를 찾는다(D-19, D-38). AI 검색 결과에는 반드시 벤더 공식 사이트의 출처 URL을 붙인다(Cisco: cisco.com, Dell: dell.com·delltechnologies.com).
  - Cisco EoX API 연동은 P1(REQ-029)이다. 도입하면 Cisco는 API로 조회하고, 「판매 종료」를 오류로, 「레코드 없음」을 판매중으로 판정한다(D-28).

| EOS 상태 | 조건 | 판정 (Cisco·Dell 공통, AI 검색) |
|---|---|---|
| 판매중 | EoS 공지가 없음 | 없음 |
| EoS 예정 | EoS 공지가 있고 End-of-Sale 일자가 검증일 이후 | 경고 |
| 판매 종료 | End-of-Sale 일자가 검증일 이전이거나 검증일과 같음 | **경고** (D-21, D-38) |
| 확인 불가 | AI 검색 실패·시간 초과, 결과에 유효한 출처가 없음, SKU를 찾지 못함 | 경고 |

- 「판매 종료」를 경고로 둔 이유: AI 검색은 틀릴 수 있다. AI 검색 결과만으로 확정을 막지 않고, 사용자가 출처를 보고 판단하게 한다.
- **사용자 시나리오**: 검증 결과에서 한 스위치 행에 「EoS 예정 — End-of-Sale 2026-12-31, LDoS 2031-12-31 (출처: https://www.cisco.com/…)」가 표시된다. Dell 메모리 행에는 「판매중 (AI 검색 결과 — 틀릴 수 있습니다, 출처: https://www.dell.com/…)」이 표시된다.
- **인수 조건 (Acceptance Criteria)**:
  - [ ] Cisco·Dell SKU의 EOS 결과에는 「AI 검색 결과」 표시와 출처 URL이 붙는다. 벤더 공식 사이트의 출처 URL이 없는 AI 결과는 「확인 불가」로 처리된다.
  - [ ] End-of-Sale 일자가 검증일 이후인 SKU는 「EoS 예정 / 경고」로 판정되고, End-of-Sale 일자와 LDoS가 표시된다.
  - [ ] AI 검색에서 「판매 종료」로 나온 SKU는 Cisco·Dell 모두 「판매 종료 / 경고」로 판정되며 확정을 막지 않는다.
  - [ ] AI 검색이 응답하지 않거나 시간 한도를 넘기면 해당 SKU가 「확인 불가 / 경고」로 판정되고, 나머지 검증은 끝까지 진행된다.
  - [ ] 대체 제품 정보가 있으면 대체 SKU가 함께 표시된다. 조회 결과에는 조회 일시와 출처 URL이 표시된다.
- **예외/에러 케이스**: 같은 SKU의 조회 결과는 정책서에서 정한 기간 동안 캐시한다(POL-029). Dell의 쉼표 목록 SKU는 목록의 각 SKU를 따로 조회하고, 가장 나쁜 상태를 행의 상태로 쓴다. Cisco 부속·자리표시 SKU(-NONE, -BLANK 등)는 AI가 공지를 찾지 못해 「확인 불가」가 많이 나올 수 있다(리스크 3).

### REQ-009 AI 검토 권고

- **설명**: 검증을 실행하면 고정 규칙과 별도로 LLM이 표준 BoM을 검토해 「검토 권고」를 낸다(D-05). 권고는 판단을 돕는 정보이며 확정을 막지 않는다. 사용하는 LLM은 사내 승인 클라우드 LLM이다(D-11).
- **권고 분류** (예시는 샘플에서 확인된 실제 사례)
  - **호환성** — 섀시·모듈·광 트랜시버·전원 규격·소프트웨어 조합이 맞지 않을 가능성. 예: Cisco 기준 샘플의 2.3 CAB-TA-EU(유럽형 전원 케이블)와 5.1 CAB-9K10A-EU. 같은 건의 1.6은 CAB-AC-C15-KOR(한국형)이다.
  - **필수 액세서리 누락** — 전원 공급 장치, 전원 케이블, 랙 마운트 키트, 광 모듈처럼 함께 있어야 하는 품목이 없음
  - **고객에게 불필요한 항목** — 고객 제출용에서 빼는 것이 나은 행. 예: Cisco의 C9300-SSD-NONE·C9300-STACK-NONE·PWR-C5-BLANK(「선택 안 함」 자리표시), Dell의 옵션 표시 가격 0원인 「하드 드라이브 없음」·「OS 없음」·「고객 알림」 행
- **사용자 시나리오**: 검증 결과 「검토 권고」 탭에 「행 2.3 CAB-TA-EU는 유럽형 전원 케이블입니다. 같은 BoM의 1.6은 한국형(CAB-AC-C15-KOR)입니다 — 호환성」이 표시된다 → 영업이 SKU를 고치거나 「확인함」을 체크한다.
- **인수 조건 (Acceptance Criteria)**:
  - [ ] 권고마다 분류, 대상 행 번호(없으면 「BoM 전체」), 지적 내용, 근거 문장이 표시된다.
  - [ ] 모든 권고 화면에 「AI가 생성한 권고이며 틀릴 수 있습니다」가 표시된다.
  - [ ] 권고가 있어도 오류가 0건이면 확정할 수 있다. 단, 모든 권고에 「확인함」을 체크해야 확정 버튼이 활성화된다.
  - [ ] LLM 호출이 실패하거나 NFR-003의 시간 한도를 넘기면 「AI 검토를 완료하지 못했습니다」가 표시되고, 재시도 버튼이 제공된다. 고정 규칙 결과는 그대로 표시된다.
  - [ ] LLM에 보낸 요청과 받은 응답은 검증 결과 ID와 함께 저장된다(사후 추적용).
  - [ ] 「고객에게 불필요한 항목」 권고를 받은 행은 REQ-018 견적서에서 한 번에 제외할 수 있다. 제외해도 표준 BoM에서는 삭제되지 않는다.
- **예외/에러 케이스**: LLM 응답이 없는 행 번호를 가리키면 그 권고를 버리고 기록만 남긴다. AI 검토가 실패한 상태에서도 확정할 수 있다. 이때 작성자가 「AI 검토 없이 확정합니다」에 체크해야 하고, 그 사실이 이력에 남는다(D-30, POL-032).

### REQ-010 검증 리포트

- **설명**: 검증 결과를 화면에 요약·목록으로 보여주고 xlsx로 내려받게 한다. 리포트는 BoM 버전별로 남는다.
- **사용자 시나리오**: 영업이 검증 리포트를 xlsx로 받아 엔지니어에게 메신저로 공유한다. 엔지니어는 시스템에서 같은 리포트를 연다.
- **인수 조건 (Acceptance Criteria)**:
  - [ ] 리포트 상단에 오류·경고·검토 권고 건수가 등급별로 표시된다.
  - [ ] 목록의 각 항목을 누르면 표준 BoM 표의 해당 행으로 이동한다.
  - [ ] 목록을 등급·규칙 ID·분류로 거를 수 있다.
  - [ ] xlsx 리포트에는 화면 목록과 같은 항목이 같은 순서로 들어가고, 검증 일시와 BoM 버전이 표시된다.
  - [ ] xlsx 리포트에는 가격 정보가 들어가지 않는다. R4·R9처럼 가격 관련 판정은 규칙 ID와 문구만 들어가고 금액은 빠진다.
  - [ ] 등급은 색과 함께 텍스트(「오류」「경고」「검토 권고」)로 표시된다(NFR-009).
- **예외/에러 케이스**: 「재검증 필요」 상태에서 리포트를 열면 「BoM이 수정되어 이 결과는 최신이 아닙니다」가 상단에 표시된다.

### REQ-011 BoM 확정

- **설명**: 작성자가 「작성중」 버전을 확정한다(D-06). 확정 조건은 세 가지다: 최신 내용으로 검증했을 것, 오류 0건, 모든 경고·검토 권고에 「확인함」 체크. 가격 정보가 비어 있어도 확정할 수 있다(D-14).
- **사용자 시나리오**: 오류를 모두 고친 뒤 재검증한다 → 경고 1건에 「확인함」을 체크한다 → 「확정」을 누르고 확인 대화상자에서 한 번 더 누른다 → 상태가 「확정 v1」이 된다.
- **인수 조건 (Acceptance Criteria)**:
  - [ ] 오류가 1건 이상이면 확정 버튼이 비활성이다. API로 확정을 호출해도 거부된다.
  - [ ] 확인하지 않은 경고 또는 검토 권고가 1건 이상이면 확정 버튼이 비활성이다.
  - [ ] 검증 이후 내용이 수정되었으면(「재검증 필요」) 확정 버튼이 비활성이다.
  - [ ] Cisco 구성형 파일로 만든, 가격 정보가 없는 BoM도 위 조건을 만족하면 확정된다.
  - [ ] 확정하면 확정 일시·확정자가 기록되고 상태가 「확정」이 된다. 경고·권고의 「확인함」 체크는 체크한 사람·일시와 함께 이력에 남는다.
- **예외/에러 케이스**: 작성자 외에는 확정 기능이 표시되지 않는다. 확정 취소 기능은 없다. 수정이 필요하면 REQ-012로 새 버전을 만든다.

### REQ-012 BoM 버전 이력

- **설명**: 확정 버전은 잠긴다. 수정하려면 최신 확정 버전을 복사해 새 「작성중」 버전(v2, v3 …)을 만든다. 모든 버전을 조회·다운로드할 수 있다.
- **사용자 시나리오**: 확정 v1 이후 고객이 라이선스 기간을 36개월에서 60개월로 바꿔달라고 한다 → 영업이 「새 버전 만들기」를 누른다 → v2(작성중)가 v1 내용으로 생성된다 → 수정·검증·확정한다.
- **인수 조건 (Acceptance Criteria)**:
  - [ ] 「새 버전 만들기」는 최신 버전이 「확정」일 때만 누를 수 있다. 새 버전의 내용(가격 정보 포함)은 최신 확정 버전과 셀 단위로 같다.
  - [ ] 한 BoM 건에 「작성중」 버전은 최대 1개다.
  - [ ] 버전 목록에 버전 번호, 상태, 확정 일시, 확정자, 오류·경고·권고 건수가 표시된다.
  - [ ] 두 버전을 골라 비교하면 추가·삭제·변경된 행이 구분되어 표시된다.
  - [ ] 확정 버전은 어떤 역할로도 수정·삭제할 수 없다.
- **예외/에러 케이스**: 아직 확정한 적 없는 v1(작성중)은 작성자가 BoM 건째 삭제할 수 있다. 확정 버전이 하나라도 있는 BoM 건은 삭제할 수 없다.

### REQ-013 표준 BoM 다운로드

- **설명**: 표준 BoM의 한 버전을 인성정보 표준 BoM xlsx로 내려받는다. 양식은 REQ-005 표준 BoM 필드를 열로 하는 단일 시트다(D-16). 상위 품목·구성품 계층을 들여쓰기로 표현한다. **파일에는 가격 정보가 들어가지 않는다.** 누가 내려받아도 같은 파일이다.
- **사용자 시나리오**: 엔지니어가 확정 v2에서 「BoM 다운로드」를 누른다 → `<고객사명>_<건명>_BoM_v2.xlsx`가 내려받아진다.
- **인수 조건 (Acceptance Criteria)**:
  - [ ] 내려받은 파일의 열은 REQ-005 표준 BoM 필드 순서와 같다. 파일에 가격 정보 필드(통화·List 단가·할인율·벤더 Net 금액)가 없다.
  - [ ] 파일의 품목 행 수와 값은 해당 버전의 표준 BoM과 같다. 구성품은 상위 품목 아래에 들여쓰기로 표시된다.
  - [ ] 파일 상단에 고객사명, 건명, 버전, 상태, 확정 일시, 작성자가 표시된다.
  - [ ] 「작성중」 버전을 내려받으면 파일 상단에 「미확정」이 표시된다.
  - [ ] 다운로드마다 사용자·일시·버전이 기록된다.
- **예외/에러 케이스**: 파일명 규칙과 파일명에 쓸 수 없는 문자의 처리는 정책서에서 정한다.

### REQ-014 BoM 목록·검색

- **설명**: 로그인한 영업·엔지니어·관리자는 전사 BoM 건 목록을 보고 조건으로 찾는다. BoM 구성 정보는 공유한다(D-10).
- **사용자 시나리오**: 엔지니어가 벤더 「Cisco」, 상태 「확정」, SKU 「C9300X-24HX-E」로 검색해 비슷한 구성을 찾아본다.
- **인수 조건 (Acceptance Criteria)**:
  - [ ] 목록에 고객사명, 건명, 벤더, 작성자, 최신 버전·상태, 최종 수정일이 표시된다.
  - [ ] 고객사명·건명(부분 일치), 벤더, 작성자, 상태, 최종 수정일 기간으로 검색할 수 있고, 조건을 함께 쓸 수 있다.
  - [ ] SKU로 검색하면 그 SKU가 들어 있는 BoM 건이 나온다. Dell 쉼표 목록 SKU 안의 개별 SKU도 검색된다.
  - [ ] 「내 BoM만 보기」를 켜면 본인이 작성한 건만 나온다.
  - [ ] 기본 정렬은 최종 수정일 내림차순이다.
- **예외/에러 케이스**: 검색 결과가 0건이면 빈 상태 안내를 표시한다. 페이지당 건수는 정책서에서 정한다.

### REQ-015 가격·견적 정보 접근 제한

- **설명**: 가격 정보(통화·List 단가·할인율·벤더 Net 금액)와 견적 정보(환율·마진율·원가·견적가·고객 견적서·원가분석표)는 해당 BoM 건의 작성자만 조회한다(D-10, D-16). 관리자도 볼 수 없다.
- **사용자 시나리오**: 다른 영업이 내 BoM을 열면 SKU·품명·수량·기간은 보이지만 가격 열이 없고, 견적 탭도 없다.
- **인수 조건 (Acceptance Criteria)**:
  - [ ] 작성자가 아닌 사용자의 BoM 상세 화면에는 가격 정보 열이 표시되지 않는다.
  - [ ] 작성자가 아닌 사용자가 BoM 조회 API를 호출하면 응답 본문에 가격 필드가 들어 있지 않다. 가려진 값이 아니라 필드 자체가 없어야 한다.
  - [ ] 작성자가 아닌 사용자에게는 견적 메뉴·탭이 표시되지 않는다. 견적·견적서·원가분석표 API를 호출하면 403을 반환한다.
  - [ ] 업로드한 원본 벤더 파일(가격형 CCW·Dell은 가격 포함)은 작성자만 내려받을 수 있다.
- **예외/에러 케이스**: SKU로 검색(REQ-014)할 때 가격 필드는 검색 대상이 아니다.

### REQ-016 원가 계산

- **설명**: 작성자가 확정 버전에 대해 견적을 만들면 행별 원가를 계산한다(D-07). 견적은 확정 버전 하나를 기준으로 한다. **최종 견적은 제조사에서 승인받은 DC율을 적용해 만든다**(D-23). 시스템은 DC 요청서를 만들지 않는다.
  - `List 금액 = List 단가 × 수량` — Dell 구성품은 `옵션 표시 가격` 그대로(수량 전체의 총 가격, D-22)
  - `원가(외화) = List 금액 × (1 − DC율)`
  - `원가(원화) = floor(원가(외화) × 환율)` — 행별로 원 미만 절사. 통화가 KRW이면 환율 1
  - 합계 원가 = 행별 원가(원화)의 합
  - **이중 계산 방지**: 원가는 구성품 행으로 합산한다. Dell 상위 품목의 `확장된 가격(표시)`는 구성품 합계와 같으므로(R9로 검사) 상위 품목 행은 원가 합계에서 뺀다. Cisco에서 가격이 비어 있는 구성품은 상위 번들 가격에 포함된 것으로 보고 0원으로 계산한다(CCW 파일 하단 주석 기준).
- **사용자 시나리오**: 영업이 Cisco 가격형으로 만든 확정 v1에서 「견적 만들기」를 누른다 → 통화가 KRW이므로 환율 입력 없이 행별 원가와 합계가 바로 표시된다.
- **인수 조건 (Acceptance Criteria)**:
  - [ ] 표준 BoM에 KRW 외 통화가 있으면 통화마다 환율 입력칸이 생기고, 모든 환율을 입력해야 계산된다. KRW만 있으면 환율 입력칸이 없다.
  - [ ] 환율은 0보다 큰 숫자이며, 소수점 둘째 자리까지 입력할 수 있다.
  - [ ] EY한영 가격형 샘플의 C9300-48T-M(List 단가 20,051,583원, 수량 2, 할인율 70%)의 원가(원화)는 12,030,949원이다(12,030,949.8 → 절사).
  - [ ] Dell 기준 샘플의 메모리 행(옵션 표시 가격 276,496,000원, 제품 수량 1, DC율 0%)의 원가는 276,496,000원이다.
  - [ ] Dell 상위 품목의 제품 수량이 2이고 구성품의 옵션 표시 가격이 1,000,000원이면, 그 구성품의 List 금액은 1,000,000원이다(제품 수량을 곱하지 않음).
  - [ ] List 단가 1,000 USD, 수량 3, 할인율 40%, 환율 1,385.50이면 원가(원화)는 2,493,900원이다.
  - [ ] List 단가가 비어 있는 행이 하나라도 있으면(구성형 CCW 등) 「단가가 없는 행이 N개 있습니다」와 해당 행 목록이 표시되고, 단가를 입력하기 전에는 견적이 저장되지 않는다. 단, Cisco 번들 포함 구성품(상위 번들에 가격이 있는 경우)은 제외한다.
  - [ ] DC율은 가격 정보의 할인율을 기본값으로 쓴다. 견적 화면에서 구분(PRODUCT / SERVICE / SOFTWARE)별 DC율을 입력하면 해당 구분의 모든 행에 한 번에 적용되고, 행별로 다시 바꿀 수 있다.
  - [ ] 견적 화면에서 바꾼 DC율은 표준 BoM 가격 정보에 반영되지 않고, 견적에만 저장된다.
  - [ ] 견적에는 기준 BoM 버전, 입력한 환율, 작성 일시가 저장된다.
- **예외/에러 케이스**: 「작성중」 버전으로는 견적을 만들 수 없다. 한 확정 버전으로 견적을 여러 개 만들 수 있다(마진율을 달리한 안). 환율 자동 조회는 하지 않는다(D-07). 견적 화면에서 입력한 단가는 그 견적에만 저장되고 표준 BoM에는 반영되지 않는다.

### REQ-017 견적가 계산

- **설명**: 원가에 마진율을 적용해 행별 견적가를 계산한다(D-07, D-15).
  - `견적가(원화) = floor(원가(원화) × (1 + 마진율))` — 행별로 원 미만 절사
  - 견적 단가 = `floor(견적가(원화) ÷ 수량)`
  - 합계 견적가 = 행별 견적가(원화)의 합
  - 이 공식은 기존 원가분석표 관행(할인단가 ÷ (1 − 마진율), 천원 단위 올림)과 **다르다**. 차이는 6장 리스크 12를 본다.
- **사용자 시나리오**: 영업이 기본 마진율 20%를 넣는다 → 서비스 행만 10%로 바꾼다 → 행별 견적가와 합계가 즉시 다시 계산된다.
- **인수 조건 (Acceptance Criteria)**:
  - [ ] 견적 전체에 적용하는 기본 마진율을 입력할 수 있고, 행별 마진율로 덮어쓸 수 있다.
  - [ ] 원가(원화) 12,030,949원, 마진율 20%이면 견적가는 14,437,138원이다(14,437,138.8 → 절사).
  - [ ] 원가(원화) 2,493,900원, 마진율 15%이면 견적가는 2,867,985원이다.
  - [ ] 마진율은 소수점 첫째 자리까지 입력할 수 있다.
  - [ ] 환율·할인율·마진율·단가 중 하나를 바꾸면 영향받는 행과 합계가 다시 계산된다.
- **예외/에러 케이스**: 마진율은 0.0~100.0%이며 음수는 입력할 수 없다(D-31, POL-036). 견적 단가 × 수량이 견적가와 다를 때(절사 차이)는 견적가를 공급가로 쓰고, 견적 단가는 `floor(견적가 ÷ 수량)`으로 표시한다(D-29).

### REQ-018 고객 견적서 다운로드

- **설명**: 견적을 고객 견적서로 내려받는다. 양식은 2종이며 견적마다 고른다(D-17). 파일 형식은 **xlsx와 PDF**다(D-25). 고객 견적서에는 원가·DC율(할인율)·마진율·환율을 넣지 않는다.

| 양식 | 기준 샘플 | 구성 |
|---|---|---|
| 단일 표형 (Insung Quotation) | `인성정보_Moody's_스위치 교체 사업_견적서_20260901.xlsx`, `인터터치.은평힐튼 견적서.xlsx` | 시트 1개. 머리(문서번호·견적일자·수신·담당자·견적명·인성정보 사업자 정보) + 품목 표(제품번호 / 제품설명 / 수량 / 소비자가 / 공급단가 / 공급가 합 / 비고) + 합계 |
| Summary + 세부 시트형 | `DC사업부\SERVER\CASE2_Server_견적서.xlsx` | Summary 시트(NO / 구분 / 상세 내역 / 수량 / 제안 단가 / 제안가합 / 비고 — 상위 품목 1개당 1행) + 상위 품목마다 세부 시트 1개(모듈명 / 상세 내역 / 수량) + 공급가 합계(VAT 별도·포함), 결제조건·무상유지보수 |

- **사용자 시나리오**: 영업이 Dell 서버 건에서 「견적서 다운로드」 → 「Summary + 세부 시트형」을 고른다 → 형식을 PDF로 고른다 → `<고객사명>_<건명>_견적서_v2.pdf`가 내려받아진다.
- **인수 조건 (Acceptance Criteria)**:
  - [ ] 두 양식 모두 품목은 기준 BoM 버전의 품목과 같다. REQ-009에서 「견적서 제외」로 표시한 행은 빠진다.
  - [ ] 단일 표형은 각 행에 SKU·품명·수량·견적 단가·견적가가 들어간다. 소비자가 열에는 List 단가가 표시된다(D-24). 사용자가 단가를 직접 입력한 행은 입력값이 표시된다.
  - [ ] Summary 형의 Summary 시트 행 수는 상위 품목 수와 같고, 각 행의 제안가합은 해당 상위 품목과 그 구성품 견적가의 합이다. 세부 시트 수는 상위 품목 수와 같다.
  - [ ] 견적서 어느 셀에도 원가·DC율(할인율)·환율·마진율 값이 없다.
  - [ ] 같은 견적을 xlsx와 PDF로 각각 내려받을 수 있고, PDF의 품목·수량·금액은 xlsx와 같다.
  - [ ] PDF는 A4 세로에 맞춰 페이지를 나누고, 품목 표 머리글을 페이지마다 반복한다. Summary형 PDF는 Summary 다음에 세부 내역이 상위 품목 순서대로 이어진다.
  - [ ] 견적서 합계 금액은 REQ-017 합계 견적가(제외 행 반영 후)와 같다.
  - [ ] 견적서 다운로드는 작성자만 할 수 있고, 다운로드마다 일시·견적 ID·양식이 기록된다.
- **예외/에러 케이스**: 샘플은 모두 「단위: 원, VAT별도」로 표기하고, Summary 형은 VAT 포함 합계도 함께 적는다. 이 표기를 기본으로 하되 확정은 OI-07에서 한다. 견적서 유효기간·결제조건·무상유지보수·수신·참조는 견적마다 입력하며, 기본값(유효기간 14일, 결제조건 「계산서 발행 후 60일 이내」 등)을 제공한다(D-33, POL-037).

### REQ-019 SKU EOS 단건 검색

- **설명**: BoM 없이도 SKU 하나의 EOS 일정을 검색한다. 브리프 5장 「견적 시 제품별 EOS 여부 검색」 기능이다. 조회 방식은 REQ-008과 같다. MVP는 Cisco·Dell 모두 AI 웹 검색이다(D-38).
- **사용자 시나리오**: 엔지니어가 벤더 「Dell」, SKU 「210-BPMK」를 입력한다 → 「판매중 (AI 검색 결과 — 틀릴 수 있습니다)」와 출처 URL이 표시된다.
- **인수 조건 (Acceptance Criteria)**:
  - [ ] 벤더와 SKU를 입력하면 EOS 상태와 EoS 공지일·End-of-Sale 일자·LDoS가 표시된다(값이 있는 것만).
  - [ ] EoS 공지가 없는 SKU는 「판매중 (AI 검색 결과 — 틀릴 수 있습니다, 출처: {URL})」로 표시된다.
  - [ ] Cisco·Dell 결과에는 「AI 검색 결과 — 틀릴 수 있습니다」 표시와 출처 URL이 붙는다.
  - [ ] 대체 제품 정보가 있으면 대체 SKU가 표시된다. 조회 일시와 출처가 표시된다.
- **예외/에러 케이스**: API·AI 검색이 실패하면 「EOS 정보를 가져오지 못했습니다」와 재시도 버튼을 표시한다. AI 검색이 SKU를 찾지 못하면 「{벤더} 자료에서 찾을 수 없는 SKU입니다 (AI 검색 결과 — 틀릴 수 있습니다)」를 표시한다(POL-029). Cisco EoX API 조회는 P1(REQ-029)이다.

### REQ-020 사용자 역할 관리

- **설명**: 관리자(CSD 담당자, D-10)가 사용자 목록에서 역할을 지정·회수한다. 영업 40명·엔지니어 150명을 지정하므로 여러 명에게 한 번에 지정할 수 있어야 한다.
- **사용자 시나리오**: 관리자가 「역할 미지정」으로 거른 뒤 엔지니어 20명을 선택해 「엔지니어」로 한 번에 지정한다.
- **인수 조건 (Acceptance Criteria)**:
  - [ ] 사용자 목록에 이름, Naver Works 계정, 부서, 역할, 최초 로그인일, 최근 로그인일이 표시된다.
  - [ ] 여러 사용자를 선택해 역할 하나를 한 번에 지정할 수 있다.
  - [ ] 역할을 「역할 미지정」으로 되돌리면 해당 사용자는 다음 요청부터 역할 지정 대기 화면만 본다.
  - [ ] 역할 변경마다 변경자·일시·이전 역할·새 역할이 기록된다.
  - [ ] 관리자는 자신의 관리자 역할을 해제할 수 없다.
- **예외/에러 케이스**: 퇴사자처럼 Naver Works 계정이 비활성화된 사용자는 로그인이 차단된다(REQ-001). 이 사용자가 작성한 BoM 건은 그대로 남는다(OI-10). 역할은 관리자가 수동으로만 지정한다. Naver Works 부서 정보로 자동 지정하지 않는다(D-32, POL-002).

### REQ-021 템플릿 파일 관리 [P1]

- **설명**: 관리자가 표준 BoM·고객 견적서 2종·원가분석표 양식 파일을 교체한다. 양식이 바뀌어도 배포 없이 반영하기 위한 기능이다. MVP에서는 양식 파일을 배포 시점에 코드와 함께 넣는다.
- **사용자 시나리오**: 관리자가 새 견적서 양식 xlsx를 올린다 → 필드와 셀 위치의 매핑 미리보기를 확인하고 적용한다.
- **인수 조건 (Acceptance Criteria)**:
  - [ ] 새 템플릿을 적용하면 이후 다운로드는 새 템플릿으로 만들어지고, 이전 템플릿 파일은 보관된다.
  - [ ] 템플릿에 필수 필드의 셀 위치가 정해지지 않으면 적용할 수 없다.
- **예외/에러 케이스**: 템플릿을 교체해도 이미 내려받은 파일은 영향받지 않는다.

### REQ-022 노하우 룰 등록·공유 [P1]

- **설명**: 영업·엔지니어가 검증 룰을 등록하면 검증 때 REQ-007 R 규칙 뒤에 적용된다. 예: 「국내 설치 건에서 전원 케이블 SKU가 -EU·-UK로 끝나면 경고」. 룰의 표현 형식(조건식 / 자연어 + LLM 해석)은 2차 기획에서 정한다.
- **인수 조건 (Acceptance Criteria)**:
  - [ ] 등록한 룰은 이름, 등록자, 판정 등급(오류/경고), 적용 벤더와 함께 목록에 표시된다.
  - [ ] 룰을 켠 뒤 위반 BoM을 검증하면 룰 이름과 함께 판정된다.
- **예외/에러 케이스**: 룰끼리 충돌할 때의 우선순위는 2차에서 정한다.

### REQ-023 과거 견적서·BoM 일괄 적재 [P1]

- **설명**: 개인 폴더에 흩어진 과거 견적서·BoM 엑셀을 여러 개 한 번에 올려 표준 BoM으로 적재한다. REQ-024·REQ-025의 검색 데이터가 된다. 수집 범위와 수집 담당은 OI-05에서 정한다.
- **인수 조건 (Acceptance Criteria)**:
  - [ ] 파일 여러 개를 한 번에 올리면 파일별 적재 성공·실패와 실패 사유가 표시된다.
  - [ ] 적재한 BoM은 「과거 사례」로 구분되고, 확정 BoM과 같은 방식으로 검색된다.
- **예외/에러 케이스**: 사업부별 과거 견적서 양식(3종)·원가분석표 양식(2종)의 처리 방식은 2차에서 정한다.

### REQ-024 BoM 초안 자동 구성 [P1]

- **설명**: 영업이 요구 구성(예: 「48포트 PoE 액세스 스위치 20대, 3년 라이선스」)을 입력하면 과거 사례를 바탕으로 표준 BoM 초안을 만든다. 초안은 「작성중」 버전으로 들어가 REQ-006 ~ REQ-011 흐름을 그대로 탄다.
- **인수 조건 (Acceptance Criteria)**:
  - [ ] 초안의 행마다 근거가 된 과거 BoM 건 ID가 표시된다.
  - [ ] 초안은 확정 전에 반드시 REQ-007 검증을 거친다.
- **예외/에러 케이스**: 근거 사례가 없으면 초안을 만들지 않고 안내한다.

### REQ-025 유사 사례 추천 [P1]

- **설명**: 작성 중인 BoM과 구성이 비슷한 확정 BoM·과거 사례를 추천한다. 유사도 기준은 2차에서 정한다.
- **인수 조건 (Acceptance Criteria)**:
  - [ ] 추천 목록의 각 사례에 고객사명, 건명, 확정일, 유사도 근거(공통 SKU 수 등)가 표시된다.
  - [ ] 다른 작성자의 사례를 추천할 때 가격 정보는 표시되지 않는다(REQ-015).
- **예외/에러 케이스**: 추천할 사례가 없으면 빈 상태 안내를 표시한다.

### REQ-026 PDF BoM 입력 [P2]

- **설명**: PDF로 받은 견적서의 표를 추출해 표준 BoM으로 변환한다. 추출한 결과는 사용자가 원본과 대조해 확인한 뒤에만 표준 BoM이 된다.
- **인수 조건 (Acceptance Criteria)**:
  - [ ] PDF를 올리면 추출된 표와 PDF 원본이 나란히 표시된다.
  - [ ] 사용자가 「추출 결과 확인」을 누르기 전에는 검증·확정할 수 없다.
- **예외/에러 케이스**: 스캔 이미지 PDF 처리 여부는 도입 시 정한다.

### REQ-027 추가 벤더 지원 [P2]

- **설명**: HPE/Aruba·Fortinet·Juniper BoM을 REQ-004·REQ-005와 같은 방식으로 판별·변환한다. 각 벤더의 매핑표와 EOS 조회 방식이 추가된다.
- **인수 조건 (Acceptance Criteria)**:
  - [ ] 추가 벤더마다 샘플 파일 판별과 매핑 결과가 기대 결과표와 100% 일치한다.
  - [ ] 추가 벤더의 EOS 조회 방식(API / AI 검색)이 벤더별로 정의된다.
- **예외/에러 케이스**: 해당 없음 — 벤더별 예외는 도입 시 정책서에 추가한다.

### REQ-028 원가분석표 다운로드

- **설명**: 견적의 행별 원가·견적가·마진을 원가분석표 xlsx로 내려받는다(D-16). 작성자 전용 내부 문서다. 열 구성은 기존 Cost Analysis Table(기업·매니지드서비스사업부 원가분석표)을 따르되, 값은 이 시스템의 공식(REQ-016·REQ-017)으로 계산한다.
- **양식 구성**
  - 머리: 고객사명(End user), 건명(Project Name), 작성자(Account Manager), 기준 BoM 버전, 견적 작성일, 매출합(합계 견적가), 매입합(합계 원가), 이익(매출합 − 매입합), GP율(이익 ÷ 매출합)
  - 구분별 DC율 표: PRODUCT / SERVICE / SOFTWARE 각각에 견적에서 입력한 DC율(구분 안에서 행별로 다르면 「행별 상이」)
  - 품목 표: 구분 / SKU(Item Name) / 품명(Description) / 수량(Q'ty) / List 단가 / List 금액 / DC율 / 원가(원화) / 마진율 / 견적 단가 / 견적가 / 비고. 구분(PRODUCT → SERVICE → SOFTWARE) 순으로 묶는다.
- **사용자 시나리오**: 영업이 견적 화면에서 「원가분석표 다운로드」를 누른다 → `<고객사명>_<건명>_원가분석표_v2.xlsx`가 내려받아진다.
- **인수 조건 (Acceptance Criteria)**:
  - [ ] 원가분석표의 행별 원가·견적가는 견적 화면 값과 원 단위까지 같다.
  - [ ] 머리의 매출합·매입합은 각각 행별 견적가 합계·원가 합계와 같고, GP율은 이익 ÷ 매출합이다(소수점 넷째 자리 반올림 표시).
  - [ ] REQ-009에서 「견적서 제외」로 표시한 행도 원가분석표에는 들어가고, 「견적서 제외」로 표시된다.
  - [ ] 원가분석표 다운로드는 작성자만 할 수 있고(REQ-015), 다운로드마다 일시·견적 ID가 기록된다.
- **예외/에러 케이스**: DC사업부·매니지드서비스사업부의 BAS(구축 투입)·영업이익 항목(`대웅제약 마곡C&D 센터 구축 원가분석표.xlsx`의 「서식_원가분석표」)은 MVP에 넣지 않는다(OI-17).

### REQ-029 Cisco EoX API 연동 [P1]

- **설명**: Cisco EOS 조회(REQ-008·REQ-019)를 AI 웹 검색에서 Cisco EoX API로 바꾼다. API 계정 확보에 시간이 걸려 2차로 미뤘다(D-38, OI-04).
- **사용자 시나리오**: 영업이 Cisco BoM을 검증한다 → Cisco 행의 EOS 결과 출처가 「Cisco EoX API」로 표시된다.
- **인수 조건 (Acceptance Criteria)**:
  - [ ] Cisco SKU의 End-of-Sale 일자가 검증일 이전이거나 같으면 「판매 종료 / 오류」로 판정된다.
  - [ ] EoX API가 정상 응답했는데 레코드가 없는 SKU는 「판매중(EoS 공지 없음)」으로 판정된다(D-28).
- **예외/에러 케이스**: 레코드 없음과 잘못된 PID를 구분하는 방법은 API 계정 확보 뒤 응답 형태를 보고 2차 기획에서 정한다.
