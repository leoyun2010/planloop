## 1. 배경 (왜 바꾸는가)

- 영업은 고객과 첫 논의·예산 잡기 단계에서 「대략 무엇이 몇 개, 얼마쯤」을 빨리 알아야 하는데, 지금은 벤더 도구(CCW·Dell Configurator)에서 구성을 끝까지 만들어 올려야 서비스가 시작된다.
- 서비스에는 이미 쓸 수 있는 자산이 있다: 업로드 때 쌓인 **SKU별 실제 List 단가**(원가 단가, CR-008 #4 — 모든 역할 공개), 확정 BoM 의 구성 이력, AI 웹 검색(EOS), AI 구조화 출력(검토 권고·내자 견적서 가져오기).
- 그래서 **자연어 요청 → 구성 초안(품목·SKU·수량) + 대략 가격**을 만들고, 초안을 BoM 건으로 넘겨 기존 편집·검증·견적 흐름에 잇는다.
- **선을 긋는 점**: 결과는 주문 가능한 BoM 이 아니라 **사전 구성 초안**이다. LLM 은 그럴듯한 SKU 를 지어내고 벤더 구성 규칙(필수 부품·호환)을 놓치기 쉽다. 그래서 SKU 를 서버가 사내 이력·웹 근거로 등급을 매기고, 가격 출처를 나눠 보이며, 정식 BoM 은 지금처럼 벤더 도구 파일을 새 버전으로 올린다(버전 비교로 차이가 보인다).

> ### REQ-N1 AI 구성 초안 (영업·관리자)
>
> - **설명**: 영업이 요구사항을 글로 적으면 AI 가 요구사항을 정리하고(빠진 핵심 정보는 되묻는다), Cisco·Dell 구성 초안(품목·SKU·수량·기간)을 만든다. 서버는 SKU 마다 확인 등급을, 가격마다 출처를 붙이고 합계를 낸다. 영업은 초안을 [BoM으로 만들기]로 BoM 건 v1(작성중)으로 넘겨 기존 편집·검증·견적을 이어 간다.
> - **사용자 시나리오**: 「본사 L3 코어 2대 이중화, 48포트 10G, 3년 지원」을 적고 [초안 만들기] → 「업링크 속도와 전원 이중화 여부를 알려 주세요」 질문에 답 → 품목 9행, 사내 단가 합계 $41,200 + AI 추정 $3,800, 미확인 SKU 1행 → [BoM으로 만들기] → 표준 BoM 편집에서 미확인 행을 고치고 검증 → 나중에 CCW 견적 파일을 새 버전으로 올려 비교.
> - **인수 조건**:
>   - [ ] 영업·관리자만 쓴다. 엔지니어는 메뉴가 없고 API 는 403.
>   - [ ] 핵심 정보가 비면 품목을 만들지 않고 질문만 돌려준다.
>   - [ ] 모든 행에 SKU 확인 등급(사내 이력·웹 근거·미확인)과 가격 출처(사내 단가·AI 추정·없음)가 칩(색 + 글자)으로 보인다.
>   - [ ] 합계는 사내 단가 합계와 AI 추정 합계를 나눠 보이고 「대략 가격 — 견적 아님」 안내가 늘 함께 있다. 미확인 SKU 의 가격은 합계에 넣지 않는다.
>   - [ ] [BoM으로 만들기]로 만든 BoM 은 검증(R1 ~ R9·EOS·AI 검토)과 견적이 기존과 같이 돈다.
>   - [ ] 관리자 「AI 구성 초안 켜기」가 꺼져 있거나 서버 설정이 AI 를 꺼 두면 「사용할 수 없음」 문구로 끝난다.
> - **예외/에러 케이스**: AI 실패·시간 초과·응답 형식 오류 → 「초안을 만들지 못했습니다」, 다시 시도. 벤더가 Cisco·Dell 이 아니면 「지원하지 않는 벤더」 안내. 호출 제한을 넘으면 429.

**② 02-policy.md — POL-N1 · POL-N2 신설, 기존 정책 보완**

> ### POL-N1 AI 구성 초안 — 요청·초안 만들기
>
> - **규칙** (한 문장): 작성자 역할은 자연어 요구사항으로 Cisco·Dell 구성 초안을 요청할 수 있고, AI 는 ① 요구사항 정리 ② 구성 초안 두 번 호출하며, 핵심 정보가 비면 ②를 부르지 않고 질문을 돌려준다.
>
> | 입력 | 규칙 |
> |---|---|
> | 고객사 · 프로젝트명 | 선택, 각 200 · 400자. **AI 로 보내지 않는다**. [BoM으로 만들기] 때 BoM 건의 고객사·건명(그때는 필수) |
> | 벤더 | 자동 / Cisco / Dell (처음 자동) |
> | 요구사항 | 필수, 10 ~ 2,000자, 제어 문자 금지 |
> | 질문에 대한 답 | 질문마다 0 ~ 500자 |
>
> - **핵심 정보** (하나라도 정할 수 없으면 질문): 벤더(자동이면 AI 가 정하되 둘 다 아니면 「지원하지 않는 벤더」), 장비 종류(스위치·라우터·무선·서버·스토리지 등), 수량. 질문은 최대 5개, 질문 → 답 왕복은 2번까지(그 뒤에는 정한 만큼으로 초안을 만들고 「가정」 목록에 적는다).
> - **초안 참고 자료(사내 이력)**: 같은 벤더의 확정 BoM 행 중 정리된 요구사항의 제품군과 맞는 것 — 벤더·행 유형·구분·SKU·품명·수량만(가격·고객사·건명·작성자 없음). 최대 200행.
> - **AI 응답 (구조화 출력)**: 행마다 벤더·행 유형(PARENT·SUBPRODUCT·COMPONENT)·상위 행·구분·SKU·품명·수량·기간(개월)·근거 URL·확신도(높음·보통·낮음)·AI 추정 List 단가와 통화(선택, 출처 URL 필수). 그 밖에 가정 목록·주의 사항. 최대 100행.
> - **호출 제한**: 사용자당 동시 1건·분당 3건, 전체 동시 4건. 넘으면 429 「잠시 뒤 다시 시도해 주세요.」
> - **시간 한도**: ①·② 합쳐 서버 설정 `NL_DRAFT_TIMEOUT_SEC`(기본 180초). 넘으면 실패.
> - **설정**: 관리자 환경설정 [AI·EOS] 「AI 구성 초안 켜기」(POL-040, 기본 꺼짐 — BoM 검증 AI 켜기와 따로). 모델·생각 강도·최대 출력 토큰은 「AI 검토」 값, 웹 검색 횟수는 행당 EOS 와 같은 값, 출처 도메인은 EOS 와 같다(POL-029 — 벤더 공식 사이트·router-switch.com).
> - **위반/실패 시 처리**
>
> | 경우 | 문구 |
> |---|---|
> | 요구사항 비어 있음 / 길이 | 「요구사항을 입력해 주세요.」 / 「요구사항은 10 ~ 2,000자로 입력해 주세요.」 |
> | 켜기 꺼짐 · 서버 설정 꺼짐 | 「AI 구성 초안을 지금 사용할 수 없습니다. 관리자에게 문의해 주세요.」 |
> | Cisco·Dell 아님 | 「Cisco·Dell 구성만 만들 수 있습니다.」 |
> | AI 실패·시간 초과·형식 오류·전송 필드 위반 | 「초안을 만들지 못했습니다. 잠시 뒤 다시 시도해 주세요.」 |
> | 호출 제한 | 「잠시 뒤 다시 시도해 주세요.」 (429) |
>
> - **기록**: 요청마다 요구사항 글(가린 뒤)·정리된 요구사항·질문과 답·초안 결과·상태·요청자·시각을 남긴다. 화면에서는 요청자 본인만 본다(관리자도 남의 초안은 못 본다). AI 요청·응답 원문은 POL-012 와 같이 DB 에만. 사용량 출처 `NL_DRAFT`(POL-041). 감사 로그 `NL_DRAFT_RUN`(대상 = 초안 ID, 결과 상태만 — 글·금액 없음).

> ### POL-N2 AI 구성 초안 — SKU 확인·가격·BoM 만들기
>
> - **규칙** (한 문장): 서버는 초안 행마다 SKU 확인 등급과 가격 출처를 정해진 순서로 매기고, 합계는 출처별로 따로 내며, 화면은 계산하지 않는다.
> - **SKU 확인 등급** (위에서부터 처음 맞는 것):
>
> | 등급 | 조건 | 칩 |
> |---|---|---|
> | 사내 이력 | 같은 벤더의 원가 단가 이력 또는 BoM 행에 같은 SKU(대문자·앞뒤 공백 제거) | 확인(ok) |
> | 웹 근거 | AI 가 준 근거 URL 이 출처 도메인 안 | 참고(info) |
> | 미확인 | 그 밖 | 주의(warn) |
>
> - **가격 출처** (위에서부터): ① 사내 단가 — 원가 단가 이력의 가장 최근 단가(같은 벤더·SKU·통화) ② AI 추정 — AI 가 준 단가, 출처 URL 이 출처 도메인 안일 때만 ③ 없음. **미확인 등급 행은 ②를 쓰지 않는다.** 금액 = 단가 × 수량(구독은 기간 반영 — POL-019 와 같은 방식), 행 단위 절사.
> - **합계**: 통화마다 「사내 단가 합계」·「AI 추정 합계」·「가격 없음 {n}행」. 두 합계를 더한 값은 「대략 합계」로만 보이고 견적·견적서에 쓰지 않는다. 다른 사람 견적의 할인율·Net 금액은 쓰지 않는다(POL-009).
> - **BoM 만들기**: [BoM으로 만들기] → 새 BoM 건(고객사·건명 필수, 작성자 = 요청자) v1(작성중)에 초안 행을 행 저장 규칙(POL-005·020)대로 넣는다. 행 출처 파일 이름 「AI 초안」, 원본 파일 없음. **List 단가는 사내 단가 행만 넣고**, AI 추정 단가는 행 비고에 「AI 추정 {통화} {단가} · {출처 도메인} · {조회일}」로 남긴다. 할인율·Net 은 비운다. 원가 단가 이력에는 쌓지 않는다(업로드만 쌓는다 — CR-008 #4). 한 초안에서 BoM 은 한 번만 만든다(두 번째는 만든 BoM 으로 이동). 감사 로그 `NL_DRAFT_TO_BOM`(초안 ID·BoM ID·행 수).
> - **검증 의사코드**:
>
>   ```js
>   function grade(row, history, hosts) {
>     const key = skuKey(row.sku);
>     if (key && (history.prices.has(row.vendor, key) || history.rows.has(row.vendor, key))) return "IN_HOUSE";
>     if (row.evidenceUrl && hosts.includes(host(row.evidenceUrl))) return "WEB";
>     return "UNVERIFIED";
>   }
>   function price(row, grade, history, hosts) {
>     const p = history.latestPrice(row.vendor, skuKey(row.sku), row.currency);
>     if (p) return {source: "IN_HOUSE", unit: p.price, currency: p.currency};
>     if (grade !== "UNVERIFIED" && row.aiPrice && hosts.includes(host(row.aiPrice.url)))
>       return {source: "AI_ESTIMATE", unit: row.aiPrice.unit, currency: row.aiPrice.currency};
>     return {source: "NONE"};
>   }
>   ```

## 5. 0단계 진행 기준 (DEC-93 ⑦)

과거 실제 요청 10 ~ 20건과 그 확정 BoM 을 정답셋으로 잰다. 넷 다 넘으면 구현, 하나라도 못 넘으면 결과를 보고 CR 을 고치거나 기각한다.

| 지표 | 기준 |
|---|---|
| SKU 유효율 (초안 SKU 중 실제 존재) | 90% 이상 |
| 주요 품목 일치율 (정답의 상위 품목·하위 제품) | 70% 이상 |
| 가격 오차 (초안 List 합계 ÷ 정답 List 합계 − 1) | ±20% 이내 |
| 시간 (요청 1건) | 120초 이하 |
