# CR-011 내자(3rd Party) 견적서 AI 가져오기 · 총공급가액 직접 수정 (DEC-86·87)

| 항목 | 내용 |
|---|---|
| CR ID | CR-011 |
| 상태 | 제안 (제안 → 승인 → 반영완료 / 기각) |
| 발생일 | 2026-10-20 (결정 2026-10-07·10-12) |
| 출처 | 사용자 요청 — 구현 저장소 `docs/decisions/open-decisions.md` DEC-86(2026-10-07)·DEC-87(2026-10-12) |
| 발생 단계 | 운영 (출시 직전 ~ 직후) |
| 유형 | 기능 추가 · 기능 변경 |
| 우선순위 | 높음 — 운영 판에 들어가 있고, POL-012 전송 범위(보안 정책)가 바뀐다 |

> CR-003·008·009 와 같은 「구현이 앞선 결정의 역반영」이다. 구현·테스트 완료(커밋 `ba05ea8`·`255ce26` DEC-86, `942d13f` DEC-87).
> 여기에는 승인 문서에서 바뀌는 곳만 적는다. 번호는 가번호(REQ-T1, POL-T1, TC-T1 ~ T10)다 — CR-005 ~ 010 반영 뒤 이어서 매긴다.
> 견적 추가 항목(CR-009 #2, DEC-78)과 견적 숫자 직접 수정(CR-009 #5, DEC-81) 위에 얹힌 기능이라 **CR-009 를 먼저 반영**한다.

## 1. 배경 (왜 바꾸는가)

- 영업은 Cisco·Dell 장비 견적에 협력사(내자) 품목 — 인건비·SW 패키지·설치·교육 등 — 을 함께 넣는다. 협력사 견적서는 업체마다 양식이 달라(엑셀 여러 시트, PDF, 패키지 > 모듈 계층, 할인 행 따로) 견적 추가 항목에 손으로 옮겨 적고 있었다.
- 2026-10-07 사용자 결정(DEC-86): **AI 가 협력사 견적서를 읽어 견적 추가 항목으로 넣는다.** 숫자 검사·할인 배분·같은 품목 합치기는 서버 규칙으로 한다.
- 2026-10-12 사용자 요청(DEC-87): 협력사 견적서의 단가는 인성정보가 **받는 값(공급단가)** 으로 넣어야 맞다 — 처음 구현(단가 → 원가 단가)을 바꿨다. 할인 배분 끝전·견적서 끝전을 맞추려고 **총공급가액을 직접 고치는 칸**을 견적 표에 더했다.
- 샘플 11건 실측(2026-10-07): 품목·합계 모두 일치. 1건(여러 견적 시트)은 AI 가 적은 견적서 합계가 틀려 「합계 다름」 경고만 잘못 떴다(넣은 품목은 맞음).

### 2.1 POL-T1 내자 견적서 가져오기 (신설안)

> - **규칙** (한 문장): 견적 작성자는 협력사 견적서를 올려 AI 가 읽은 품목을 견적 추가 항목으로 넣을 수 있고, 숫자 검사·할인 배분·합치기는 서버가 정해진 규칙으로 한다.
> - **파일**: `.xlsx`·`.xls`·`.pdf`, 10MB 이하(업로드 한도와 같다), 비어 있지 않을 것, PDF 는 파일 머리 `%PDF-`. 암호 걸린 엑셀은 받지 않는다. 엑셀은 시트마다 비지 않은 셀을 「R행 | 열: 값」 텍스트로 옮기고(셀 300자에서 자름), 전체가 20만 자를 넘으면 받지 않는다.
> - **AI 가 뽑는 것** (프롬프트): 가격이 적힌 공급 품목 행 — 소계·합계·VAT·할인 행, 설명 줄, 같은 품목을 다시 적은 요약표, 견적이 아닌 시트, 「제안사 제공」·「-」, 유지보수·TCO 처럼 이번 구매가 아닌 열은 뺀다. 행마다 구분(아래)·구분 원문·품명·수량·단위·단가·공급금액, 전체로 통화·견적서 합계(VAT 별도, 할인 전)·최종 금액(VAT 별도, 할인·네고 뒤).
> - **구분**: 인건비·개발·설치·구축·교육·기술지원·테스트 → SERVICE, SW·License·패키지·모듈·솔루션 → SOFTWARE, H/W·서버·장비 → PRODUCT.
> - **서버 정제** (순서대로):
>
> | 단계 | 규칙 |
> |---|---|
> | 행 검사 | 품명이 없거나 구분이 세 값이 아니면 뺀다. 수량이 없으면 금액 ÷ 단가, 그것도 없으면 1(1식). 수량·단가·금액은 견적 추가 항목 한도 안(CR-009 #2) |
> | 단가 ↔ 금액 | 단가 × 수량과 금액이 1원 넘게 다르면 **금액을 믿고** 단가 = 금액 ÷ 수량(원 단위) — 확인할 점에 품목 이름 |
> | 통화 | 원화가 아니면 넣지 않는다(422) |
> | 합계 대조 | 읽은 품목 합이 견적서 합계와 1원 넘게 다르면 경고만 |
> | 할인 배분 | 최종 금액 < 품목 합이면 비율(최종 ÷ 합)을 모든 품목의 공급단가·공급금액에 곱하고 원 단위 반올림, 남는 몇 원은 공급금액이 가장 큰 품목에 — 합이 최종 금액과 늘 같다. 최종 금액 ≥ 품목 합이면 그대로 |
> | 합치기 | 같은 구분·품명·공급단가 행은 수량·금액을 더해 처음 나온 자리에 한 행으로 |
> | 매핑 | 2장 #3 |
>
> - **호출**: 사용자당 동시 1건·분당 5건, 전체 동시 4건 — 넘으면 429. 시간 한도 180초(코드 상수). AI 실패·시간 초과·형식 오류·전송 필드 위반이면 실패 문구.
> - **화면에 넣기**: 미리보기에서 고른 행만 견적 추가 항목 뒤에 붙인다. 추가 항목 50개 상한(CR-009 #2)을 넘으면 넣지 않고 남은 자리 수를 알린다.
> - **기록**: AI 요청·응답 원문은 POL-012 와 같이 DB 에만(검증 결과 없이, BoM 을 지우면 함께 삭제), PDF 는 크기·해시만. 사용량은 POL-041. **감사 로그 사건은 따로 두지 않는다** — 넣은 결과는 견적 저장(기존 사건)으로 남는다.
> - **위반/실패 시 처리** (문구는 구현 카탈로그 그대로):
>
> | 경우 | HTTP | 문구 |
> |---|---|---|
> | 확장자 | 400 | 「내자 견적서는 .xlsx, .xls, .pdf 파일만 올릴 수 있습니다.」 |
> | 크기·빈 파일·손상·암호 | 400 | 업로드 공통 문구(POL-014) |
> | 내용이 너무 많음 | 400 | 「견적서 내용이 너무 많아 한 번에 읽을 수 없습니다. 견적 시트만 남긴 파일로 다시 올려 주세요.」 |
> | 켜기 꺼짐·서버 설정 꺼짐 | 503 | 「AI 기능이 꺼져 있어 견적서를 읽을 수 없습니다. [행 추가]로 직접 넣거나 관리자에게 문의해 주세요.」 |
> | 이미 읽는 중·호출 제한 | 429 | 「견적서를 읽는 중입니다. 끝난 뒤 다시 시도해 주세요.」 |
> | AI 실패 | 502 | 「견적서를 읽지 못했습니다. 잠시 뒤 다시 시도하거나 [행 추가]로 직접 넣어 주세요.」 |
> | 원화 아님 | 422 | 「견적서에 원화 금액이 없습니다({currency}). [행 추가]로 소비자가와 통화를 직접 넣어 주세요.」 |
> | 품목 없음 | 422 | 「견적서에서 가격이 있는 품목을 찾지 못했습니다. [행 추가]로 직접 넣어 주세요.」 |
> | 50개 상한 | — | 「추가 항목은 {max}개까지 넣을 수 있습니다. 지금 {current}개가 있어 {room}개만 더 넣을 수 있습니다.」 |
>
> - 확인할 점(미리보기 경고): 「품명이나 가격이 없는 {n}행(「제안사 제공」 등)은 뺐습니다.」 · 「단가 × 수량이 금액과 다른 품목 {n}개는 견적서의 금액에 맞춰 단가를 정했습니다: {names}」 · 「읽은 품목 합 {sum}원이 견적서 합계 {total}원과 다릅니다. …」 · 「최종 금액 {final}원에 맞춰 모든 품목의 공급단가·공급금액을 {rate}% 낮췄습니다.」 · 「같은 품목 {n}행을 수량을 더해 합쳤습니다.」. 넣은 뒤 「추가 항목 {n}개를 넣었습니다. 확인한 뒤 견적을 저장해 주세요.」
> - **검증 의사코드**:
>
>   ```js
>   function allocate(lines, finalTotal) {                 // 할인·네고는 품목별로
>     const sum = total(lines);
>     if (!finalTotal || !sum || finalTotal >= sum) return lines;
>     const r = finalTotal / sum;
>     const out = lines.map(l => ({...l, unitPrice: won(l.unitPrice * r), amount: won(l.amount * r)}));
>     out[argmax(out, l => l.amount)].amount += finalTotal - total(out);   // 끝전 → 가장 큰 품목
>     return out;
>   }
>   function toItem(l) {                                    // DEC-87 매핑
>     const exact = l.unitPrice * l.qty === l.amount;
>     return {category: l.category, name: l.name, qty: l.qty, currency: "KRW", listPrice: null, costPrice: null,
>             salePrice: exact ? l.unitPrice : null, saleAmount: exact ? null : l.amount};
>   }
>   ```
