## 1. 배경

- 백업이 EC2 안에만 있어 인스턴스·디스크 장애 때 함께 잃는다. 복원해 본 적도 없다.
- 서비스가 멈추거나 AI 호출이 계속 실패해도 사용자 신고 전에는 모른다.
- 사용자 비활성화(DEC-63) 뒤 퇴사자의 BoM 건은 아무도 고칠 수 없다 — 가격·견적은 작성자만 보고, 관리자도 남의 건은 못 본다(POL-009).

## 2. 변경 내용 (TO-BE 요지 — 구현 완료)

| 항목 | TO-BE | 반영 문서(안) |
|---|---|---|
| 백업 (DEC-23 결정) | 매일 DB·업로드 파일 → 서버 로컬 7일 + S3 30일(버킷 수명 주기). 실패하면 관리자 알림. 복원 리허설을 출시 전 1회·분기마다 | PRD NFR(가용성·복구) 보완, 리스크 표 |
| 관리자 알림 (DEC-67) | Naver Works 봇 메시지로 지정 관리자(`ALERT_RECIPIENTS`)에게: ① 서비스 무응답(5분 간격 연속 2회)·복구 ② 백업 실패 ③ AI 호출 실패 급증(최근 60분 5건 이상 중 50% 이상, 60분에 한 번) ④ 월 예산 경고·초과(같은 달 단계마다 한 번). 문구 `ALERT_*` | PRD NFR·REQ-031 보완, POL-041 보완(예산 알림), 신규 POL(관리자 알림) |
| BoM 작성자 넘기기 (DEC-68) | SCR-012에서 한 명을 골라 [BoM 넘기기] → 받는 사람(사용 중인 영업·관리자) 선택 → 확인 문구 「{from}님의 BoM 건 {n}개를 {to}님에게 넘깁니다. 넘긴 뒤에는 {to}님만 가격·견적을 보고 고칠 수 있고, {from}님은 볼 수 없습니다. 넘기시겠습니까?」 → 토스트 「BoM 건 {n}개를 {name}님에게 넘겼습니다.」. 버전·검증·견적이 함께 넘어간다. 같은 사람·엔지니어·역할 미지정·비활성에게는 불가(「받는 사람은 사용 중인 영업·관리자여야 합니다.」), 넘길 건이 없으면 「넘길 BoM 건이 없습니다.」. 감사 「BoM 작성자 넘기기」(BoM 건마다) | 신규 REQ(P0)·POL, POL-009·011 보완, SCR-012, TC 신설 |

## 3. 영향 분석

- 화면: SCR-012 [4] 일괄 지정 바에 [BoM 넘기기] + 대화상자. 다른 화면 변경 없음
- 정책: POL-009(작성자 = `boms.author_id`, 넘기기로 바뀜), POL-011(새 사건), POL-041(예산 알림)
- QA: 넘기기 TC 1건(정상·예외 묶음), 알림은 스텁(`notify` 모드) TC 1건 + 서버 수동 점검 항목(무응답·백업·복원 리허설)
- 운영: 서버 `.env` 새 키(BACKUP_S3_URI, ALERT_RECIPIENTS, NW_BOT_ID, NW_SERVICE_ACCOUNT, NW_BOT_PRIVATE_KEY_B64), cron 2줄, S3 버킷·IAM 역할, Naver Works 봇 등록 — 구현 저장소 `deploy/SERVER_SETUP.md` 6·8
