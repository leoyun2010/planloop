## 1. 한 줄 정의

> **유지보수 엔지니어**가 정기점검 때 고객사 장비 로그를 자동으로 수집하고, 룰 기반으로 정상/주의/이상을 판정받고, AI가 쓴 총평이 들어간 점검보고서 초안을 **점검 당일** 받아 볼 수 있게 하는 **로컬 PC 웹앱**

## 2. 해결하려는 문제

- **수집이 수작업이다**: 장비마다 콘솔·SSH로 접속해 점검 명령어를 직접 입력하고 복사해 붙여넣는다. 명령어를 잘못 입력해 필요한 내용을 확인하지 못하는 경우가 생긴다. 자동화 스크립트(Python·Ansible)는 작성자 개인에게 묶여 있어 다른 엔지니어가 쓰기 어렵다. (#1, #4, #6)
- **확인과 판정을 사람에게 의존한다**: 장비 수십 대의 출력을 사람이 읽다 보니 이상 징후를 놓친다. 정상/주의 판단과 총평이 엔지니어 경험에 따라 달라진다. 특이 로그와 권고 버전은 매번 검색해야 한다. (#1, #2, #5)
- **보고서 작성이 따로 걸린다**: 수치를 Word·PPT에 옮겨 적다가 오기·누락이 생긴다. 전 회차 보고서를 열어 손으로 대조한다. 그러다 보니 점검 당일 제출이 어렵고, 월말에 작업이 몰리면 제출이 늦어진다. (#2, #7)
- **왜 지금인가**: 기술 부문 5개 부서가 같은 문제로 AX 과제를 따로 제출했다(8건 중 6건이 정기점검). 공통 도구를 하나 만들면 중복 개발을 막고 점검 품질을 통일할 수 있다.

## 4. 핵심 가치 제안

- **수집 표준화**: 벤더별 명령어 세트 템플릿으로 누가 점검해도 같은 항목을 같은 품질로 수집한다. 개인 스크립트 대비 실행 환경을 구성할 필요가 없다.
- **판정은 룰, 설명은 AI**: 값 추출과 정상/주의/이상 판정은 기준표 기반 룰 엔진이 결정한다(재현 가능). AI는 이상 사유 설명과 총평·권고 문장 작성만 보조한다. (#2, #5)
- **보안 우선**: 고객사명·장비명·IP·Hostname을 가명화한 뒤에만 AI로 보낸다. 원본과 매핑은 PC 안에만 둔다. 외부 전송이 전혀 없는 모드(로컬 모델 또는 정형 문장)도 선택할 수 있다.
- **전 회차 자동 비교**: 이전 보고서를 열어 손으로 대조하지 않아도 회차별 추이와 변화 항목을 자동으로 보여 준다.

## 5. 핵심 기능 (5개, 처리 흐름순 — P0/P1 우선순위는 미정 — 확인 필요)

1. **점검 대상·명령어 세트 관리** — 고객사·장비 인벤토리 등록(접속정보 암호화 저장), 벤더별 점검 명령어 세트 템플릿 등록·편집 (#1, #4, #5, #6)
2. **로그 수집 (4가지 방식)** — ① SSH 일괄 접속·명령 자동 실행 ② 저장된 출력 파일(txt) 일괄 업로드 ③ Cisco RADKit Client 일괄 실행 ④ API·DB 수집(AXL/RisPort70, vManage API, MSSQL). 장비별·일자별 파일명 규칙으로 Raw/가명화본을 분리 저장 (#1, #2, #4, #5, #6, #7)
3. **값 추출·룰 기반 판정** — 버전·가동시간·온도·팬/전원·CPU/메모리/디스크·포트 에러·STP·NTP·이중화·인증서·백업·주요 로그 추출. 기준값·전 회차 대비 정상/주의/이상 판정, 특이 로그·권고 버전 기준표 자동 대조 (#1, #2, #5, #7)
4. **가명화 + AI 분석** — 고객사명·장비명·IP 가명화와 원복. AI 총평·이상 사유·권고 문장 생성. 방식은 설정에서 선택: Claude API / 로컬 모델 또는 정형 문장 (#2, #5, #7)
5. **리포트 생성·검토·이력** — 웹 화면 조회 + PDF 출력, 고객사별 Word(docx) 템플릿 자동 기입, 초안 검토·수정, 회차 이력 보관·비교 (#1, #2, #7)

- 대상 장비군(1차): Cisco 라우터·스위치(IOS/NX-OS), Cisco SD-WAN, Nexg·Dell 등 타 벤더, 컨택센터(CUCM/CVP/ICM/Finesse/CUIC/VVB)
