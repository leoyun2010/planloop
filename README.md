# 웹앱 개발 기획 시스템

웹 애플리케이션 개발 전(前) 단계의 기획 산출물을 만들고, 개발·QA 중 발생하는 요구사항 변경을
산출물에 지속적으로 역반영하는 Claude Code 기반 기획 시스템입니다.

**핵심 철학 — 되묻지 않는 스펙**: 기획 산출물의 1차 독자는 사람과 구현 AI(Claude Code) 둘 다입니다.
PRD(왜) + 정책서(어떤 규칙으로 검증) + 화면(어떻게 보이고 동작) + QA TC(어떻게 확인) 4종이
세트로 갖춰져야 구현자가 기획자에게 되묻지 않고 개발할 수 있습니다.

## 산출물

| 산출물 | 파일 | 내용 |
|---|---|---|
| 회의록 | `minutes/` | 회의 결정사항 원본 보관 — 추적 체인의 출발점 |
| 프로젝트 브리프 | `00-brief.md` | 문제 정의, 타깃, 핵심 기능, 제약 (1장) |
| PRD | `01-prd.md` | 기능 요구사항(REQ) + 인수 조건, 비기능 요구사항(NFR), 주차별 계획, 리스크 |
| 정책서 | `02-policy.md` | 검증 가능한 규칙(POL) — 적용 시점, 위반 시 문구, 검증 의사코드까지 |
| IA | `03-ia.md` | 사이트맵, 화면 목록(SCR), 사용자 흐름도 (Mermaid) |
| 화면정의서 | `04-screens/SCR-###.md` | 레이아웃 + 컴포넌트 트리(JSX) + 상태 4종 + 유효성 |
| HTML 와이어프레임 | `04-screens/SCR-###.html` | 브라우저에서 바로 여는 로파이 목업 (+ `index.html` 전체 뷰어) |
| QA 테스트케이스 | `05-qa-tc.md` | 실행 가능한 검증 절차(TC) — 모든 P0 REQ·POL 커버 |
| 변경요청 | `changes/` | 개발·QA 중 요구사항 변경 기록 (CR) |

## 사용법

### Codex CLI

이 저장소의 루트에서 `codex`를 실행합니다. Windows PowerShell에서는 `codex.cmd`도 사용할 수 있습니다.
Codex 입력창에 `$`를 입력해 스킬을 선택하거나, `$plan-init`처럼 이름을 직접 입력합니다.
Codex가 열린 상태에서 저장소를 업데이트했다면 스킬을 찾지 못할 때 세션을 다시 시작하세요.

| 작업 | Codex 스킬 |
|---|---|
| 프로젝트 시작 | `$plan-init` |
| 회의록 반영 | `$minutes` |
| PRD 작성 | `$prd` |
| 정책서 작성 | `$policy` |
| 화면과 와이어프레임 작성 | `$wireframe` |
| QA 테스트케이스 작성 | `$qa-tc` |
| 변경요청 작성 | `$change` |
| 승인된 변경요청 반영 | `$merge-change` |
| 구현과 기획 비교 및 동기화 | `$sync-impl` |
| 기획 현황과 정합성 점검 | `$plan-status` |

### Claude Code

Claude Code에서 슬래시 커맨드로 진행합니다.

### 1) 기획 단계 (프로젝트 시작 → 스펙 세트 완성)

```
/plan-init      새 프로젝트 시작 — 인터뷰 후 브리프 작성
/minutes        회의록·녹취 전사 → 결정사항 7개 이내 요약 → 산출물 반영 ("회의가 기획이 된다")
/prd            브리프 → PRD (요구사항 ID 부여, 인수 조건, 리스크)
/policy         PRD → 정책서 (6요소: 규칙·적용 시점·위반 문구·예외·의사코드·TC)
/wireframe      PRD·정책서 → IA + 화면정의서 + HTML 목업 + 전체 화면 뷰어
/qa-tc          스펙 세트 완성 — 모든 P0 요구사항·정책에 테스트케이스 연결
```

각 문서가 완성되면 검토 후 문서 상태를 `승인(Approved)`으로 바꿉니다.
**승인 이후에는 문서를 직접 수정하지 않고 변경요청 절차를 사용합니다.**

### 2) 개발·QA 단계 (요구사항 변경 역반영)

```
/change         변경 발생 시 — 영향 분석 포함 CR 문서 작성 (changes/open/)
/merge-change   CR 승인 후 — 관련된 모든 산출물(TC 포함)에 일괄 반영 + CHANGELOG 기록
/sync-impl      구현이 문서보다 앞서갔을 때 — ①차이만 리포트 → ②사람 판단 → ③반영 (2단계 분리)
/plan-status    현황·정합성 점검 — 깨진 ID 참조, TC 커버리지, 완료 정의(DoD) 충족 여부
```

예시: QA에서 "로그인 5회 실패 시 잠금 해제 수단이 없다"는 이슈가 나오면 →
`/change`로 CR 작성 (POL-001 정책 + SCR-002 로그인 화면 + TC 영향 분석) → 승인 →
`/merge-change`가 정책서, 화면정의서, HTML 목업, 테스트케이스, CHANGELOG를 한 번에 갱신.

## 추적 체인 (ID 체계)

```
회의 결정(minutes/) → REQ-### (PRD) → POL-### (정책) → SCR-### (화면) → TC-### (테스트)
                        └── 변경은 CR-###이 체인 전체를 관통
```

"왜 이 화면/로직이 필요한가"를 물으면 TC → POL → REQ → 회의 결정까지 번호로 역추적할 수 있습니다.
자세한 규칙(완료 정의, 버전, 정합성)은 [CLAUDE.md](CLAUDE.md) 참조.

## 폴더 구조

```
templates/           산출물 템플릿 (직접 수정하지 않음)
.claude/skills/      슬래시 커맨드 정의
projects/<이름>/     프로젝트별 산출물
  ├── minutes/       회의록 원본 + 결정→ID 매핑
  ├── 00-brief.md ~ 03-ia.md
  ├── 04-screens/    화면정의서(.md) + 목업(.html) 쌍 + index.html 뷰어
  ├── 05-qa-tc.md    QA 테스트케이스
  ├── changes/open/  진행 중 CR
  ├── changes/merged/ 반영 완료 CR (이력)
  └── CHANGELOG.md
```

  구현↔기획 2단계 동기화 루프, 검사 가능한 완료 정의, 산출물 뷰어
