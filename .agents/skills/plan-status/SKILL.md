# 기획 산출물 현황/정합성 점검

## 절차

1. 대상 프로젝트 폴더를 확인한다 (`projects/` 하위).
2. **현황 요약**을 수집한다:
   - 각 문서의 버전·상태 (문서정보 표에서)
   - REQ/NFR/POL/SCR/TC 개수와 상태 분포 (정의됨/개발중/QA/완료, TC는 미실행/통과/실패)
   - `changes/open/`의 미해결 CR 목록 (상태·우선순위·경과일)
3. **정합성 검사**를 수행한다:
   - **깨진 참조**: 문서에 인용된 REQ/POL/SCR/TC ID가 실제 정의 문서에 존재하는가 (grep으로 ID 전수 대조)
   - **고아 항목**: 어떤 문서에서도 참조되지 않는 REQ (화면·정책 어디에도 연결 안 됨)
   - **쌍 불일치**: 04-screens/에 .md만 있고 .html이 없는(또는 반대) 화면, index.html 뷰어에 누락된 화면
   - **TC 커버리지**: TC가 없는 P0 REQ, 위반 케이스 TC가 없는 POL
   - **TBD 잔존**: "TBD", "미정", "확인 필요"로 남아 있는 항목
   - **버전 불일치**: 변경이력 마지막 버전과 문서정보 표의 버전이 다른 문서
   - **완료 정의(DoD) 검사**: AGENTS.md의 "완료 정의" 표 기준으로 각 산출물의 충족 여부 (예: 인수 조건 체크박스 2개 미만인 REQ, 6요소가 빠진 POL, 검증 불가 표현 잔존)
4. 결과를 리포트한다:
   - ✅ 정상 / ⚠️ 경고 / ❌ 문제 로 구분한 테이블
   - 문제 항목별 권장 조치 (예: "CR-003이 14일째 미결 — 승인 또는 기각 결정 필요")
5. 발견된 문제의 수정은 사용자 확인 후 진행한다. 승인된 문서의 내용 수정이 필요하면 `$change` 절차를 안내한다.
