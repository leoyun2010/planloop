# 정책서 작성/갱신

## 사전 조건

- `projects/<프로젝트명>/01-prd.md`가 있어야 한다. 없으면 `$prd`를 먼저 안내한다.

## 절차

1. `01-prd.md`의 모든 REQ를 훑으며 정책이 필요한 지점을 도출한다. 체크 관점:
   - **인증/권한**: 누가 할 수 있는가? 로그인 필요한가? 실패 시?
   - **입력 규칙**: 글자 수, 형식, 금지 값, 중복 허용 여부
   - **수량/빈도 제한**: 최대 개수, 호출 제한, 재시도 정책
   - **상태 전이**: 생성→수정→삭제 조건, 삭제 시 연관 데이터 처리
   - **노출/정렬**: 무엇이 언제 누구에게 보이는가, 기본 정렬
   - **법/개인정보**: 수집 항목, 동의, 보관 기간
2. 정책 방향이 갈리는 항목(예: 탈퇴 시 게시물 처리 — 삭제 vs 익명화)은 Codex 대화에서 사용자가 결정하게 한다. 임의로 정하지 않는다.
3. `templates/02-policy.md` 구조로 `02-policy.md`를 작성한다. 각 POL은 **6요소**를 갖춘다:
   - ① 규칙 한 문장 — 값과 조건으로 명시 (예: "적절한 길이" ❌ → "2~50자" ⭕)
   - ② 적용 시점 — 어느 화면/API/이벤트에서 발동하는가
   - ③ 위반/실패 시 처리 — 차단/경고/기록 여부 + 사용자 안내 문구 원문 그대로
   - ④ 예외 조건
   - ⑤ 검증 의사코드(JS) — 정책 문서 자체가 스펙이자 테스트 기준이 되게 한다
   - ⑥ 관련 TC — 아직 05-qa-tc.md가 없으면 "TBD"로 두고 `$qa-tc` 실행 시 채운다
4. **역참조 갱신**: `01-prd.md`의 REQ 테이블 "관련 정책" 열에 POL ID를 채워 넣는다.
5. 완료 후 다음 단계로 `$wireframe`을 안내한다.

## 규칙

- 승인된 정책서는 직접 수정하지 않는다 — `$change` 절차를 안내한다.
- 정책 없는 REQ가 남아 있으면 "정책 불필요" 판단 근거를 사용자에게 확인한다.
