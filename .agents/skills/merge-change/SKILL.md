# 변경요청 반영 (Merge)

## 사전 조건

- `changes/open/`에 상태가 "승인"인 CR이 있어야 한다.
- 대상 CR이 불명확하면 open/ 목록을 보여주고 사용자에게 확인한다. 상태가 "제안"이면 먼저 승인 여부를 묻는다.

## 절차

1. CR 문서를 읽고 "3. 영향 분석" 테이블과 "4. 반영 체크리스트"를 작업 목록으로 삼는다.
2. 영향받는 각 문서를 TO-BE 내용대로 수정한다:
   - **01-prd.md**: REQ 추가/수정/삭제. 삭제는 행을 지우지 않고 상태를 "폐기"로 바꾸고 취소선 처리 (ID 결번 유지)
   - **02-policy.md**: POL 갱신, 관련 REQ 참조 갱신
   - **03-ia.md**: 화면 추가/삭제 시 사이트맵·화면목록·흐름도 갱신
   - **04-screens/**: 화면정의서(.md)와 HTML 목업(.html)을 **반드시 쌍으로** 갱신. 화면 추가/삭제 시 `index.html` 뷰어 목록도 갱신
   - **05-qa-tc.md**: 변경된 REQ/POL/SCR을 참조하는 TC 갱신, 새 규칙에는 새 TC 추가
3. 수정한 각 문서의 버전을 올리고(내용 변경 minor, 방향 전환 major) 문서 하단 변경이력에 CR ID와 함께 기록한다.
4. `CHANGELOG.md`에 한 줄 추가: `| 날짜 | 버전 | 문서 | 변경 요지 | CR-### |`
5. CR 문서의 체크리스트를 모두 체크하고, 상태를 "반영완료"로, 결정 기록에 반영일을 추가한 뒤 `changes/merged/`로 이동한다.
6. 사용자에게 반영 결과를 요약 보고한다: 수정된 문서 목록과 버전, 개발팀에 전달할 변경 요지.

## 규칙

- 체크리스트 항목을 하나라도 건너뛰면 반영완료로 표시하지 않는다.
- 반영 중 CR에 없던 추가 변경이 필요해지면 임의로 확장하지 말고 사용자에게 확인 후 별도 CR로 만든다.
- 반영 후 `$plan-status`로 ID 참조 정합성을 확인하면 좋다.
