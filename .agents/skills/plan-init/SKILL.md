# 새 프로젝트 기획 시작

## 절차

1. 사용자에게 프로젝트명(영문 폴더명으로 쓸 짧은 이름)을 확인한다.
2. `projects/<프로젝트명>/` 아래에 다음 구조를 만든다:
   - `minutes/`, `changes/open/`, `changes/merged/`, `04-screens/` 디렉터리
   - `CHANGELOG.md` (헤더만: `# CHANGELOG — <프로젝트명>` + 표 헤더 `| 일자 | 버전 | 문서 | 변경 내용 | CR |`)
3. 브리프 작성에 필요한 정보를 인터뷰한다. **회의록·녹취 전사가 이미 있으면 인터뷰 대신 `$minutes`로 결정사항을 추출해 입력으로 쓴다.**
   인터뷰 시 한 번에 전부 묻지 말고 Codex 대화에서 핵심부터:
   - 무엇을 만드는가 (한 줄 정의, 해결하려는 문제)
   - 누가 쓰는가 (타깃 사용자)
   - 핵심 기능 3~5개와 우선순위
   - 제약 조건 (일정, 기술 스택, 법/규제)
   - 1차 출시에서 제외할 것
4. `templates/00-project-brief.md`를 복사해 `projects/<프로젝트명>/00-brief.md`를 작성한다.
   - 사용자가 답하지 않은 항목은 추측하지 말고 "미정 — 확인 필요"로 표시한다.
5. 작성 후 사용자에게 검토를 요청하고, 다음 단계로 `$prd`를 안내한다.

## 규칙

- AGENTS.md의 ID 체계·작성 스타일을 따른다.
- 브리프는 1~2페이지를 넘지 않는다. 상세 내용은 PRD로 미룬다.
