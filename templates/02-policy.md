> 정책서는 "시스템이 어떤 규칙으로 검증하는가"를 정의한다.
> 설명이 아니라 **검증 가능한 규칙**으로 쓴다. 정책 문서 자체가 스펙이자 테스트 기준이 되어,
> 개발자·QA(사람이든 Claude든)가 이 문서만 보고 되묻지 않고 판단할 수 있어야 한다.
> 각 정책은 6요소를 갖춘다: 규칙 / 적용 시점 / 위반 시 처리(문구 그대로) / 예외 / 검증 의사코드 / 관련 TC

## 1. 회원/인증 정책

### POL-001 {정책명}

- **규칙** (한 문장): (예: 비밀번호는 8자 이상, 영문+숫자+특수문자 중 2종 이상 조합)
- **적용 시점**: (어느 화면/API/이벤트에서 발동하는가. 예: SCR-005 회원가입 폼 제출 시, `POST /api/signup`)
- **위반/실패 시 처리**: 차단/경고/기록 중 무엇인지 + 사용자 안내 문구 원문 그대로
  (예: 차단. 문구 "비밀번호는 8자 이상, 영문·숫자·특수문자 중 2종 이상이어야 합니다")
- **예외**: (예: 소셜 로그인 가입자는 적용 제외)
- **검증 의사코드**:

  ```js
  // 이 함수가 곧 정책의 정의다. 구현은 이 로직과 동일해야 한다.
  function checkPol001(password) {
    if (password.length < 8) return fail("MSG_PW_TOO_SHORT");
    const kinds = [/[a-zA-Z]/, /[0-9]/, /[^a-zA-Z0-9]/].filter(r => r.test(password)).length;
    return kinds >= 2 ? pass() : fail("MSG_PW_COMPLEXITY");
  }
  ```

- **관련 요구사항**: REQ-###
